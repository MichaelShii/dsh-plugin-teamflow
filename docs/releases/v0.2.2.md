Release — a maintenance release of "bug fixes + engineering infrastructure" (7 commits / 34 files / +836 −94): fixes three measured defects (dead-code dispose on the normal settlement path, a dangling triage timeout timer, unbounded growth of the in-memory `runs` registry), closes a latent gap where `resume` could not find per-project journals, and introduces an oxlint 0-warning gate + a CI lint step. **No breaking changes**; the host window is unchanged; no new features.

### 验证方式（本次新增：A/B 行为验证）

全部修复用同一套 A/B harness 验证：`git archive` 分别导出**修复前**与**修复后**的 `host/ + store.ts` 到隔离副本（各自独立 `DSH_HOME`），stub 掉宿主子代理服务与私有 peer，跑真实 `runAgent` / `runTriage` / `executePipeline` / `resumeRun` / `getRun` 对照行为差异。四项验证全部通过后发版：

| 验证项 | 修复前 | 修复后 |
|---|---|---|
| 正常结算路径 dispose | 5/5 阶段 0 次 | 5/5 各 1 次，且发生在 `result` 结算之后 |
| 分诊超时定时器 | cleared 0 / pending 1，进程 >120s 不退出 | created 1 / cleared 1 / pending 0，进程 171ms 退出 |
| runs 注册表有界化（灌 120 条历史后跑真实 pipeline） | 120 → 121（单调增长） | 120 → 100，淘汰 21 条最旧，`getRun` 回读完整 |
| 内存不存在的 per-project journal resume | `Run not found` | 续跑至 completed |

### 本次变更

**① 正常结算路径子代理从未 dispose（修复）**

- **问题**：`runner.ts` 结算 `finally` 里的 `if (run) { ... run.dispose() }` 与上一行 `untrackInFlight(...)` 的行注释写在**同一物理行**——整条语句被 `//` 注释吞成死代码。取消路径与护栏中止路径都会 dispose，唯独**正常结算路径从不释放子代理会话**，违背宿主契约（dsh-subagent 的规范结算 `settleRun` = await result 后必 dispose 释放子资源）。
- **修复**：语句拆到独立行恢复执行；A/B 实测见上表 ①。

**② 分诊超时定时器悬挂（修复）**

- **问题**：`triage.ts` 的 `Promise.race` 超时用 `setTimeout` 但无 `clearTimeout`/`unref`——每次分诊成功都留一个 240s 悬挂定时器。常驻宿主里无感知，但短命进程（脚本/测试）会被吊住到自然超时。
- **修复**：定时器句柄落变量，race 结算（无论输赢）后 `clearTimeout`。A/B 实测见上表 ②。

**③ `runs` 内存注册表有界化（修复）**

- **问题**：进程级 `runs: Map<runId, journal>` 只 set 不 delete，且宿主启动时把**全部**历史 journal 灌入内存——常驻宿主跨工作区单调增长（单 run journal 20–200KB：stages 随 QA 打回追加、执行期日志无上限）。
- **修复**：磁盘（`persistJournal`）为权威，内存降级为「最近 `RUNS_MEMORY_KEEP`(100) 条终态 + 全部活跃 run」的有界缓存。终态 checkpoint 落盘**之后** `pruneRuns()` 收缩（淘汰决策 `evictableRunIds` 为纯函数，running 与被 `inFlight`/`activeProducts` 引用的 run 豁免且占排序位）；被淘汰 run 由 `getRun` 统一入口读磁盘回读（**不回填**内存，浏览历史不撑大注册表），`snapshot`/`teamflow_status`/`stageDetail`/`teamflow_merge` 五处读点全部切换。A/B 实测见上表 ③。

**④ resume 查不到 per-project journal 的隐性缺口（修复）**

- **问题**：`resumeRun` 的磁盘读只查全局 `runs/` 路径（`journalFile(id)`）；per-project 新格式 journal（`$DSH_HOME/teamflow/<ws>/runs/`）一直靠宿主启动时 `loadJournals()` 全量回填的**内存**兜底才续得上——一旦内存侧不完整（未来多实例/按需加载），这类 run 就续不了。
- **修复**：新增 `store.loadJournalById(id)`（per-project 优先、全局兜底，与 `persistJournal` 写路径一一对应；runId 走 `^[A-Za-z0-9-]+$` 白名单防路径注入），作为 resume 与 `getRun` 的统一权威读取。A/B 实测见上表 ④。

**⑤ 工程基建：oxlint 0-warning 门禁 + CI lint**

- devDeps 引入 oxlint（选型对齐宿主 deepseek-harness；Rust 单二进制，不受 typescript-eslint 对 TS 6 的适配节奏影响），存量 **210 warnings 清零**（58 处历史死 import 等）。
- CI（`.github/workflows/ci.yml`）在 test/bundle 之前追加 lint 步骤，**warning 即失败**。
- 豁免口径与理由登记于 `AGENTS.md` §4 与 `CONTRIBUTING.md`「Lint gate」：`catch (e) {}` 是刻意的尽力而为风格（`caughtErrors: none`）；`_` 前缀豁免；`no-useless-fallback-in-spread` / `no-new-array` off——`|| {}` 兜底与 `new Array(n)` 在 `strict:false` 鸭子类型下承担**类型角色**（unknown 展开/收窄会让 `runPool` 等消费点类型劣化，实测 tsc 6 错），不是风格偏好，勿"清理"；`while (true)` 的 QA 打回循环为有界设计（`round > QA_REWORK_LIMIT` → break）+ 行内 disable。
- Prettier 刻意暂缓：风格已稳定统一，首跑全仓重排污染 blame 的代价大于收益。

**⑥ 其他**

- dev 并发上限 `8` 三处硬编码收敛为常量（`DEV_MAX_CONCURRENCY` / `DEV_DEFAULT_CONCURRENCY`）。
- `CONTRIBUTING.md` 新增「Lint gate」一节（含"oxlint 会扫未跟踪文件，本地跑 lint 前先清 scratch 目录"的提示）——本节由 TeamFlow 流水线自身产出（patch 档 run `tf-mui8equ6-4vne7g`，新版本代码跑新版本流水线的 dogfooding 验证）。

## English

### TL;DR

- **No breaking changes**: host window unchanged (`>=0.1.7-alpha.1 <0.2.0`); journal format, task-folder contract and `teamflow_*` tool parameters are all backward compatible.
- **Restart `dsh --profile web` after upgrading.**
- **No new features** — this is a defect-fix + engineering-infrastructure release.

### Verification (new this release: A/B behavior verification)

All fixes were verified with one A/B harness: `git archive` exports of **pre-fix** and **post-fix** `host/ + store.ts` into isolated copies (each with its own `DSH_HOME`), host subagent services and private peers stubbed out, then the real `runAgent` / `runTriage` / `executePipeline` / `resumeRun` / `getRun` are driven on both copies and compared:

| Check | Pre-fix | Post-fix |
|---|---|---|
| dispose on normal settlement | 0 of 5 stages | 1 per stage (5/5), after `result` settles |
| triage timeout timer | cleared 0 / pending 1, process hung >120s | created 1 / cleared 1 / pending 0, exit in 171ms |
| bounded `runs` registry (120 seeded histories + a real pipeline run) | 120 → 121 (monotonic growth) | 120 → 100, 21 oldest evicted, fully readable back via `getRun` |
| resume of a per-project journal absent from memory | `Run not found` | resumed to completed |

### Changes

**① Subagents were never disposed on the normal settlement path (fix)** — the `if (run) { ... run.dispose() }` statement in `runner.ts`'s settlement `finally` shared a physical line with the preceding `untrackInFlight(...)` line comment and was swallowed into dead code. Cancel and guard-abort paths disposed; the **normal settlement path never released child sessions**, violating the host contract (`settleRun` in dsh-subagent always disposes after the result settles). Fixed by restoring the statement onto its own line.

**② Dangling triage timeout timer (fix)** — the `Promise.race` timeout in `triage.ts` used `setTimeout` without `clearTimeout`/`unref`, leaving a dangling 240s timer behind every successful triage. The handle is now stored and cleared when the race settles, win or lose.

**③ Bounded in-memory `runs` registry (fix)** — the process-level `runs` map was set-only, and the host seeds **all** historical journals into it at startup — monotonic growth across workspaces in a long-lived host. The disk (`persistJournal`) is now authoritative; memory is a bounded cache of "the newest `RUNS_MEMORY_KEEP`(100) terminal runs + every active run". `pruneRuns()` fires after the terminal checkpoint is persisted; eviction decisions live in the pure function `evictableRunIds` (running runs and runs referenced by `inFlight`/`activeProducts` are exempt but still occupy recency slots). Evicted runs are read back through the unified `getRun` entry (disk read, **never re-added** to memory), and five read sites (`snapshot`, `teamflow_status`, `stageDetail`, `teamflow_merge`) were switched to it.

**④ Latent gap: resume could not find per-project journals (fix)** — `resumeRun`'s disk read only checked the global `runs/` directory; per-project journals (`$DSH_HOME/teamflow/<ws>/runs/`) silently depended on the startup-time bulk memory backfill. New `store.loadJournalById(id)` (per-project first, global fallback, matching `persistJournal`'s write paths; runId whitelist guards against path injection) is now the single authoritative read for both resume and `getRun`.

**⑤ Infrastructure: oxlint 0-warning gate + CI lint** — oxlint introduced (aligned with the host repo; a Rust binary immune to typescript-eslint's TS 6 adaptation timeline), existing **210 warnings reduced to zero** (58 dead imports among them); CI runs lint before test/bundle with warnings-as-failures. Exemption rationale is documented in `AGENTS.md` §4 and `CONTRIBUTING.md`: `catch (e) {}` is deliberate best-effort style; `_`-prefixed bindings are exempt; `no-useless-fallback-in-spread` / `no-new-array` are off because `|| {}` fallbacks and `new Array(n)` carry a **type role** under `strict:false` duck-typing (mechanical rewrites degrade consuming call sites — measured as 6 tsc errors); the `while (true)` QA-rework loop is bounded by design. Prettier is deliberately deferred.

**⑥ Misc** — the dev concurrency cap `8` collapsed from three hardcoded sites into constants (`DEV_MAX_CONCURRENCY` / `DEV_DEFAULT_CONCURRENCY`); `CONTRIBUTING.md` gains a "Lint gate" section produced by a TeamFlow pipeline run itself (`tf-mui8equ6-4vne7g`, patch mode — dogfooding the new code on a real pipeline).

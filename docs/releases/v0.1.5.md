# TeamFlow v0.1.5

[中文](#zh) | [English](#en)

Release — lightweight-mode improvements: the patch mode now truly delivers "single agent changes + self-tests", triage is model-driven (regex narrowed to deterministic guardrails), and several edge-case fixes around triage output, external aborts, and stage gating.

## 中文

### 本次变更

**新增**
- **patch 档兑现「单 agent 直改 + 自测即交付」**：阶段集从 4 段（确认单→技术方案→开发→验收）精简为 2 段（**确认单 → 单 agent 直改**）——无技术方案/QA/验收子代理，开发完成（自测通过）即收口提交。UI 微调（按钮换位置/挪控件/改文案/间距/颜色）、常量/数值调整、单点修复、回滚、笔误修正这类改动现在走最轻路径

**改进**
- **需求分诊重构为模型主导**：档位判断完全交给模型（自然语言语义判断，天然支持中英文需求）；正则从「五档关键词匹配」收窄为确定性护栏（架构信号强升、UI 需求不低于轻量档、显式设计请求升档）。**UI 微调类需求（换位置/挪控件/改文案——不改变行为/交互逻辑）不再被误判为标准功能档**，直接落到轻量档
- **分诊输出失败自动纠错重试**：分诊子代理只输出「Let me output the JSON.」开场白而无实际 JSON 时，自动带纠错提示重试一次（「直接输出 JSON 对象本身」），仍失败才走正则兜底

**修复**
- **外部中止（aborted）不再误报「预算熔断」**：用户重启等外部中止导致的阶段失败，此前会被结算成「token 超预算熔断需人工介入」（实际是阶段累计消耗含成功任务，误导处理方向）——现在单独标记「外部中止」，明确引导断点续跑（补跑失败任务，已完成任务复用）
- **patch 档不再误跑架构蓝图**：阶段集已精简但技术方案块仍无条件执行（架构阶段全模式启用的遗留）——补上门控，patch 直改不再白烧一个架构师子代理
- **分支名不再被档位词污染**：需求文本中的「patch/lite/tech」等档位词不再被提取成分支名（此前「显式的用 patch 模式」会产出 `feat/patch`）
- **provider 错误细节记录**：阶段失败时记录底层错误信息（此前只有 `stopReason=error`，无从排查瞬时/持久错误）

```bash
dsh plugin --profile web add dsh-plugin-teamflow
```

## English

### Changes

**New**
- **patch mode now truly delivers "single agent changes + self-tests"**: stage set slimmed from 4 (confirm → tech → dev → acceptance) to 2 (**confirm sheet → single-agent change**) — no tech/QA/acceptance subagents; a successful dev pass (self-tested) goes straight to the unified closing commit. UI micro-adjustments (moving buttons/controls, copy, spacing, colors), constant/value tweaks, single-point fixes, rollbacks and typo fixes now take the lightest path

**Improvements**
- **Triage is now model-driven**: mode judgment is fully delegated to the model (natural-language semantic judgment, inherently bilingual); the regex was narrowed from five-tier keyword matching to deterministic guardrails (architecture signals upgrade, UI work never below the light tier, explicit design requests upgrade). **UI micro-adjustments (relocating controls/copy — no behavior or interaction-logic change) are no longer misjudged as the standard tier** and land directly in the light tiers
- **Triage auto-corrects prose-only replies**: when the triage subagent replies with only a preface ("Let me output the JSON.") and no actual JSON, it retries once with a corrective hint ("output the JSON object itself"), falling back to the regex verdict only if that also fails

**Fixes**
- **External aborts (aborted) no longer misreported as "token budget tripped"**: a stage failure caused by an external abort (e.g. you restarted) was previously settled as "budget exceeded — manual intervention needed" (the accumulated figure included successful tasks' usage, steering the wrong course). Now it is marked "external abort" with a clear resume hint (failed tasks re-run, completed ones reused)
- **patch mode no longer runs the architecture-blueprint stage**: the stage set was slimmed but the tech block still executed unconditionally (leftover from the architecture-everywhere era) — now gated; patch changes no longer burn an architect subagent
- **Branch names no longer polluted by mode words**: "patch/lite/tech" in the requirement text are no longer extracted as the branch name (previously "explicitly use patch mode" produced `feat/patch`)
- **Provider error details recorded**: stage failures now capture the underlying error (previously only `stopReason=error`, with no way to tell transient from persistent failures)

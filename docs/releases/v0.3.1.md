# v0.3.1 发布说明（取证）

> 版本：`0.3.1`（patch）
> 基线：`v0.3.0` → `HEAD`，**12 笔提交 / 18 个文件 / +1540 −24 行**（`git log v0.3.0..HEAD` 生成）
> 主题：**确认单上的「改 PRD」做成闭环** —— 改写绑定版本、在原 child 上下文里续跑、用量准确、批准语义收紧。
> 本文件是取证与论证；结论层见 `CHANGELOG.md`。

---

## 1. 为什么做这一版

v0.3.0 把「确认单必须由人批准」这道闸门立起来了，但用户提出「要改」时，链路还是断的：

1. 改完 PRD，**上一版的批准没有失效** ⇒ 改过的 PRD 从未被批准却直接开工（issue #11，用户截图实证）；
2. 修成「重出确认单」后加了次数上限（2 次）⇒ 第 3 次直接拒绝，用户只能重开 run、白丢已跑的 PRD；
3. 改写实现是**重跑整个 PRD 子代理**（新 spawn、从零读需求）⇒ 又贵又**漂移**：用户只要求改一处，
   没提的部分也可能被顺手改写；
4. 放开次数后又发现：`confirmApprovedRev` 被模型自己写死 ⇒ PRD 永久改不动。

本版把这条链路补完整，并用真机逐环验通。

## 3. 真机取证

工具链：`dsh --profile web`，插件经 `deploy.mjs --sync` 同步（50 文件），每条 run 均重启宿主后执行。

### 3.1 改写闭环（hy3）

| run | 轮数 | 结果 |
|---|---|---|
| `tf-mvchuuvf-j7kmzk` | 5 版 | 第 4/5 版走续跑；第 5 版**正确删除** `--depth`、保留 `children` 与 stdout/stderr |
| `tf-mvcl5m8t-0qhl8y` | 5 版 | 同上；第 3 版曾因 180s 超时回落（后提到 300s） |
| `tf-mvdeqi60-p48r0f` | 4 版 | 每版都命中续跑、零回落 |
| `tf-mvdhxn6h-87vnog` | 3 版 | 11 条 AC 逐条对上两次要求；旧结构字段只出现在说明性语境 |

**上下文累积的直接证据**：`PRD.v1 → v2 → PRD.md` 的特征计数
（`--depth` 0→16、`children` 0→11），证明第 1 轮加参数、第 2 轮改 JSON 结构的落地情况。

### 3.2 续跑 vs 重跑的成本（同一子代理、按 turn 统计）

| 路由 | 轮次 | 每轮新算 input | cacheRead | 耗时 |
|---|---|---|---|---|
| `workbuddy/hy3` | 重跑 / 续跑 ×2 | 217,782 / 203,350 / 231,713 | 27,904 / 7,744 / 2,368 | 122s / 116s / 163s |
| `deepseek-account/deepseek-flash` | 首版 / 续跑 ×3 | 16,168 / 14,072 / 17,877 / 18,687 | 278k → 1.47M（累计） | — / 84s / 78s |

**结论**：续跑的技术收益（同上下文、不漂移）与路由无关；**成本收益取决于路由是否做 prompt 缓存**——
真机 `workbuddy/hy3` 三轮 `request/header` 前缀 40,790 字节**逐字节相同**（仅末字段 `initial`→`resume`），
但 **`cacheWrite` 恒为 0** ⇒ 服务端没做自动缓存；`deepseek-flash` 有 ⇒ 每轮新算降到 1.5 万量级。

> 判据沉淀：**看 `cacheWrite` 是否恒 0**，别只看 cacheRead（cacheRead 低可能只是前缀变了）。

## 5. 已知未验

1. **桌面版（宿主 `0.2.0-rc.2`）**：本插件 0.3.x 要求宿主 ≥ `0.2.1-alpha.2`，桌面侧需等上游发版。

2. **重复护栏（`log.usageAccumDup`）从未触发**：修复后不再需要它，保留作保险，属于死路径。
3. **超 5 轮改写**未验：上下文会被 compaction 裁剪（窗口 192k），早期内容存在被挤掉的风险。
   缓解手段是快照（文件不丢），但没有量化验证。

## 6. 升级指引

- 无 `engines` 变化，无 schema / journal / 任务夹契约变更。
- 升级后**必须重启** `dsh --profile web`（桌面版重启应用）——插件是构建产物 `lib/host.mjs`，
  进程不重启则仍加载旧代码（本版排查中曾因此误判过一次"修复无效"）。
- 想验证改写是否走了续跑：看日志里 `PRD 改写走**续跑**`；出现 `回落为重跑` 会写明是哪一类原因。

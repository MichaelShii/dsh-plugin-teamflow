# TeamFlow v0.1.9

[中文](#zh) | [English](#en)

Release — a language-and-cleanup release: the whole product surface (workbench UI, host replies, pipeline logs and the artifacts a run produces) now follows your interface language, the plugin's own run logs move out of your project entirely, and a four-day silent failure that stopped runs from committing is fixed for good.

<a id="zh"></a>

## 中文

### 本次变更

**新增**
- **界面中英双语（客户端）**：工作台文案（面板、tab、状态词、按钮、时间格式）跟随宿主语言**实时切换、无需重启**——走宿主 `ctx.locale` 服务（插件注册词典 + slot 声明语言 + 名称用 thunk），不自建 i18n
- **host 侧回复与产物也跟随界面语言**：此前只有界面双语，工具返回、完成汇报、流水线日志、以及 run 产出的 PRD / QA-REPORT / ACCEPTANCE 正文仍是中文。现在**语言在 run 起跑时解析一次并落 run 快照**——同一条 run 内语言一致、断点续跑沿用原语言、你中途切界面语言只影响之后新起的 run；覆盖 11 个 prompt 工厂 + AGENTS.md/memory 模板 + 日志/诊断/注入块/分诊理由
- **运行日志的根离开你的项目**：子代理受宿主文件沙箱约束（只能写会话工作区），所以先在项目内暂存；**run 一结束 host 就把值得留的部分归档到 `$DSH_HOME/teamflow/<workspace>/logs/<runId>/` 并删掉项目内副本**。归档只留**检查脚本、不可重跑的载荷与结论笔记**：实测一次真实 run 里 93% 的体积是可重跑的命令输出或与 git 里一模一样的源码快照，一律丢弃。崩溃/被 kill 的 run 不留残渣（下次同工作区起跑自动清扫），每个工作区保留最近 20 次
- **不再制造输出 dump**：子代理被明确要求**不要**把命令/套件输出重定向进文件——长输出本来就由宿主截尾并把全文 spill 到它报告的临时路径（DSH 原生能力）。少掉的正是「一次 run 写 23 个 `.out` + 5 个 `regression-*.log`（1.2 MB，占其产出文件 41%）」这类噪音
- **缺陷卡终于看得见「缺陷是什么」**：点开一张缺陷卡，现在能看到**复现步骤 / 期望行为 / 实际行为 / 关联验收项**（此前这四列在解析时被整列丢弃，卡上只有合成标题），标题也变成自解释的「R3-1 · 日志/注入面」；打回修复时给开发看的缺陷清单同样带上完整描述
- **QA 返工治理（A/B/C 三件套 + E）**：实测真正的返工来自「修复不完整 / 扫描面不完整」，不是缺陷多——**A** 每个 P0–P2 修复必须落**永久可执行门禁**（修复前失败、修复后通过）并在证据块里给出命中数 before→after；**B** 缺陷行新增 `检测命令` + `通过判据` 两列（缺陷的**可执行定义**：修复方据此验收、复验方据此回归、误报用它当场证伪）；**C** 复验轮必须先**原样重跑上一轮探针**再补未覆盖的面，不得重造基线。**E**：QA 打回超限时不再整段跳过验收，改为以**「已知问题」只读模式**跑一次验收（产出验收表 + 未闭环阻断缺陷清单），但结论一律**强制需人工裁定**——插件永不放行合并
- **QA 轮次收敛埋点**：每轮把阻断缺陷的**稳定身份**（检测命令优先 > 模块+实际文本 > 缺陷 id）与增/减/停滞计数写进 journal，并配一个只读报表脚本（`scripts/qa-rounds-report.mjs`：收敛 vs 停滞、检测命令可用率、门禁落地率、单轮成本）——**先看数据再决定要不要动轮次上限**
- **决策记录 ADR-0009**：不做插件级用户记忆层（跨产品线的用户偏好不属于「一需求一链路」的批处理场所，宿主原生 `AGENTS.md` 已覆盖该需求）

**修复**
- **收口提交静默失效 4 天（2026-09-11 → 09-15 所有 run 跑完都没提交）**：上一版的提交面有两处写法互相拆台——先把 `logs/teamflow/` 写进 `.gitignore`，紧接着又用负 pathspec **点名**这个已被忽略的路径，git 直接报错退出（索引其实已写好），而代码用这次 add 的结果**短路**了提交，三条日志一条都不触发 → **坏了 4 天，日志上一个字都没有**。现在：整树 add + **索引兜底**（只动索引、不删你的文件）+ **提交结果决定日志级别**（失败带 git 的真实原因），并新增**真 git 集成测试**把这个坑锁死
- **缺陷解析按表头认表**：旧实现按「第 2 格是不是 P 级」认缺陷，于是 QA 报告里的「复验对照表」被登记成新的阻断缺陷 → 每轮复验重生一个 → **必然超限停线并跳过验收**（自我实现的停线，与交付质量无关）。现在只有**表头显式声明严重级列**的表格才解析
- **未验收的 run 不再邀请合回 main**：合回指引要求「已完成 + 无人工介入 + 验收阶段真的跑过」，并在需人工介入时显式提示不要据此合回
- **英文界面下的三处漏点**：阶段子代理回复语言、给模型的工具返回/会话注入语言、团队展示名（`teams.json` 只有中文时按内置英文名回落，不改写你的文件）
- **缺陷表转义管道符错列**：单元格里按契约转义的 `\|` 此前照样被切开，导致「实际」串进「关联验收项」——而新增的检测命令列几乎必然含 `|`

**改进**
- 归档/清理/保留策略全部集中到日志生命周期一处（白名单、自愈清扫、保留 20 次、活跃 run 豁免、失败只 warn 不阻断收尾）
- 提交面从「两道防线」升级为三道：`.gitignore` 幂等补写 + 索引兜底 + 失败可见（`npm publish` 的内容与仓库源码一致，无运行时新增依赖）

**已知待办**
- **E（超限时的只读验收）在真实场景里还没出现过**（需要 QA 打回超过 2 轮），目前只有契约级门禁
- P3 遗留：`clip()` 截断标记尚未本地化（`…[已截断 N 字符]` 会出现在英文注入文本里，41 个调用点需分批处理）；`teamflow_*` 工具描述内嵌中文状态名（插件**加载期**注册、此时还没有语言源，且中文短语对中文需求的触发有正向作用——先定判据再动）
- `$DSH_HOME/teamflow/` 下 `runs/` 与只写过 `teams.json` 的空壳目录仍无遗忘机制（`logs/` 已有）
- 护栏的**复读检测**仍在读宿主已弃用的事件读取器（提醒通道与挂死判据已迁到官方投影）
- 归档保留的检查脚本若用相对路径 import 项目文件，搬走后不再能原地重跑（输出已留在归档笔记里）

### 安装

```bash
dsh plugin --profile web add dsh-plugin-teamflow
```

安装后需重启 `dsh --profile web` 才生效。

## English

### Changes

**New**
- **Bilingual UI (client)**: workbench text (panels, tabs, status vocabulary, buttons, time formatting) now follows the host language and **switches live — no restart** — through the host `ctx.locale` service (the plugin registers a dictionary, declares the locale per slot, and uses thunks for names). No home-grown i18n
- **Host replies and artifacts follow the interface language too**: previously only the UI was bilingual — tool returns, completion reports, pipeline logs and the PRD / QA-REPORT / ACCEPTANCE text a run produces were still Chinese. The language is now resolved **once when a run starts and snapshotted on the run**: consistent within a run, preserved across resumes, and switching the interface language later only affects runs started afterwards. Covers 11 prompt factories + the AGENTS.md/memory templates, logs, diagnostics, injected blocks and triage rationale
- **The run-log root moves out of your project**: sub-agents are confined by the host file sandbox (they can only write the session workspace), so they stage inside the project; **as soon as the run ends the host archives what is worth keeping to `$DSH_HOME/teamflow/<workspace>/logs/<runId>/` and deletes the in-project copy**. Only **checkers, non-derivable payloads and conclusion notes** survive: measured on a real run, 93% of the bytes were rerunnable command output or an exact copy of something already in git, and all of it is dropped. A crashed/killed run leaves no residue (the next run in the same workspace sweeps it automatically), and each workspace keeps its latest 20 runs
- **No output dumps are manufactured**: sub-agents are explicitly told *not* to redirect command/suite output into files — long output is truncated to its tail by the host, which spills the full text to a temp path it reports (native DSH behaviour). What disappears is exactly the old noise (one run wrote 23 `.out` files + 5 `regression-*.log`, 1.2 MB, 41% of its produced files)
- **Defect cards finally show what the defect is**: opening a card now shows **steps to reproduce / expected / actual / related acceptance criterion** (these four columns used to be discarded during parsing, leaving only a synthesized title), and the title is self-explanatory ("R3-1 · logging/injection surface"). The same full descriptions now reach the developer during a rework round
- **Rework governance (A/B/C, plus E)**: measurements showed real rework comes from *incomplete fixes / incomplete sweeps*, not from defect volume — **A** every P0–P2 fix must land a **permanent executable gate** (fails before, passes after) with before→after hit counts in the evidence block; **B** defect rows gain `Check command` + `Pass criterion` (the defect's **executable definition**: the fixer verifies against it, the re-verifier regresses with it, and a false positive is disproved on the spot); **C** a re-verification round must **re-run the previous round's probes as-is** before covering new ground, and must not rebuild baselines. **E**: when QA bounces exceed the limit, acceptance is no longer skipped entirely — it runs once in **"known issues" read-only mode** (acceptance table + open blocking defects), with the verdict **forced to human adjudication**; the plugin never authorises a merge
- **QA convergence instrumentation**: each round records the blocking set's **stable identity** (check command first, then module + actual text, then defect id) plus new/repeat/resolved counts into the journal, with a read-only report script (`scripts/qa-rounds-report.mjs`: converging vs stalling, check-command availability, gate landing rate, per-round cost) — **measure before touching the rework limit**
- **Decision record ADR-0009**: no plugin-level user memory layer (cross-product user preferences have no place in a "one requirement, one pipeline" batch flow; the host's own `AGENTS.md` already covers it)

**Fixes**
- **Four days of silently skipped commits (2026-09-11 → 09-15, every run finished without committing)**: two parts of the previous commit surface worked against each other — the plugin appended `logs/teamflow/` to `.gitignore` and then a negative pathspec **named** that now-ignored path, so git exited with an error (the index had in fact been written) while the code **short-circuited** the commit on that result and triggered none of its three log branches → **broken for four days with nothing in the log**. Now: whole-tree add + an **index safety net** (index only, your files stay) + **the commit result decides the log level** (failures carry git's real reason), locked in by a new **real-git integration test**
- **Defect parsing now recognises tables by their header**: the old implementation treated "is cell 2 a P-level?" as a defect, so QA's "re-verification comparison" table was registered as a new blocking defect every round → guaranteed to exceed the rework limit and skip acceptance (a self-inflicted stop line unrelated to delivery quality). Only tables whose header explicitly declares a severity column are parsed now
- **Runs that never reached acceptance no longer invite a merge to main**: the merge hint requires "completed + no human intervention + acceptance actually ran", and says explicitly not to merge when human adjudication is pending
- **Three gaps found by the first English run**: sub-agent reply language, the language of tool returns/session injections, and team display names (`teams.json` files that only carry Chinese now fall back to built-in English names — your file is never rewritten)
- **Escaped pipes in defect tables no longer shift columns**: a cell escaped as `\|` was still split, pushing "actual" into "related acceptance criterion" — and the new check-command column almost always contains a `|`

**Improvements**
- Archiving, sweeping and retention now live in one place (whitelist, self-healing sweep, keep 20 runs, active-run exemption, failures warn without blocking the run's closing steps)
- The commit surface went from two guards to three: idempotent `.gitignore` write + index safety net + visible failures (the published package matches the repository source; no new runtime dependencies)

**Known follow-up**
- **E (read-only acceptance on exceeding the rework limit) has never occurred in a real run** (it needs more than 2 QA bounce rounds); today it is covered by contract-level gates only
- P3 leftovers: the `clip()` truncation marker is not localised yet (`…[已截断 N 字符]` can appear in English injected text; 41 call sites to do in batches); `teamflow_*` tool descriptions embed Chinese state names (registered at plugin **load time**, before any language source exists, and the Chinese phrases help trigger on Chinese requirements — decide the predicate first)
- Under `$DSH_HOME/teamflow/`, `runs/` and the empty shells that only ever got a `teams.json` still have no forgetting mechanism (`logs/` now does)
- The guard's **repeat detection** still reads the host's deprecated event readers (the reminder channel and the hang criterion moved to official projections)
- An archived checker that imports project files by relative path can no longer be re-run in place after the move (its output is preserved in the archived notes)

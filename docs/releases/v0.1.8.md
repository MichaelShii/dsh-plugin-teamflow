# TeamFlow v0.1.8

[中文](#zh) | [English](#en)

Release — a workbench-and-gate release: the workbench becomes an app-level panel you can open without a session, and two long-standing gate bugs are fixed — honest "cannot run this here" reports are no longer judged as non-delivery, and the circuit breaker no longer trips on the first failed attempt.

## 中文

### 本次变更

**新增**
- **全局团队工作台（应用级主面板）**：工作台从「某个会话里的一个 tab」升级为应用级主面板——左侧边栏多一个图标，点开后中央主区整块换成 TeamFlow：左栏是按产品线组织的列表（每条产品线的流水线数量、活跃数、最近需求与验收结论），右栏是该产品线的流水线 run 与 backlog（需求 / 任务 / 缺陷）。**它不依附某个会话**：关掉对话、切到别的项目，面板照样能看到全部历史
- **流水线详情进右侧栏**：点任意一条 run，就在右侧栏打开完整详情（阶段表、token 用量、阶段详情、验证证据、产出文件、日志）
- **状态徽章可点筛选（多选）**：分组行上的状态计数现在可以直接点。真实问法往往是「还没结束的有哪些」，所以支持**多选**——同时勾选「进行中 + 待验收 + 需人工」即可一次看清。筛选会覆盖默认折叠（勾了终态就自动展开，不会出现点了却看不到卡片的情况），行尾显示「筛选中 N 项 · 显示 x/y × 清除」
- **入口指向「发起会话」**：从全局面板点产物或 run 详情时，会先切到**这条 run 真正所属的会话**再打开——右侧栏是会话级的，旧行为跳回的是你当前所在的会话，与这条 run 无关

**修复**
- **交付判定不再因措辞误杀**：过去只要回复里出现「无法执行」这类拒绝词，就被判定为未交付，即使它其实诚实地报告了环境限制、并附上了完整的验证证据（命令 + 退出码 + 断言计数）。现在判定分三级：先看有没有实质产出，再看有没有验证证据块，**只有在既没有证据块、又命中拒绝词时才判未交付**。措辞只作为诊断留痕，不再当门禁
- **熔断不再「一次失败就停」**：阶段预算原先包含缓存重放，导致任何任务失败一次就立刻熔断、自动重试形同虚设。现在熔断只看**真实新增**的消耗（不含缓存命中），阈值 200k；汇报与工作台展示仍按官方 billed 口径，两套口径严格分开
- **收口提交不再卷入插件自己的日志**：插件会要求子代理把命令输出与临时脚本写进 `logs/teamflow/`，而这些本就不是交付物。现在提交面用 pathspec 强制排除该目录，并在提交前幂等补写 `.gitignore`（不依赖你的仓库有没有配好）——一次收口提交里绝大部分「噪音文件」从此不再出现
- **日志布局收口，路径写全**：要求每个用途只用一个文件、重跑时追加而不是新建变体（`-run2` / `-nopipe`…），避免同一份套件输出被反复落盘。同时所有路径改为完整限定路径——此前写成 `scripts/`、`probe/` 这类通用目录名时，模型会理解成项目根目录，把一次性草稿建到了仓库根
- **一批工作台显示与交互修复**：右栏详情不再卡在「读取中」（取地址改走宿主绑定的 hook）；去掉二次解包与空信封静默失败；修复一处 React hook 归属错位导致的崩溃；面板不再顶出外层页面滚动条（改按宿主高度契约布局）；恢复看板列内滚动与表头吸顶；窄列里的数字行不再顶破面板；详情浮层收敛为单一事实源（不用关两次）；重复点同一条产品线不再无响应

**改进**
- **全局面板布局重做**：主区改为标签页（流水线 run ｜ Backlog），一次只显示一个列表；详情改为覆盖式浮层，不再和列表抢宽度。此前四栏并排 + 自适应在常见窗口宽度下必然拥挤（卡片被压窄、行折行、展开后滚不动）
- **展示层收拢**：主题、状态词表、格式化（token 口径、时间、耗时、折叠文本）统一到一处，会话内工作台与全局面板共用，两处展示语言不会再各自漂移
- **宿主 slot 契约对齐**：补齐 slot 归属声明与对应的 optional peer，避免加载顺序不确定时出现的「slot 不存在」

**已知待办**
- 全局面板目前**只读**（没有 backlog 流转的写路径）
- 熔断阈值仍是常量，还没做成可配置项
- 护栏的**复读检测**仍在读宿主已弃用的事件读取器（提醒通道与挂死判据已迁到官方投影，复读需要流式文本内容，官方替代方案待定）

### 安装

```bash
dsh plugin --profile web add dsh-plugin-teamflow
```

安装后需重启 `dsh --profile web` 才生效。

## English

### Changes

**New**
- **Global team workbench (app-level panel)**: the workbench moves from "a tab inside one session" to an application-level panel — a new icon in the left sidebar swaps the whole main area to TeamFlow: the left column lists product lines (pipeline count, active count, latest requirement and acceptance verdict), the right column shows that product line's pipeline runs and backlog (requirements / tasks / defects). **It is not tied to a session**: close the conversation or switch projects and the panel still shows the full history
- **Pipeline detail in the right sidebar**: clicking any run opens its full detail in the right sidebar (stage table, token usage, stage detail, verification evidence, artifacts, logs)
- **Clickable status badges (multi-select)**: the status counts on a group row are now clickable. The real question is usually "what is still unfinished", so selection is **multi-select** — tick "running + pending acceptance + needs human" and see everything at once. Filtering overrides the default collapse (selecting a terminal state expands it, so you never click "accepted 19" and see nothing), and the row shows "filtering N · showing x/y × clear"
- **Entries point at the originating session**: opening an artifact or run detail from the global panel first switches to **the session that run actually belongs to**. The right sidebar is session-scoped; the old behavior switched back to whatever session you happened to be in, which had nothing to do with that run

**Fixes**
- **Delivery judgement no longer fails honest reports**: previously any reply containing a refusal phrase such as "cannot execute" was judged as non-delivery, even when it was honestly reporting an environment limitation and attaching complete verification evidence (command + exit code + assertion count). Judgement is now three-tier: objective substance first, then a real delivery signal (the verification-evidence block), and **only when there is no evidence block and a refusal phrase is hit does it judge non-delivery**. Wording is now diagnostic only, never a gate
- **The circuit breaker no longer trips on the first failure**: the stage budget used to include cache replays, so any single task failure tripped the breaker immediately and made automatic retries dead code. The breaker now counts only **newly generated** consumption (cache hits excluded), threshold 200k; reporting and the workbench still use the official billed basis, and the two bases are kept strictly separate
- **Closing commits no longer sweep in the plugin's own logs**: the plugin asks sub-agents to write command output and scratch scripts into `logs/teamflow/`, and those were never deliverables. The commit surface now force-excludes that directory via pathspec and idempotently appends to `.gitignore` before committing (independent of whether your repository configures it) — the bulk of "noise files" in a closing commit are gone
- **Log layout consolidated, paths fully qualified**: one file per purpose, and a re-run appends instead of creating a new variant (`-run2` / `-nopipe` …), so the same suite output is no longer re-dumped to disk. All paths are now fully qualified — previously, generic directory names like `scripts/` or `probe/` were interpreted as the project root, and one-off scratch files landed at the repository root
- **A batch of workbench display and interaction fixes**: right-sidebar detail no longer stuck on "loading" (address now read through the host-bound hook); removed double-unwrapping and silent empty-envelope failures; fixed a React hook-ownership mismatch that caused a crash; the panel no longer pushes out the outer page scrollbar (now laid out to the host's height contract); restored in-column scrolling with sticky headers; numeric rows no longer overflow narrow columns; the detail overlay is a single source of truth (no more closing twice); re-clicking the same product line is responsive again

**Improvements**
- **Global panel layout reworked**: the main area is now tabs (pipeline runs ｜ backlog), showing one list at a time; detail became an overlay that no longer competes for width. The previous four-column layout with auto-fit was guaranteed to be cramped at common window widths (narrow cards, wrapped rows, unscrollable expansions)
- **Display layer consolidated**: theme tokens, status vocabulary, and formatting (token basis, time, duration, folded text) now live in one place shared by the in-session workbench and the global panel, so the two can no longer drift apart
- **Host slot contract aligned**: slot ownership declarations and the matching optional peers are filled in, avoiding "slot does not exist" under nondeterministic load order

**Known follow-up**
- The global panel is currently **read-only** (no write path for backlog transitions)
- The circuit-breaker threshold is still a constant, not yet configurable
- The guard's **repeat detection** still reads the host's deprecated event readers (the reminder channel and the hang criterion moved to official projections; repeat detection needs streaming text content, and the official replacement is still being designed)


# TeamFlow v0.2.0

[中文](#zh) | [English](#en)

Release — 一次「能力扩张 + 兼容性收紧」的大版本（69 次提交 / 90 个文件 / +5,785 −425 行）：流水线可以随时中断，需求开跑前先过一道澄清闸门，交付形态成为 PRD 的必填验收项，新增能力全程中英同步，运行日志与用户仓库的边界收到「**绝不改写你的 `.gitignore`**」，判定与诊断多处收紧，并适配 dsh 0.1.7-alpha.1 的破坏性宿主变更（**升级前请先升 dsh**）。

## 中文

### ⚠️ 升级要点（必读）

- **⚠️ 破坏性：宿主下限抬到 dsh `>=0.1.7-alpha.1 <0.2.0`（升插件前先升 dsh）**——0.1.7-alpha.1 的 session format v4 在事件被 Session 采纳**之前**校验 `source.kind`，拒绝 v3 退役的 `{ kind: 'plugin', plugin: 'x' }` wrapper；而 0.1.6-alpha.2 及更早**没有** `session-format-v3-to-v4` 包，其 source kind 是封闭白名单、**不含 `plugin:*`**。两种形态互不兼容，跑错版本的后果不是「某个阶段失败」而是**整条 run 在事件写入阶段直接抛错失败**（实测 probe-v3 的 journal 因此没落盘，目录里只有 `teams.json`）。插件的四处注入事件（团队上下文 ×2、完成汇报、护栏提醒）已全部改为命名空间形态 `{ kind: 'plugin:dsh-plugin-teamflow', ... }`；解析过插件事件的第三方需按 v4 适配。
- **行为收紧（非可选）：档位不再由模型自选 + 澄清闸门生效**——省略 `lite`/`mode` 即交给自动分诊（分诊判 ≥medium 而调用方选了轻档位时**强升档**）；除 `patch` 档外**一律**过分诊，所以第一次启动**可能被问一轮 must-know 问题**——这是设计，不是故障。已给过澄清答复就不再拦，残余疑点转为 PRD 里的显式假设。
- **新增早停 + 判定收紧 + 安装变更**——工作区起不了命令时约 15 秒内停手上报（新增 `env-unavailable` 信号，不再误报成「输出被截断」、不再自动重试），修好工作区后 `teamflow_resume` 续跑并复用已完成阶段与产物；验收结论只认**字面量结论行**、缺陷只认**显式严重级表头**、dev 任务身份用 `dt-N`（历史 journal 兼容，续跑按新规则判定）；安装入口改**运行时探测**（源码运行 / profile 名非 `web` 都能给出正确指令），安装步骤由**主 agent** 执行；`logs/teamflow/` 永不入提交，且噪音排除**不再改写你的 `.gitignore`**。

### 本次变更

**① 流水线可中断（新增）**
- **界面三处入口都能中断在跑的流水线**：会话内工作台顶栏「⏹ 中断 #xxxxxx」、全局面板 run 行、run 详情头（右栏 tab 与面板浮层），共用同一个**两段式内联确认**按钮（首次点击进入「确认中断?」，3 秒内再点才执行——客户端没有宿主 confirm/对话框依赖，不引新依赖；面板里整行可点开详情，按钮自己 `stopPropagation`）。
- **中止走宿主官方 `SubagentRun.dispose()`**（官方契约「cancel remaining work, reach child quiescence」），并新增 host 侧 `status === 'running'` 门禁：此前 `cancelRun` 对任何「内存里存在」的 run 都置 `cancelled` 并返回成功——对已完成的 run 是**污染 journal**，对重启后回填的 interrupted run 是「提示成功但状态永远不变」；现在取消失败对界面可见（工作台报「已不在运行中」，面板给提示），而阶段间隙（`inFlight` 为空）仍可取消。
- **并发 dev 一次全停**：`inFlight` 改为 runId → Map<stage, run> 多路追踪；并发池加 `shouldStop` 判定，取消后**不再补位取新任务**（此前表现为「中断了又自动启动一个」）。
- **收尾与留痕**：终态归一移到 `finally` 首句（取消走正常返回时 run 曾卡在「运行中」）；dev 的收口（取消检查 + 提测门禁）移到 `resume`/`else` 的汇合点，两条路径不再各写一份；取消来源落盘，取消态**不再给模型续跑引导**，取消的 run **不产生提交**；取消只置位不改状态机。
- **显示修正**：被中断的阶段不再显示成「已关闭 / Closed」（`client/locales.ts` 的 `status.*` 是 backlog 卡片词表，`closed`/`cancelled`/`verified` 都译「已关闭」，阶段面直接复用导致误显示；新增阶段级词条 `stageStatus.cancelled` =「已中止 / Stopped」）；相位组头取色同理——`cancelled` 曾与 `failed`/`needs-human` 并列，用户主动中断被涂成**错误色（红）**，而同一节点里的阶段卡竖条与「已中止」chip 是灰的（红头灰身）。
- 新增 `test/cancel.test.js`（30 断言，真行为级）：门禁真值表 / 置位 + dispose + 落盘 / 阶段间隙可取消 / dispose 抛错不吞取消 / descriptor↔服务↔三处 UI 入口同源。

**② 需求澄清闸门与分诊收紧（新增 + 修复）**
- **探索态需求不再直接开跑**：社区讨论（deepseek-ai/deepseek-harness#6405）两位用户的反馈命中同一条缺口——①「我想开发一个 dsh 插件」这种陈述式探索不匹配疑问句式正则 → 直接跑完整条流水线，用户原话「我都不知道自己想要啥，它做完了」；②「意图澄清需要 agent 与人对话，子代理形态怎么做」——宿主 `DELEGATED_CALLER` 与 `exit_plan_mode` 都**拒绝存活子级**，故澄清只能由 host 发起、落主线程。做法：启动前复用「本来就要跑的那一次分诊」做预检，命中 must-know 即返回 `needs-clarification` 并**不建 run**；主线程问清后把答复放进新参数 `requirementSupplement` 重调（PRD 收到 `[CLARIFIED]` 权威输入，明令不得再自行假设）。
- **合格线由 host 判，不靠模型自觉**：`qualifyBlockers` 要求每条必须同时给出「≥2 个互斥读法 + 改变哪个 AC/范围 + 猜错要返工什么」，三项缺一即丢弃并记 warn（上限 3 条）——否则「模型几乎总能为任何需求凑出问题」，闸门会退化成每次都打断。
- **档位不再由模型自选**：根因是**我们自己的参数描述在推荐它**——`lite` 的说明写着 "(recommended)"，模型在推理里逐字引用（`testb`：「lite: true (最小可用版, small change) — recommended for small changes」）。量化：全部 22 会话 / **33 次 `teamflow_start`** 里带 `lite` 6 次、带 `mode` 8 次（**0 次**先跑 `teamflow_triage` 预览）→ **14/33（42%）的启动完全跳过 triage**，澄清闸门与「架构信号 → 至少 medium」护栏在近一半启动上静默失效。修法两条：删掉 "(recommended)"；除 `patch` 外一律过分诊，调用方选了轻档位而分诊判 ≥medium → **强升并落 `log.modeUpgraded`**。同批修掉：分诊判 `lite` 而调用方显式传了 `needDesign=true`（`lite` 的定义就是「no UI design」，两者语义冲突）——未给档位且 `needDesign=true` 时由宿主抬到 ≥medium。
- **闸门收敛与权威判定**：实测 `dddd` 工作区里模型 **6 次** `teamflow_start` 全部返回 `needs-clarification`、**没有创建任何 run**，blocker 数 3 → 2 → 2 始终绕同一个问题（分诊输入只有需求原话、澄清答复从没进过分诊）。修法：分诊输入改为 `requirement + [CLARIFIED] requirementSupplement`；**没给过答复才拦**，已给过 → 不再拦，残余 blocker 作假设开工并记 `log.clarifyProceedWithAssumptions`（假设进 PRD「假设与待澄清」段、汇报高亮）。另外把**权威判定从「工具内预检」移到 pipeline**（实测 `testc`：预检当场抛错被吞掉、静默退成正则兜底，`teamflow_start` 总耗时 0.4 秒而模型分诊实测 1.5–1.9 s；差别只在预检漏传了 `exec.signal`），并新增 `abortForClarification` 兜底。
- **分诊本身修复**：超时 90s → 240s（截图实锤：推理中的分诊被 dispose，fallback 原因现已可见化）；加短期缓存（消除决策返回路径的重复分诊，缓存有效性改「待决策状态机」，TTL 不再承担正确性）；加**自洽门禁**——需求原文已写明「装进我的 dsh web profile 里真实可用」、分诊自己已判 `installable: true`，却同时抛出「要不要真能装进 profile」的 blocker（凭空造出一轮澄清 → 输入变了 → 缓存必然不命中 → 同一需求被分诊两次）；现在 `settles` 字段与已判值自相矛盾的条目被丢弃并计入 `blockersDropped`。
- **交互与注入闭环**：闸门/决策统一走 `ask_user_question` 点选（readings 本就是互斥选项，天然适配）；`start` 的输出 schema 补声明 `kind`/`message`（此前 git-init 决策与 paused/no-team 返回路径被宿主 `additionalProperties:false` 当场拒收——实测两次 start 失败、零 run）；团队选择注入补「澄清前置 / 澄清后务必回带开工（原话进 `requirement`、结论进 `requirementSupplement`）/ `needs-clarification` 怎么处理」三段（实测 `session-518e9188`：团队注入已下发，但模型 0 次调用工具、该产品线 runs = 0，闸门根本没机会执行）。同批修掉两处自伤：`__triage` 等内部字段被 `execOptions` 白名单丢弃、PRD「假设段」的正则匹配不到**编号标题**（`## 3. 假设与未知` 这类写法提取为空）。

**③ 交付形态契约与验收判定（新增 + 修复）**
- **交付形态契约：把「形态本身隐含的验收标准」变成 PRD 必填的可测 AC**（防「看着完整却装不上」）：事故是「一个看着完整的 dsh 插件（host/src/client/lib 全有、功能 AC 全绿、QA 还真查出 3 个缺陷并打回修复、验收 ✅ 通过）却装不进 profile」——缺 `cordis.patch.yml`、缺 `package.json` 的 `dsh.bundle.patch` 声明、`files` 白名单漏文件、依赖用了 `workspace:`。根因不是模型没做好，而是 **AC 里从来没有「宿主可加载/可安装」这一条**。做法：分诊新增一个正交维度 `artifact` + `installable`（用单选维度覆盖所有交付物类型，新形态只加枚举值），host 侧 `ARTIFACT_CONTRACTS` **契约数据表**（新增一类交付物 = 加一行数据，不加判定逻辑）展开进 `state.__runCtx` → `prdPrompt` **强制**把它们写成可测 AC。
- **非 dsh 宿主不再套用 dsh 契约**：用户质疑「我开发 openclaw 插件，或者 hermes 插件，你如何识别不同的场景？这些在 dsh 的契约在其他的不一定有效吧」——质疑是对的：`plugin-host/plugin-client/plugin-full` 是 **dsh 私有词汇**（profile 层入口声明 / `dsh.bundle.patch` / `dsh.client` 块 / `files` 白名单），给 hermes / pi / OpenClaw 的插件套 dsh 契约等于反向返工。修法：新增与 `artifact` 正交的 `ArtifactHost = 'dsh' | 'other' | 'unknown'`，`plugin-*` 且 `host !== 'dsh'` → **0 条本仓契约**，改为要求 PRD 产出**「宿主契约调研」段**且是**硬门禁**（缺段 = PRD 阶段失败走重试；行式解析，**空标题不算**——否则模型学会只写标题就过）；模型判 `unknown` 而需求含 dsh 标识词（`dsh`/`@deepseek-ai/dsh-*`/`deepseek-harness`/`cordis`）→ 确定性护栏抬为 `dsh`（不覆盖模型明确判的 `other`）。
- **契约判据补两条实锤**：① UI 挂载点 `register.name` **必须是 slot 名**——流水线交付的 Markdown 表格对齐器把插件自己的标识 `md-table-align.dock` 当成了 slot 名，与 `ctx.slots.inject('conversation.input.dock', …)` 对不上 → **静默不挂载、工具条永不出现**，而它的功能单测 **31/31 全绿、验收 ✅ 通过**；② 契约样本来源改为「**本机已安装的 dsh 插件**」——原实现写的是「去读**本仓**已有的同类插件样本」这个**本仓相对路径**，而 `npm pack` 显示发布包**只有 10 个文件、不含源码**，npm 用户的孤立工作区里那条路根本不存在（probe-v2 恰好在工作区位于本仓 `plugins/` 下时成立，即那轮「有参考」其实是**测试被喂了答案**）。
- **安装/装载安全三条契约 + QA 形态探针**（安装事故驱动）：插件装进 profile 后**重启宿主起不来（P0）**——根因是 `lib/index.js` 是**旧构建产物**（源码里已修的 `ctx.inject(['settings'])` 没进产物），最后靠另开一个 agent 把插件卸载才救回宿主。三条契约：**① 构建产物与源码同步**（安装前重新构建；产物含当前源码特征字符串或 mtime 晚于全部 src）；**② 装载安全**（模块顶层不得抛错，判据 `node -e "require('<产物入口>')"` 退出码 0）；**③ 安装必须带回滚**（安装前写明卸载命令，装后验证失败 → **先回滚再报告**，绝不把宿主留在起不来的状态）。`stateSliceFor` 对 qa/acceptance 下发契约清单，`qaPrompt` 增 **0b 节**把契约项变成必跑探针（命令 + 退出码进 `QA-REPORT.md`），环境做不到的（需重启宿主）必须进人工补测清单、不得沉默。
- **修掉「交付形态契约整条链从未生效」**（第五次白名单漏字段）：`triageRecordOf` 只搬 9 个字段、漏了 `artifact` 与 `installable`，于是 `normalizeArtifact(undefined)` = `'other'` → 契约恒为 `[]` → **`[交付形态契约 · 必填 AC]` 从未注入过任何 PRD**，`qaPrompt` 的 0b 形态探针同理。**实测（不是推断）**：全部 **64/64** 个 run 的 `triage` 都不带 `artifact` 字段，`log.artifactContract` 一次都没落过。顺带抓出我自己写错的一处：接口声明叫 `upgradedFrom`，三处写入点写的却是内部标记 `__upgradedFrom`，搬运时读 `.upgradedFrom`（没有任何人写它）→ `log.modeUpgraded` 静默消失。并立**接线门禁**（照 `state.test.js` 的做法：静态解析 `TriageVerdict` 接口顶层键、逐个断言真的被搬运，豁免表本身也被断言）。
- **判定收紧**：
  - **验收结论行只认字面量模板行，且有多个时取最后一个**——真实产物第 11 行是章节标题 `## 1. 验收结论摘要`（含那四个字却不是结论行），旧实现用 `.find()` 取**第一个**含「验收结论」的行 → 取到标题 → 四档词全落空 → **明明通过却判 needs-human**。现只认行首 `验收结论：` / `整体结论：` / `Acceptance verdict:` / `Overall verdict:`（允许 `## `、列表符前缀），**不认** `**验收结论：**` 这类加粗破坏冒号连写的写法（宁严勿松）。
  - **「📝 需求不适用」改行首锚定**——真实报告在正文里论证「为什么不判『📝 需求不适用』」，旧实现走**全文匹配** → 命中标题里的引用 → 判 `reject`（而且 `journal.humanIntervention` 还是 false，与 error 文案自相矛盾）。现在剥掉 markdown/列表/表格前缀后该行必须以 📝 + 需求不适用**开头**才算；📝 出现在句中 → 落 needs-human。顺带补上 `reject` 分支缺失的 `humanIntervention = true`。
  - **缺陷解析只认显式声明严重级列的表头**：旧实现按「第 2 格是不是 P 级」认缺陷，于是 QA 报告里的「复验对照表」被登记成新的阻断缺陷 → 每轮复验重生一个 → **必然超限停线并跳过验收**（自我实现的停线，与交付质量无关）。
  - **doc 类阶段回复过短不再等于「没交付」**：真实链条是三步——PRD 子代理 17 次调用里 14 次是空转式探索，最后只回了一个 state 块（284 字符）→ 284 < 下限 400 → 判「视为未交付」，而 `PRD.md` 其实已落盘 4894 字节、还调了 `present`；→ 该阶段 fresh **259k > 200k** → 预算门把本该有的自动重试拦掉 → `failed` + 需人工。现在回复不合格时**回读任务夹产物**（按阶段给候选文件名，取最长的一个），文件在且达该阶段长度下限 → 判交付并记 warn；**兜底不豁免非空回复**（pipeline 要用回复合并 state 块）。
  - **熔断预算随 provider 缓存能力自适应**：`FRESH_TOKEN_BUDGET = 200k` 的立论是「cacheRead 是廉价重放」（有缓存 provider 上实测 1.2–2.4k/次），而**不缓存的 provider 上每轮工具调用都要重付 system prompt + 工具定义（实测 ~15.5k/次）** → 200k 退化成「一个阶段最多约 13 次调用」。新增 `metering.effectiveFreshBudget`：命中率 <50% 且调用数 ≥5 判「该 provider 无缓存」→ 预算 ×3，熔断日志用独立措辞 `diag.breakerUncached`；有缓存的 provider 分毫不动。

**④ 双语链路与展示回归（改进 + 修复）**
- **新增能力全程中英同步**：中断按钮、分诊/澄清日志、汇报行、安装待办、改动存档决策文案等全部走既有客户端词典（`client/locales.ts`）与 host 分面词典（`host/locales/`），zh/en **逐条同形**（en 无 CJK）由既有 locale 门禁守。0.1.9 建立的语言层（语言唯一读取点 = 客户端推送 > settings > `en`、run 起跑快照写 `journal.locale`、判据/解析词表只增不改）**保持不变**——本版只是让新增能力也走这条链，并修掉展示层回归。
- **修复 dev 子任务卡片只剩「开发」两个字**（0.1.9 起的回归）：证据链是「截图里三张卡片的时长 2m18s/3m3s/2m48s 唯一定位到某个 run → **journal 里标题完好**（`taskKey` 三条齐全）→ 问题在展示 → 客户端 `stageLabelOf` 靠 `s.taskKey` 区分任务级阶段，而 **host 的 snapshot 投影从未带 `taskKey`** → 该分支永不成立 → 全部 dev 卡片退化成阶段名」。**同一根因还吃掉 QA 缺陷修复轮**（`taskKey=null`，只显示「开发」）。修法：投影补 `taskKey` + `stageLabelOf` 对 dev 阶段兜底保留 label；**历史 run 零迁移**（标题一直在 journal 里，重启后老 run 也恢复显示）。
- **修复阶段状态词张冠李戴**：`cancelled` 曾复用 backlog 卡片词表 → 被中断的阶段显示成「已关闭 / Closed」（en 更明显：`Closed`）。
- **修复相位组头取色**：`cancelled` 曾与 `failed`/`needs-human` 并列 → 用户主动中断被涂成红色，红头灰身；删掉该判定后组头落到兜底灰，真失败仍为红（不会误变绿）。
- **run 记录能看出「引擎是谁」**：`journal.engine = { provider, model }` 在 run 起跑由 `resolveChildRoute(parent)` 解析后落盘 + 落 `log.engine`，**逐阶段**再记 `stage.provider/model`（子代理路由跟随主线程/团队配置、可被改道，与 run 起始默认不一定相同），完成汇报新增「引擎（模型路由）：provider/model」一行——此前为了回答「是不是模型的锅」，必须解压会话文件才拿到模型名。

**⑤ 收口提交面与运行日志边界（修复）**
- **归属说明**：「运行日志的根离开你的项目」（项目内暂存 → run 终态按白名单归档 `$DSH_HOME/teamflow/<workspace>/logs/<runId>/` → 删项目内副本；命令/套件输出与源码快照一律丢弃；起跑自愈清扫 + 每工作区保留最近 20 次；不制造输出 dump）是 **v0.1.9 已交付**的能力。本版改的是它与**你的仓库**之间的边界，不是这项能力本身。
- **不再改写用户的 `.gitignore`**（用户截图实锤）：用户打开项目的 `.gitignore` 发现 `.pnpm-store/` **顶着「TeamFlow 运行日志（插件自有产物…）」的注释**——表象是注释张冠李戴（`mergeGitignore` 的注释是整批一条），**真问题是越界**：host 把「该忽略什么」写进了**用户的项目文件**。修法：删掉 `ensureCommonNoiseIgnores`，基线提交改用 `tfAddArgs(BASELINE_NOISE_EXCLUDES, 工作区路径)` 的 **magic pathspec 索引层排除**——只影响 host 自己那一次 `git add`，用户 `.gitignore` **一个字节都不碰**（真 git 集成测试逐字节断言）。
- **忽略自检改用 `git check-ignore`**：初版自检用相对路径读 `.gitignore` → 读到的是**宿主进程 cwd 而非目标仓库**，两个方向同时错（目标仓库没忽略的被误拦 → 排除失效、噪音进索引；目标仓库忽略了的被误放 → 点名 + 被忽略 → **`git add` exit 1**，正是 0.1.9 那个「4 天没有任何 run 提交过」的坑原样复活）。改用 git 自己的规则引擎（通配/取反/嵌套 `.gitignore`/全局 excludesfile 全覆盖），**无法判定时一律不下发**（失败的代价不对称）。
- **`.gitignore` 三层分工**：L1 止血清单缩小、L2 PRD 阶段 PM 按项目技术栈规划、L3 QA 收口探针——把「该忽略什么」还给项目与用户。
- **基线提交抗冷启动**：惯例噪音先排除 + `add`/`commit` 超时抬到 120s。

**⑥ 任务身份与断点续跑（修复）**
- **dev 任务身份改为 host 生成的稳定 `dt-N`**：冲突检测把 `files` 有交集的蓝图任务**合并**成一个子代理执行（本意是保证并发不写同一文件，是对的），但合并时把 `title` **拼接**成 `"T0 … + T6 … + T7 …"`，而 `taskKey` 只存 title、`devTaskStatuses` 按 **title 全文精确匹配**归并 → resume 时从蓝图取回的是**未合并**的三个 title → 三个都查不到 → 判「未完成」→ **重复执行已成功的工作**（用户观察：「T0 被触发两次，第一次明面成功了」，backlog 里 `dev-1` 与 `dev-7` 同为 T0 的重复卡肉眼可见）。修法（用户拍板：身份必须结构化，不用产物存在性、更不用字符串规则）：按定义顺序生成稳定 `dt-N`，合并时 `taskIds` 数组累加（`['dt-1','dt-7','dt-8']`）并落盘，`devTaskStatuses` **逐 id 归并**，子卡匹配键同步改用 `dtId`。
- **首版引入的回归当场修正**（用户实测「又点了 resume，0/1/2 开始重试」）：首版写的是「存量 stage 无 `taskIds` → **在判定里**回退 `taskKey`/`label`」——那是给脏数据打补丁，且回退是 per-stage 的 → **id/title 两套命名空间永远对不上**，实测**补跑 8 个**，比修之前的 title 判定（补跑 2 个）**更差 4 倍**。正确做法：新增 `backfillDevTaskIds(stages, defs)`，用**蓝图自己的 title** 去匹配 stage 的 `taskKey`（方向是**结构化 → 文本**，不是反解字符串），合并 title 会补出**多个** id，结果**写回 journal**（幂等）；判定因此**始终只有一个键空间**（`devTaskStatuses` 函数体内不出现 `taskKey`）。实测同一份真实 journal（21 个 dev stage）：补算前 8 个待补跑 → **补算后仅 1 个**。门禁 `test/dev-task-id.test.js`（25 条）+ smoke 11 条（含反向断言：判定函数体内不得出现 `taskKey`、不得按分隔符切分 title）。
- **外部供应商故障不再被当成交付缺陷**：实测某 run 第一轮连续 6 个 dev 阶段 `stopReason=error` → 旧行为快速重试两次就转人工，而**16 分钟后同样的请求成功了**——那是「供应商在一段时间窗内不可用」，与阶段内容无关。三件事一起做：**① 错误分类**（`util.classifyExternalFailure`：429/402/rate limit/quota/insufficient_balance/5xx/upstream/timeout/ECONNRESET/中文「限流/额度/余额/超时/上游不可用」→ `external`；上下文超限/护栏/产出过短 → `content`；未命中按内容类处置，宁严勿松。⚠️ 启发式——宿主只给 `stopReason=error` + 错误文本、无结构化错误码，故命中原文写进日志便于核对）；**② 长退避重试**（`EXTERNAL_BACKOFF_MS = 30s→60s→120s→240s`，总等待 ≈7.5 分钟；**不计入熔断预算**——等待不烧 token；**不受 `RETRY_LIMIT` 约束**——那是「换做法重试」，外部故障是「等窗口过去」，两件事不共用一个计数器；退避可被取消立刻打断）；**③ 退避用尽 → 落可续跑中断态而非 failed**（`journal.externalFailure=true`，汇报明写「疑似外部供应商不可用，**非交付缺陷**；窗口恢复后 `teamflow_resume` 只补跑未完成阶段，已完成阶段与产物全部复用」）。
- **新增第五个早停信号：环境不可用（`env-unavailable`）**：工作区根本起不了命令时（沙箱 ACL provision 失败、命令 100% 失败且错误逐字相同），旧行为要靠 token 预算熔断才停——实测一个阶段因此烧掉 **52.6k 输出 token、3 分 45 秒**，而错误被误报成「输出被截断（max-tokens）」，于是走了自动重试（重试没有意义，错误逐字相同）。现在 host 识别「工具调用失败率 100% + 命令类阶段」→ **连续 2 次提醒 / 3 次中止**（约 15 秒），**不自动重试**、**优先于「完成了」判定**，落可续跑中断态并提示「这不是模型问题，先修工作区再 resume」。实测同一工作区同一故障：**1,510 输出 / 15 秒**。
- **`execOptions` 白名单完整性**（同型第三次）：用户按改动存档问句选了「开启」（`preAction='init'` 正确回传、run 正常启动），但 **git init 静默没执行**（journal 里没有任何 init 日志）——`startPipeline` 的 `execOptions` 显式携带清单漏了**分支策略四字段**（`branchPolicy`/`branchName`/`preAction`/`commitMessage`）。补齐 + 逐字段断言门禁（共 6 项；以后加内部字段漏一个就红）。同批把 `preAction` 入口整形放行四值（`stash`/`commit`/`init`/`keep-nogit`）——此前改动存档决策会被工具入口**静默丢弃**。
- **`state.json` 的 `gitMode` 从来存不住**（白名单漏字段第四次，「答案记住」整条失效）：`loadState` 是**逐字段白名单重建**（不是整体读取），而它**漏了 `gitMode`** → pipeline 明明写了并落了日志，但**任何一次阶段 state 块合并**（走 load→save 往返）都会把它丢掉 → 文件里永远没有 → **每次 run 又从头问一遍「要不要开启改动存档」**，用户当初要的「后续 run 不再问」整条失效。修好（且只接受 `'repo'`/`'none'` 合法值、脏值过滤不固化），并立**字段完整性门禁**：静态解析 `TeamflowState` 接口顶层键，逐个断言 `loadState` 真的搬运了它 → **将来新增持久化字段忘了搬运会立刻红**，不依赖有人记得来加断言。

**⑦ 安装、部署与工程门禁（新增）**
- **安装入口不再写死，改 host 运行时探测**（用户原话：「不只是兼容我的环境，因为我这是个 toc 插件，每个用户环境不一样，路径不要写死」）：契约里原本写死「`dsh plugin --profile web add <spec>` 退出码 0」，但① 源码运行下 **`dsh` 不在 PATH**；② profile 名也不一定叫 `web`；③ 一键安装的用户则确实有 `dsh`——一条写死的命令**不可能同时成立**。新增 `util.detectInstallEnv` / `profileFromModulePath` / `installRecipe` 三个纯函数，事实全部运行时得到；**主源是宿主给的权威锚点 `ctx.baseUrl`**（`ctx.baseUrl` 就是当前 profile 目录，且赋值在挂载插件树之前，Cordis 原型继承使插件构造时即读得到）——`DSH_HOME` **是可选覆盖变量而非安装产物**（实测用户机器上 `DSH_HOME` 为空，且 `.env` 永远设不了它：boot 的 `BOOTSTRAP_PREFIXES` 命中即抛错）；`DSH_HOME` 只作为补 home 的 hint。探测失败（`ok=false`）→ **PRD 必须改为「问用户 profile 在哪」，绝不编路径**。
- **明确「安装由主 agent 执行」**：流水线子代理的权限范围在启动时固定、写不了 profile；主 agent 的 profile 写入被拒后宿主会给出升级通道（`ask` 策略下经用户批准即可，无人应答 fail closed）。完成汇报新增「🧩 安装待办（需主 agent 执行）」——含**本机真实 profile 目录 + 本机命令形态 + 回滚**；探测失败时改为「先问用户 profile 位置」。
- **改动存档两态模型（方案 A：入口定、出口遵）**：两条 run 的产物因「工作区不是 git 仓库」**从未进入任何版本库**，而用户全程只看到「全部完成 ✅」——三个可见性缺口同时存在（入口静默跳过分支决策、「状态核对不可用」只注入子代理提示词、出口把提交失败记成「失败（忽略）」）。对非程序员，一个 run 一个 commit / 分支隔离 / 改动审计就是**唯一的安全网**。做法：① **入口定**：非 git 工作区 → `needs-decision kind=git-init`，**人话问句**（"开启后：本次运行的改动会单独存成一档，随时可以整体撤销…不开启：改动直接写入文件夹，之后无法一键撤销"），答案写进该工作区 `state.json` 的 `gitMode`（`"repo" | "none"`），后续 run 不再问；② **出口遵**：`gitMode="none"` → **根本不尝试提交**；repo → 正常收口 + 汇报新增「📦 本次改动已存档（1 次提交）：不满意可整体撤销」。两层防线（init 是灾难动作）：**L1** 危险路径（驱动器根/家目录本身或祖先/系统目录/深度≤1）→ **不给 init 选项**只给 keep + 建议「把项目放进单独的文件夹」；**L2** 目录过大（>1000 文件或 >100MB 或 1s 采样超时）→ 只 init **不做基线提交**；另有执行期二次校验（`preAction="init"` 时重判，命中 L1 降级为不初始化并继续，run 不打断）。
- **`deploy.mjs` FILES 漏项补齐**：`deploy.mjs FILES` 覆盖**全部** host/client 源码，但漏了 `guard.ts`/`runlogs.ts`/`products.ts`/`state.ts`/`teams.ts` 五个 → 「profile 里那份源码」长期陈旧。补齐 + 立**清单完整性门禁**（真实文件 ⊆ FILES，漏一个即红），不靠人记。
- **新增七套门禁并全部接入发布前检查**：`state`（字段完整性）、`dev-task-id`、`triage-gate`（闸门/护栏/形态契约真值表）、`journal` 序列化完整性（静态解析持久化形态 `JournalRecord`(32 键)/`JournalStage`(19 键) 逐个断言真的被写出——**首跑就抓出四个「只写不落盘」字段**：`branch`/`mergeStatus`/`guardReason`/`guardOutcome`，与 0.1.9 的 `verifyEvidence`、本版的 `triage.artifact` 完全同型）、`instruction-budget`、`changelog`、`client-host-api`。`package.json` 的 `test`/`prepublishOnly` 从 14 套扩到 **21 套**。
- **CI 现代化**：GitHub Actions 全部升到 v5（node24），消掉 Node 20 deprecation 告警。

**⑨ 宿主兼容：dsh 0.1.7-alpha.1（破坏性适配）**
- **session format v4 事件 source 适配**（实测整轮 run 失败，破坏性）：升级到 0.1.7-alpha.1 后，宿主的 `session-format-v3-to-v4` 在事件被 Session 采纳前校验 `source.kind`，**拒绝 v3 退役的 `{kind:'plugin', plugin:'x'}` wrapper**（`message-sources.ts`：`format v4 message requires a producer-owned source kind`），要求带命名空间的 `kind:'plugin:<name>'`。插件所有注入事件用的都是旧 wrapper → 新 run 在事件写入阶段直接抛错失败（probe-v3 的 journal 因此没落盘）。修法：四处 `source` 全部改为 `{kind:'plugin:dsh-plugin-teamflow', ...}`（删 `plugin` 字段、保留 `form`/`summary`）+ 回归断言（全池命中新形态、无退役写法）。注：`runner.ts` 的 `session.append('tool-workflow/agent-start', …)` 不携带 message/source，不在 v4 校验的遍历范围内，无需改。
- **宿主下限随 v4 要求收窄**：`engines.dsh` 由 `>=0.1.5-rc.2 <0.2.0` 改为 **`>=0.1.7-alpha.1 <0.2.0`**——0.1.6-alpha.2 及更早没有 v4 迁移包，其 source kind 校验是**封闭白名单**（`SOURCE_KINDS`，不含 `plugin:*`），两种 source 形态互不兼容。semver 实测：`0.1.7-alpha.1`/`0.1.7-alpha.2`/`0.1.7`/`0.1.8`/`0.1.9` **PASS**，`0.1.6-alpha.2`/`0.1.6`/`0.2.0-rc.1`/`0.2.0` **fail**。
- **客户端跳会话迁移到 `uiWorkspace.openSession`**：症状是工作台流水线详情浮层「🎬 跳转子代理会话」长期**灰着**、全局面板产物跳转静默降级为「当前会话右栏内联打开」。根因在宿主侧：0.1.7-alpha.1 的一批客户端重构删除了会话服务的 `openSubagent` 与 `open`，插件的守卫 `typeof sessions.openSubagent === 'function'` **恒为 false**。排除项（实测）：run journal 里 **18/18** 阶段 `childId` 全部落盘 → 数据面完好，问题纯在客户端 API 面。修法：跳会话唯一入口改为 `uiWorkspace.openSession`（宿主自家 `ui-workflow-run` 面板同款调用；target 为会话 id 或持久子代理地址），`inject` 摘掉已无引用的 `sessions` 死依赖，并删掉 `sessions.list.getSnapshot().current` 这个恒 `undefined` 的判据（`SessionListState` 已无 `current`）。收益：新 API 是**真跳转**（替换 `mainView` 并让主区回到 Conversation），旧 `openSubagent` 只跳不切视图。
- **新增 `test/client-host-api.test.js`**（宿主删 API 不是插件 bug，但当时**全套测试无一变红**——缺的是契约面门禁）：① 客户端源码不得引用已移除成员（`openSubagent` / `sessions.open` / `SessionListState.current`）；② 出现的每个 `sessions.<成员>` / `uiWorkspace.<成员>` 必须在**冻结白名单**内（依据 0.1.7-alpha.1 的 `sessions.ts` 成员表 + `navigation.ts` + `control-types.ts`）；③ 用到 `uiWorkspace` 就必须 `inject` 并桥接到 props，反之无 `sessions.*` 引用时不得保留 `'sessions'` 死依赖；扫描剥注释后再判（迁移说明必然要写被移除的 API 名）。
- **兼容性核查结论（诚实边界）**：0.1.7-alpha.1 下**仅 v4 source 一项为破坏性变更**——typert 严格描述符仍要求 `create()`、`subagents.start(name, request)` / `SubagentRun.{id,localAgent,result,dispose()}` 签名未变、`tokenUsage` 投影四桶（`uncachedInputTokens`/`outputTokens`/`cacheReadTokens`/`cacheWriteTokens`，`stateVersion:2`）与 `sessionStats.steps` 调用数来源与 `metering.ts` 读取完全一致、`agent.inject/followup/steer`、`settings`/`locale` 只读端口、`ctx.remote.$mount`、`ctx.locale.*` 全部兼容。**但当时的核查只覆盖 session-format v4、漏了客户端服务 API 面**（`sessions.openSubagent`/`open` 被删这件事是后来才发现的），该结论应视为不完整——这也是新增上面那道 API 面门禁的原因。

### 已知限制 / 未完成项

- **跨父会话跳转子代理仍禁用**：DSH 的子代理目录按父会话加载，`selectSubagent` 不支持跨父导航。插件已把 `journal.ownerSession`（发起会话）下发到阶段详情，当发起会话 ≠ 当前会话时跳转按钮**禁用 + title/文案提示**；等官方支持跨父导航后再解锁（数据已备好）。
- **熔断/阶段预算仍是硬编码常量**：`FRESH_TOKEN_BUDGET` 尚未做成 service Config（阈值不可调），且只作用于**单阶段单次尝试**；本版只做了「随 provider 缓存能力自适应 ×3」，没有改判定语义。
- **需求澄清闸门只做了 Phase 1**：启动前拦一轮 + PRD 假设可见化 + shadow 埋点已落地；**Phase 2 的「PRD 确认单」未做**——即 PRD 产出后暂停、让你在计划上直接改（`resume(runId, { redoFrom: 'prd', supplement })`）并复用宿主原生审阅卡。当前闸门只负责「唤起第一轮对齐」，不负责「追问到满意」（残余疑点转成 PRD 显式假设）。另有两处待观察：分诊对纯 `lite` 需求是否会把档位判重（升档率与 token 放大从 `journal.triage.upgradedFrom` 攒）；显式 `lite`/`mode` 路径现在都会多一次分诊调用（成本 <1%，但要实测确认）。
- **交付形态契约目前是 policy 级**：只要求 PRD 把形态契约写成可测 AC，缺失**不硬拦**（靠 QA/验收按 AC 走，可升级为 host 硬门禁）；`plugin-client` 形态的契约目前只有 2 条（bundle 声明 + `files`），待真实案例补充。
- **宿主 Windows 沙箱 ACL 问题已上报上游**：在用户自建目录（无继承沙箱 ACE）下，宿主 provision 工作区 ACE 失败 → 该目录下所有 shell 命令 100% 失败，且只表现为会话深处的一条工具错误、没有可行动信息（实测代价：一个阶段烧了 52.6k 输出 token 才被上报）。插件侧无法修复，只能**早停**并提示「这不是模型问题，请先修复工作区再 resume」（实测同一工作区同一故障：52,588 输出 / 3 分 45 秒 → **1,510 输出 / 15 秒**）。最小复现与实测根因见 `docs/reports/`。
- **`$DSH_HOME/teamflow/` 仍无遗忘机制**：`logs/` 已有保留策略（每工作区最近 20 次 + 起跑自愈清扫），但 `runs/` 无 TTL 无归档（单个最大 137 KB，某工作区累计 2.90 MB）、只写过 `teams.json` 的空壳目录不会被清理（实测 11 个目录里 6 个是空壳，1 个旧格式 key 残留）；`backlog/*.json` 各配一个等大 `.bak`。

### 安装

```bash
dsh plugin --profile web add dsh-plugin-teamflow
```

安装后需重启 `dsh --profile web` 才生效。**升级前请先把 dsh 升到 `0.1.7-alpha.1`（或同系列更高版本），否则流水线会在事件写入阶段直接失败。**

## English

### ⚠️ Upgrade notes (read first)

- **⚠️ Breaking: the host floor rises to dsh `>=0.1.7-alpha.1 <0.2.0` (upgrade dsh before the plugin)** — dsh 0.1.7-alpha.1's session format v4 validates `source.kind` **before** an event is admitted to the Session and rejects the retired v3 `{ kind: 'plugin', plugin: 'x' }` wrapper, while 0.1.6-alpha.2 and earlier have **no** `session-format-v3-to-v4` package and their source kinds are a closed whitelist that does **not** include `plugin:*`. The two shapes are mutually incompatible, and the consequence is not "one stage fails" but **the whole run throwing while writing events** (probe-v3's journal was never written; only `teams.json` landed). All four injected events (team-context inject ×2, completion report, guard reminders) now use `{ kind: 'plugin:dsh-plugin-teamflow', ... }`; third parties that parse plugin events must adapt for v4.
- **Behaviour tightened (not optional): tiers are no longer model-selected, and the clarification gate is live** — omitting `lite`/`mode` hands the decision to auto-triage (which **upgrades** when it judges ≥medium while the caller picked a lighter tier); everything except `patch` goes through triage, so your first start **may ask one round of must-know questions** — by design, not a failure. Once a clarification answer has been supplied the gate will not block again; leftover uncertainties become explicit assumptions in the PRD.
- **New early stop + tighter judging + install changes** — when the workspace cannot run commands the stage stops and reports in about 15 seconds (new `env-unavailable` signal; no more misreporting as "output truncated", no automatic retry), and `teamflow_resume` reuses every completed stage and artifact afterwards. Acceptance verdicts are only read from **literal verdict lines**, defects only from tables whose header **declares a severity column**, and dev task identity is `dt-N` (historical journals stay compatible; resumed runs judge by the new rules). The install entry point is now **detected at runtime** (correct instructions for source runs and non-`web` profile names) and installation is performed by the **main agent**. `logs/teamflow/` never enters a commit, and noise exclusion **no longer rewrites your `.gitignore`**.

### Changes

**① Interruptible pipelines (new)**
- **Three UI entry points can stop a running pipeline**: the in-session workbench top bar ("⏹ Stop #xxxxxx"), a run row in the global panel, and the run detail header (right-sidebar tab and panel overlay) — all sharing one **two-step inline confirmation** button (first click arms "Confirm stop?", a second click within 3 seconds executes; the client has no host confirm/dialog dependency, so nothing new is pulled in; panel rows remain clickable for detail and the button stops propagation).
- **Abort goes through the host's official `SubagentRun.dispose()`** (host contract: "cancel remaining work, reach child quiescence"), behind a new host-side `status === 'running'` gate: previously `cancelRun` marked any run "present in memory" as `cancelled` and returned success — **polluting the journal** for finished runs, and for interrupted runs restored after a restart it was "report success while the status never changes". Failed stops are now visible in the UI ("no longer running"), and gaps between stages (`inFlight` empty) remain cancellable.
- **Concurrent dev tasks all stop at once**: `inFlight` became a runId → Map<stage, run> multi-path tracker and the pool gained a `shouldStop` check, so it **no longer picks up a new task** after a cancel (which used to look like "I stopped it and it started another one").
- **Closing and trail**: terminal-state normalisation moved to the first statement of `finally` (a cancel that returned normally used to leave the run stuck on "running"); the dev closing step (cancel check + test-request gate) moved to the shared `resume`/`else` junction so the two paths no longer carry separate copies; the cancel source is persisted, a cancelled run **gets no resume guidance for the model** and **never commits**; cancelling only sets a flag, it does not rewrite the state machine.
- **Display fixes**: an interrupted stage no longer renders as "Closed" (`client/locales.ts`'s `status.*` is the backlog card vocabulary where `closed`/`cancelled`/`verified` all translate to 已关闭, and the stage surface reused it directly; a new stage-level term `stageStatus.cancelled` = "Stopped" was added). Phase group header colouring had the same problem — `cancelled` sat alongside `failed`/`needs-human`, so a user-initiated stop painted the header in the **error colour (red)** while the stage card below it was grey (red head, grey body).
- New `test/cancel.test.js` (30 assertions, behaviour-level): gate truth table / flag + dispose + persistence / cancellable between stages / a throwing dispose does not swallow the cancel / descriptor ↔ service ↔ three UI entry points share one source.

**② Clarification gate and triage tightening (new + fixes)**
- **Exploratory requirements no longer start a run**: two community reports on the same gap (deepseek-ai/deepseek-harness#6405) — ① a statement-shaped exploration such as "我想开发一个 dsh 插件" does not match the question-shaped regex, so the full pipeline ran and the user's own words were "我都不知道自己想要啥，它做完了"; ② "intent clarification needs the agent to talk to a human — how does a subagent do that?" The host's `DELEGATED_CALLER` and `exit_plan_mode` both **reject a live child**, so clarification can only be initiated by the host on the main thread. Approach: reuse **the triage call that was going to happen anyway** as a preflight; a must-know hit returns `needs-clarification` and **creates no run**; the main thread asks, then re-calls with the answers in the new `requirementSupplement` parameter (the PRD receives `[CLARIFIED]` as authoritative input and is forbidden to assume further).
- **The bar is judged by the host, not by model self-discipline**: `qualifyBlockers` requires every item to supply "≥2 mutually exclusive readings + which AC/scope changes + what a wrong guess costs"; missing any of the three drops it with a warning (max 3) — otherwise "a model can almost always invent questions for any requirement" and the gate degrades into interrupting every time.
- **Tiers are no longer model-selected**: the root cause was **our own parameter description recommending it** — the `lite` help text said "(recommended)" and models quoted it verbatim in reasoning (`testb`: "lite: true (最小可用版, small change) — recommended for small changes"). Measured: across 22 sessions / **33 `teamflow_start` calls**, 6 carried `lite` and 8 carried `mode` (**0** of them previewed with `teamflow_triage` first) → **14/33 (42%) of starts skipped triage entirely**, silently disabling both the clarification gate and the "architecture signal → at least medium" guardrail. Two fixes: the "(recommended)" hint was removed, and everything except `patch` goes through triage — a lighter tier is **upgraded and logged as `log.modeUpgraded`** when triage judges ≥medium. Same batch: triage judging `lite` while the caller explicitly passed `needDesign=true` (`lite` is defined as "no UI design", a direct conflict) — the host now raises to ≥medium when no tier was given and `needDesign=true`.
- **Gate convergence and authority**: in one measured workspace the model called `teamflow_start` **6 times**, every call returning `needs-clarification` and **creating no run at all**, with the blocker count going 3 → 2 → 2 around the same question (triage saw only the raw requirement; the clarification answers never reached it). Fixes: triage input became `requirement + [CLARIFIED] requirementSupplement`; **the gate only blocks when no answer has been supplied yet** — once answered it proceeds, treating leftover blockers as assumptions and logging `log.clarifyProceedWithAssumptions`. Separately, the **authoritative decision moved from the in-tool preflight into the pipeline** (measured: the preflight threw, was swallowed and silently fell back to the regex — `teamflow_start` "finished" in 0.4 s while real model triage measures 1.5–1.9 s; the only difference was a missing `exec.signal`), with a new `abortForClarification` fallback.
- **Triage fixes**: timeout 90s → 240s (screenshot evidence: an in-flight triage was disposed and the fallback reason was invisible), a short-term cache to remove duplicate triage on the decision path (recast as a pending-decision state machine so the TTL no longer carries correctness), and a **self-consistency gate** — a requirement that already says "装进我的 dsh web profile 里真实可用" and that triage itself judged `installable: true` still produced a "does it really have to install into the profile?" blocker, inventing a clarification round (which changed the input, which necessarily missed the cache, which triaged the same requirement twice); a `settles` field that contradicts an already-judged value is now dropped and counted in `blockersDropped`.
- **Interaction and injection loop**: gates and decisions go through click-through `ask_user_question` (mutually exclusive readings map naturally onto options); `start`'s output schema now declares `kind`/`message` (the git-init decision and paused/no-team return paths were being rejected by the host's `additionalProperties: false` — measured as two failed starts and zero runs); the team-selection injection gained three sections ("clarify first / once clarified you must come back and start — raw words in `requirement`, conclusions in `requirementSupplement` / how to handle `needs-clarification`") after measuring a session where the injection was delivered but the model called no tools at all and the product line had zero runs, so the gate never got a chance to run. The same batch fixed two self-inflicted bugs: internal fields such as `__triage` were dropped by the `execOptions` whitelist, and the PRD's "assumptions" regex missed **numbered headings** (a form like `## 3. 假设与未知` extracted as empty).

**③ Delivery-form contracts and acceptance judging (new + fixes)**
- **Delivery-form contracts turn the acceptance criteria implied by a form into mandatory, testable PRD ACs**: the incident was a plugin that **looked complete** (host/src/client/lib all present, functional ACs green, QA found 3 defects and bounced them back for fixing, acceptance ✅ passed) yet **could not be installed into the profile** — missing `cordis.patch.yml`, missing the `dsh.bundle.patch` declaration, a `files` whitelist that omitted it, and `workspace:` protocol dependencies. The root cause was not the model: **no AC had ever covered "loadable/installable by the host"**. Approach: triage gained one orthogonal dimension `artifact` + `installable` (a single-choice dimension covers every deliverable type; new forms only add an enum value), and the host-side `ARTIFACT_CONTRACTS` **data table** (a new deliverable type is a new data row, not new judging logic) is expanded into `state.__runCtx` so `prdPrompt` **must** write them as testable ACs.
- **Non-dsh hosts no longer get dsh contracts**: a user asked "I develop openclaw plugins, or hermes plugins — how do you tell the scenarios apart? dsh's contracts don't necessarily hold elsewhere" — and was right: `plugin-host`/`plugin-client`/`plugin-full` are **dsh-private vocabulary** (profile-layer entry declaration / `dsh.bundle.patch` / `dsh.client` block / `files` whitelist), so applying dsh contracts to hermes / pi / OpenClaw plugins produces backwards rework. Fix: a new `ArtifactHost = 'dsh' | 'other' | 'unknown'` orthogonal to `artifact`; `plugin-*` with `host !== 'dsh'` gets **zero** repository contracts and instead requires a **"host contract research" section** in the PRD behind a **hard gate** (missing = PRD stage fails and retries; line-based parsing, and an **empty heading does not count** — otherwise models learn to write only the heading). A deterministic guardrail promotes `unknown` to `dsh` when the requirement contains dsh identifiers (`dsh`/`@deepseek-ai/dsh-*`/`deepseek-harness`/`cordis`), without overriding an explicit `other`.
- **Two measured criteria added**: ① a UI mount point's `register.name` **must be the slot name** — a delivered Markdown table aligner used its own identifier `md-table-align.dock` where `ctx.slots.inject('conversation.input.dock', …)` was expected, so it **silently never mounted and the toolbar never appeared**, while its unit tests were **31/31 green** and acceptance ✅ passed; ② the contract sample source became "**dsh plugins installed on this machine**" — the old implementation pointed at a **repository-relative path** to "a similar plugin in this repo", but `npm pack` shows the published package is **10 files with no source**, so that path does not exist in an npm user's isolated workspace (probe-v2 happened to run inside this repo's `plugins/`, meaning that round's "had a reference" was in fact **the test being fed the answer**).
- **Three install/load-safety contracts plus QA shape probes** (driven by an install incident): after installing the plugin into the profile, **the host would not boot (P0)** — `lib/index.js` was a **stale build artifact** (the fixed `ctx.inject(['settings'])` never made it into the bundle) and the host was only rescued by opening another agent to uninstall the plugin. The three contracts: **① build artifacts match the source** (rebuild before installing; the artifact contains a current-source marker or its mtime is newer than every src file); **② load safety** (a module must not throw at top level; criterion: `node -e "require('<artifact entry>')"` exits 0); **③ installs must carry a rollback** (write down the uninstall command beforehand; on a failed post-install check, **roll back first and then report** — never leave the host unable to boot). `stateSliceFor` ships the contract list to qa/acceptance and `qaPrompt` gained **section 0b** turning each contract item into a mandatory probe (command + exit code into `QA-REPORT.md`), with anything the environment cannot do (host restart) required to appear in the manual-test list rather than being silently skipped.
- **Fixed "the delivery-form contract chain never worked"** (the fifth whitelist-field omission): `triageRecordOf` copied only 9 fields and dropped `artifact` and `installable`, so `normalizeArtifact(undefined)` = `'other'` → contracts always `[]` → **`[delivery-form contract · mandatory AC]` was never injected into any PRD**, and `qaPrompt`'s 0b probes likewise. **Measured, not inferred**: all **64/64** runs carried no `artifact` field in `triage`, and `log.artifactContract` had never once fired. The same sweep caught a self-inflicted bug: the interface declares `upgradedFrom` but all three write sites set the internal marker `__upgradedFrom`, so the copy read `.upgradedFrom` (which nobody writes) and `log.modeUpgraded` silently disappeared. A **wiring gate** was added (following `state.test.js`: statically parse `TriageVerdict`'s top-level keys and assert each is really carried, with the exemption table itself asserted too).
- **Tighter judging**:
  - **Verdicts are read only from literal template lines, and when there are several the last one wins** — in a real artifact line 11 was the section heading `## 1. 验收结论摘要` (containing those words but not being a verdict line) and the old `.find()` took the **first** line containing "验收结论" → the heading → all four buckets missed → **a passing deliverable was judged needs-human**. Now only lines starting with `验收结论：` / `整体结论：` / `Acceptance verdict:` / `Overall verdict:` count (allowing `## ` and list markers), and bolded forms like `**验收结论：**` are deliberately **not** accepted (better strict than guessing).
  - **"📝 requirement not applicable" is line-anchored** — a real report argued in prose about "why it is not judged 📝 requirement not applicable", and the old **full-text match** hit the quoted phrase → `reject` (with `journal.humanIntervention` still false, contradicting the error text). Now, after stripping markdown/list/table prefixes, the line must **begin** with 📝 + the phrase; an in-sentence 📝 falls to needs-human. The `reject` branch's missing `humanIntervention = true` was added too.
  - **Defect parsing only recognises tables whose header explicitly declares a severity column**: the old implementation asked "is cell 2 a P-level?", so QA's "re-verification comparison" table was registered as a brand-new blocking defect every round → **guaranteed to exceed the rework limit and skip acceptance** (a self-inflicted stop line unrelated to delivery quality).
  - **A too-short doc-stage reply no longer means "not delivered"**: in a real chain the PRD subagent spent 14 of 17 calls on idle exploration and finally returned only a state block (284 characters) → below the 400 floor → judged non-delivery, while `PRD.md` had in fact landed at 4,894 bytes and `present` had been called; then the stage's fresh **259k > 200k** tripped the budget gate, killing the automatic retry it should have had → `failed` + needs-human. Now an unqualified reply **reads back the task-folder artifact** (per-stage candidate file names, longest one wins) and judges delivery when the file exists and meets the stage's length floor, logging a warning; the fallback **does not exempt an empty reply** (the pipeline needs the reply to merge state blocks).
  - **The breaker budget adapts to the provider's caching ability**: `FRESH_TOKEN_BUDGET = 200k` was justified by "cacheRead is a cheap replay" (measured 1.2–2.4k per call on a cached provider), but **a provider with no prompt cache re-pays the system prompt and tool definitions on every tool round (measured ~15.5k per call)** → 200k degenerates into "about 13 calls per stage". New `metering.effectiveFreshBudget`: hit rate <50% with ≥5 calls concludes "this provider has no cache" → budget ×3, with a separate breaker log wording `diag.breakerUncached`; cached providers are untouched.

**④ Bilingual pipeline and display regressions (improvements + fixes)**
- **Every new capability ships in both languages**: cancel buttons, triage/clarification logs, report lines, install to-dos and change-archiving copy all go through the existing client dictionary (`client/locales.ts`) and host faceted dictionaries (`host/locales/`), **key-for-key identical** (and no CJK in `en`) guarded by the existing locale gate. The language layer built in 0.1.9 (single read point = client push > settings > `en`, per-run snapshot in `journal.locale`, append-only parse vocabularies) is **unchanged** — this release routes new capabilities through it and fixes display regressions.
- **Fixed dev subtask cards showing only "开发"** (a regression since 0.1.9): the evidence chain was "three cards' durations (2m18s/3m3s/2m48s) uniquely identify one run → **the journal titles are intact** (`taskKey` present on all three) → so it is a display problem → the client's `stageLabelOf` distinguishes task-level stages by `s.taskKey`, and **the host snapshot projection never carried `taskKey`** → that branch never fires → every dev card degrades to the phase name". **The same root cause ate the QA defect-fix rounds** (`taskKey=null`, rendering as "开发"). Fix: the projection carries `taskKey` and `stageLabelOf` falls back to the label for dev stages; **historical runs need no migration** (the titles were always in the journal, so old runs recover after a restart).
- **Fixed a stage status term mix-up**: `cancelled` reused the backlog card vocabulary, rendering an interrupted stage as "Closed" (more obvious in English).
- **Fixed phase group header colouring**: `cancelled` sat alongside `failed`/`needs-human`, so a user-initiated stop was painted red (red head, grey body); removing that judgement drops the header to the fallback grey while real failures stay red (and never turn green by accident).
- **Run records now show which engine ran them**: `journal.engine = { provider, model }` is resolved at run start from `resolveChildRoute(parent)` and persisted (plus `log.engine`), with a **per-stage** `stage.provider/model` (a child route follows the main thread/team config and can be redirected, so it may differ from the run default); the completion report gained an "engine (model route): provider/model" line — you used to have to unpack session files just to answer "was it the model's fault?".

**⑤ Closing-commit surface and the run-log boundary (fixes)**
- **Attribution note**: "the run-log root moves out of your project" (stage inside the project → archive to `$DSH_HOME/teamflow/<workspace>/logs/<runId>/` by whitelist at the terminal state → delete the in-project copy; command/suite output and source snapshots always dropped; start-up self-healing sweep plus the latest 20 runs per workspace; no output dumps manufactured) shipped in **v0.1.9**. This release changes the **boundary** between that and **your repository**, not that capability.
- **Your `.gitignore` is no longer rewritten** (screenshot evidence): a user opened their project's `.gitignore` and found `.pnpm-store/` sitting under a "TeamFlow run logs (plugin-owned artifacts…)" comment — the surface symptom was a mis-attributed comment (`mergeGitignore` writes one comment for the whole batch), but **the real problem was overreach**: the host was writing "what should be ignored" into **the user's project file**. Fix: `ensureCommonNoiseIgnores` was deleted and baseline commits now use index-level **magic pathspec** exclusions (`tfAddArgs(BASELINE_NOISE_EXCLUDES, workspace)`) — affecting only the host's own `git add`, leaving the user's `.gitignore` **byte-for-byte untouched** (asserted by a real-git integration test).
- **Ignore self-check now uses `git check-ignore`**: the first version read `.gitignore` by relative path, which resolves against the **host process cwd rather than the target repository** — wrong in both directions (a path the target repo does not ignore is falsely blocked → exclusion fails and noise enters the index; a path it does ignore is falsely allowed → "named + already ignored" makes **`git add` exit 1**, resurrecting exactly the 0.1.9 pitfall where no run committed for four days). It now uses git's own rule engine (wildcards, negations, nested `.gitignore`, global excludesfile), and when it cannot decide, **nothing is excluded** (the costs are asymmetric).
- **Three-layer `.gitignore` split**: L1 shrinks the bleeding-stop list, L2 lets the PM plan per tech stack during PRD, L3 uses a QA closing probe — "what to ignore" goes back to the project and its user.
- **Cold-start hardening for baseline commits**: conventional noise excluded first, with `add`/`commit` timeouts raised to 120s.

**⑥ Task identity and resume (fixes)**
- **Dev task identity is now the host-generated stable `dt-N`**: conflict detection **merges** blueprint tasks whose `files` overlap into one subagent (correct in intent — concurrent writers must not touch the same file), but concatenated their `title` into `"T0 … + T6 … + T7 …"`, while `taskKey` stored only the title and `devTaskStatuses` merged by **exact full-text title match** → on resume the blueprint returns the **unmerged** titles → none of the three is found → judged "not done" → **already-successful work runs again** (the user observed "T0 was triggered twice, the first one visibly succeeded", with duplicate backlog cards where `dev-1` and `dev-7` were both T0). Fix (decided by the maintainer: identity must be structural — not artifact existence, and certainly not string rules): stable `dt-N` ids in definition order, merging accumulates a `taskIds` array (`['dt-1','dt-7','dt-8']`) that is persisted, `devTaskStatuses` merges **per id**, and subtask cards match on `dtId`.
- **The first version's regression was corrected on the spot** (maintainer: "clicked resume again, 0/1/2 started retrying"): it fell back to `taskKey`/`label` **inside the judgement** for stages without `taskIds` — patching dirty data, and per-stage, so **id and title became two namespaces that can never agree**: measured at **8 needless re-runs**, four times worse than the old title-based judgement (2). Correct approach: `backfillDevTaskIds(stages, defs)` matches stages by the **blueprint's own titles** (structured → text, never string deconstruction); a merged title yields **several** ids; the result is **written back to the journal** (idempotent). Judgement therefore uses **exactly one key space** (`devTaskStatuses` contains no `taskKey` at all). On the same real journal (21 dev stages): 8 pending re-runs before backfill → **only 1 after**. Gates: `test/dev-task-id.test.js` (25 assertions) + 11 smoke assertions, including reverse assertions that the judgement body never mentions `taskKey` and never splits titles.
- **External provider failures are no longer treated as delivery defects**: in one measured run six consecutive dev stages finished with `stopReason=error` → the old behaviour retried twice quickly and handed off to a human, yet **the same request succeeded 16 minutes later** — a provider being unavailable in a time window, unrelated to the stage content. Three things together: **① classification** (`util.classifyExternalFailure`: 429/402/rate limit/quota/insufficient_balance/5xx/upstream/timeout/ECONNRESET and the Chinese equivalents → `external`; context overrun/guardrail/too-short output → `content`; no match is treated as content, strict over lax — ⚠️ heuristic, since the host only gives `stopReason=error` plus error text and no structured code, so the matched text is logged for verification); **② long backoff** (`EXTERNAL_BACKOFF_MS = 30s→60s→120s→240s`, ≈7.5 minutes total; **not counted against the breaker budget** because waiting burns no tokens; **not bound by `RETRY_LIMIT`**, which governs "retry differently" while an outage is "wait out the window" — two different counters; interruptible by a cancel); **③ exhaustion lands in a resumable interrupted state instead of `failed`** (`journal.externalFailure=true`, reporting explicitly "suspected external provider outage, **not a delivery defect**; after the window recovers `teamflow_resume` re-runs only the unfinished stages and reuses every completed stage and artifact").
- **New fifth early-stop signal: environment unavailable (`env-unavailable`)**: when the workspace cannot run commands at all (sandbox ACL provisioning failed, every command failing with a byte-identical error), the old behaviour only stopped at the token budget — one measured stage burned **52.6k output tokens over 3m45s**, and the error was misreported as "output truncated (max-tokens)", so it went through automatic retries (pointless: the error was byte-identical every time). The host now recognises "100% tool-call failure rate in a command-type stage" → **2 consecutive reminders / 3 aborts** (about 15 seconds), **no automatic retry**, **taking precedence over "done"**, landing in a resumable interrupted state that says "this is not the model's fault — fix the workspace and resume". Measured on the same workspace and fault: **1,510 output / 15 seconds**.
- **`execOptions` whitelist completeness** (the third instance of the class): a user answered the change-archiving question with "enable" (`preAction='init'` came back correctly and the run started), but **`git init` silently never ran** (no init log at all in the journal) — `startPipeline`'s explicit `execOptions` list was missing the **four branch-policy fields** (`branchPolicy`/`branchName`/`preAction`/`commitMessage`). Fixed with a per-field assertion gate (6 items; a future internal field left out turns red). Same batch: the `preAction` entry point now admits all four values (`stash`/`commit`/`init`/`keep-nogit`), since the change-archiving decision used to be **silently dropped** at the tool boundary.
- **`gitMode` in `state.json` could never persist** (the fourth whitelist omission; "remember the answer" was entirely broken): `loadState` rebuilds state **field by field from a whitelist** (not a bulk read) and **dropped `gitMode`** → the pipeline wrote it and logged it, but **any state-block merge** (a load→save round trip) lost it → the file never contained it → **every run asked "enable change archiving?" again from scratch**, defeating exactly what the user had asked for. Fixed (accepting only `'repo'`/`'none'`, filtering dirty values instead of fixing them), plus a new **field-completeness gate** that statically parses the `TeamflowState` interface's top-level keys and asserts each is really carried — **a future persisted field left out turns red immediately**, without relying on anyone remembering to add an assertion.

**⑦ Install, deploy and engineering gates (new)**
- **The install entry point is no longer hard-coded; it is detected at runtime** (maintainer: "don't just accommodate my environment — this is a toc plugin, every user's environment is different; don't hard-code paths"): the contract used to hard-code "`dsh plugin --profile web add <spec>` exits 0", but ① under a source run **`dsh` is not on PATH**; ② the profile need not be called `web`; ③ a one-click install does have `dsh` — one hard-coded command **cannot hold for all three**. Three new pure functions (`util.detectInstallEnv` / `profileFromModulePath` / `installRecipe`) obtain every fact at runtime; the **primary source is the host's authoritative anchor `ctx.baseUrl`** (`ctx.baseUrl` is the current profile directory, assigned before the plugin tree is mounted, and Cordis prototype inheritance makes it readable when the plugin is constructed) — `DSH_HOME` is an **optional override variable, not an installation artifact** (measured empty on a user machine, and it can never be set from `.env`: boot's `BOOTSTRAP_PREFIXES` throws on match) and only serves as a home hint. A failed detection (`ok=false`) means **the PRD must ask the user where the profile is and never invent a path**.
- **Installation is explicitly the main agent's job**: a pipeline subagent's permission scope is fixed at start and it cannot write the profile; when the main agent's profile write is denied the host offers an escalation path (with an `ask` policy, user approval suffices; with no one to answer it fails closed). The completion report gained an "🧩 install to-do (for the main agent)" line carrying the **real local profile directory + the local command shape + a rollback**; when detection fails it becomes "ask the user where the profile is" instead.
- **Two-state change archiving (option A: decided at the entrance, obeyed at the exit)**: two runs' artifacts **never entered any version control** because "the workspace is not a git repository", while the user only ever saw "all done ✅" — three visibility gaps at once (the entrance silently skipped the branch decision; "state check unavailable" was only injected into subagent prompts; the exit logged a failed commit as "failed (ignored)"). For a non-programmer, one-commit-per-run / branch isolation / change audit **is the only safety net**. Approach: ① **entrance**: a non-git workspace gets a `needs-decision kind=git-init` in **plain language** ("enabled: this run's changes are archived separately and can be reverted wholesale at any time… disabled: changes are written straight into the folder and cannot be undone with one click"), and the answer goes into that workspace's `state.json` as `gitMode` (`"repo" | "none"`) so later runs never ask again; ② **exit**: `gitMode="none"` means **no commit is attempted at all**, while `repo` commits normally and reports "📦 this run's changes are archived (1 commit): revert wholesale if you don't like them". Two guards, because init is a destructive action: **L1** dangerous paths (drive root, the home directory itself or an ancestor, system directories, depth ≤1) → **no init option at all**, only keep plus advice to "put the project in its own folder"; **L2** oversized directories (>1000 files, >100MB, or a 1s sampling timeout) → init **without** a baseline commit; plus execution-time re-validation (`preAction="init"` is re-judged, an L1 hit degrades to no-init and the run continues).
- **`deploy.mjs` FILES gaps filled**: the manifest covers **all** host/client source, but omitted `guard.ts`/`runlogs.ts`/`products.ts`/`state.ts`/`teams.ts`, so "the copy of the source in the profile" had gone stale. Filled, plus a **manifest-completeness gate** (real files ⊆ FILES; one missing turns red) so it no longer depends on memory.
- **Seven new gate suites, all wired into pre-publish checks**: `state` (field completeness), `dev-task-id`, `triage-gate` (gate/guardrail/form-contract truth tables), `journal` serialization completeness (statically parses the persisted shapes `JournalRecord` (32 keys) and `JournalStage` (19 keys) and asserts each is really written — **its first run caught four write-only fields**: `branch`/`mergeStatus`/`guardReason`/`guardOutcome`, exactly the same class as 0.1.9's `verifyEvidence` and this release's `triage.artifact`), `instruction-budget`, `changelog` and `client-host-api`. `test`/`prepublishOnly` grew from 14 suites to **21**.
- **CI modernised**: all GitHub Actions moved to v5 (node24), clearing the Node 20 deprecation warnings.

**⑧ Workbench, docs and release process (improvements)**
- **AGENTS.md slimmed from 64,134 B to 19,766 B (−69%)**: §5 went from "argument + evidence + gate list" to one-line invariants plus pointers, and the reasoning/evidence/post-mortems moved into a new searchable layer `docs/anchors/` (one file per topic plus an index); the file now carries only "current state" while history lives in `docs/devlog.md`.
- **New "instruction budget" gate** (seven assertions): whole file ≤22 KiB, §5 ≤6 KiB, §5 lines ≤400 chars, no dates/runIds/"实锤" anywhere, every anchors pointer must resolve, no orphan documents in `docs/anchors/`, and every test file in the §2 index must exist — **size is no longer a matter of memory**.
- **New CHANGELOG gate** (two assertions): ① every published version section must have a matching `docs/releases/<v>.md` (detailed reasoning belongs in the release notes; the CHANGELOG keeps only what users can perceive); ② the count of dates/runIds/probe directory names/source coordinates outside version headings may only **decrease**.
- **README trimmed and screenshots split by language**: core features **17 → 8** (zh 3,924 → 968 characters; the old section mixed "what users need" with "how it is implemented" and repeated itself); version anchoring 1,720 → 581 characters; directory structure 1,225 → 845 characters; architecture section 1,079 → 718 characters. All **12 screenshots (zh 6 + en 6) are now per-language** — `README.en.md` used to reference the same files as the Chinese README, so the English docs showed a Chinese UI; `en/*` are now **photographed in the English UI**, with the rule recorded in `CONTRIBUTING.md` (never share one screenshot between zh/en, ≤400 KB per image). Both languages gained a "global panel" section, and dev commands went back to `pnpm` (the repository lockfile is `pnpm-lock.yaml`; mixing in npm generates a `package-lock.json` on contributors' machines).
- **Release process formalised**: `main` carries only "what has been published to npm", day-to-day development and documentation live on the current `release-vX.Y.Z`, and **contributors open PRs against the latest release branch** (release → PR → squash into main → tag → GitHub Release → cut the next branch). Two SOP criteria: **publish success is judged by the write path** (the registry read path — `npm view`, packument, version endpoints — can lag by minutes; a repeat publish's 403 `cannot publish over the previously published versions` is the authoritative, idempotent receipt); and **check your local VPN/TUN before blaming `git push`** rather than attributing it to "it worked after switching to HTTP/1.1" (measured: the same command fails the same way before the link recovers — spurious correlation).
- **New upstream report** `docs/reports/2026-09-23-dsh-windows-sandbox-acl-provision-failure.md`: Windows sandbox provisioning failure on user-created directories, with a minimal reproduction, the measured root cause (three security edits share one `SetNamedSecurityInfoW` call, and the third — labelling the directory Low integrity — is a **SACL** write requiring `SeSecurityPrivilege`, which a normal user token does not have), the blast radius and the raw evidence.
- **Release-material and dev-line housekeeping**: the line formally moved to `0.2.0` (branch `release-v0.2.0`, with the version, source assertions and doc references aligned without missing a spot); `CHANGELOG.md` opened a `[0.2.0] - unreleased` section with an "⬆️ upgrade notes (TL;DR)"; two `docs/TODO.md` entries (the clarification gate's design rationale and the continuable pilot's preconditions) were rewritten as "positioning argument + measured cost + retrospective evidence"; and screenshot sizes were reduced (one image 413 KB → 167 KB via 256-colour quantisation, dimensions unchanged).

**⑨ Host compatibility: dsh 0.1.7-alpha.1 (breaking adaptation)**
- **session format v4 event source adapted** (measured: a whole run failed; breaking): after upgrading to 0.1.7-alpha.1, the host's `session-format-v3-to-v4` validates `source.kind` before an event is admitted and **rejects the retired v3 `{kind:'plugin', plugin:'x'}` wrapper** (`message-sources.ts`: "format v4 message requires a producer-owned source kind"), demanding a namespaced `kind:'plugin:<name>'`. Every plugin-injected event used the old wrapper, so a new run threw while writing events (probe-v3's journal was never written). Fix: all four `source`s became `{kind:'plugin:dsh-plugin-teamflow', ...}` (dropping the `plugin` field, keeping `form`/`summary`), with a regression assertion that the pool only contains the new shape. Note: `runner.ts`'s `session.append('tool-workflow/agent-start', …)` carries no message/source and is outside the v4 validation traversal, so it needs no change.
- **The host floor narrows with the v4 requirement**: `engines.dsh` goes from `>=0.1.5-rc.2 <0.2.0` to **`>=0.1.7-alpha.1 <0.2.0`** — 0.1.6-alpha.2 and earlier have no v4 migration package and their source-kind validation is a **closed whitelist** (`SOURCE_KINDS`) that excludes `plugin:*`, so the two source shapes are mutually incompatible. Measured with semver: `0.1.7-alpha.1` / `0.1.7-alpha.2` / `0.1.7` / `0.1.8` / `0.1.9` **pass**; `0.1.6-alpha.2` / `0.1.6` / `0.2.0-rc.1` / `0.2.0` **fail**.
- **Client session navigation migrated to `uiWorkspace.openSession`**: the symptoms were the workbench run-detail overlay's "🎬 jump to subagent session" staying **greyed out** and global-panel artifact links silently degrading to "open inline in the current session's right bar". The root cause is host-side: a batch of client refactors in 0.1.7-alpha.1 removed the session service's `openSubagent` and `open`, so the plugin's guard `typeof sessions.openSubagent === 'function'` was **always false**. Ruled out by measurement: **18/18** stages had `childId` persisted in the run journal → the data plane was intact, the problem was purely the client API surface. Fix: the only navigation entry point is now `uiWorkspace.openSession` (the same call the host's own `ui-workflow-run` panel uses; target is a session id or a persistent subagent address), `inject` drops the now-unreferenced `sessions` dependency, and the permanently `undefined` predicate `sessions.list.getSnapshot().current` was removed (`SessionListState` no longer has `current`). Benefit: the new API performs a **real jump** (replacing `mainView` and returning the main area to Conversation), whereas the old `openSubagent` only navigated without switching views.
- **New `test/client-host-api.test.js`** (a host removing an API is not a plugin bug, but **nothing in the suite turned red** — what was missing was a contract-surface gate): ① client source must not reference removed members (`openSubagent` / `sessions.open` / `SessionListState.current`); ② every `sessions.<member>` / `uiWorkspace.<member>` used must be in a **frozen whitelist** (based on 0.1.7-alpha.1's `sessions.ts` member table plus `navigation.ts` and `control-types.ts`); ③ using `uiWorkspace` requires injecting it and bridging it to props, while a source with no `sessions.*` reference must not keep a dead `'sessions'` dependency; comments are stripped before scanning, since a migration note necessarily names the removed APIs.
- **Compatibility review conclusion (honest boundary)**: under 0.1.7-alpha.1 **only the v4 source is breaking** — typert strict descriptors still require `create()`, the `subagents.start(name, request)` / `SubagentRun.{id,localAgent,result,dispose()}` signatures are unchanged, the four `tokenUsage` projection buckets (`uncachedInputTokens`/`outputTokens`/`cacheReadTokens`/`cacheWriteTokens`, `stateVersion:2`) and `sessionStats.steps` as the call-count source match `metering.ts` exactly, and `agent.inject/followup/steer`, the read-only `settings`/`locale` ports, `ctx.remote.$mount` and `ctx.locale.*` are all compatible. **But that review only covered session-format v4 and missed the client service API surface** (the removal of `sessions.openSubagent`/`open` was found later), so the conclusion should be regarded as incomplete — which is why the API-surface gate above now exists.

### Known limitations / open items

- **Cross-parent subagent navigation is still disabled**: DSH loads the subagent directory per parent session and `selectSubagent` does not support cross-parent navigation. The plugin already ships `journal.ownerSession` (the originating session) down to stage detail and **disables the jump button with a title/copy hint** when the originating session differs from the current one; it unlocks once the host supports cross-parent navigation (the data is ready).
- **The breaker/stage budget is still a hard-coded constant**: `FRESH_TOKEN_BUDGET` is not yet a service Config (the threshold is not adjustable) and applies only to **a single attempt of a single stage**; this release only made it adapt (×3) to a provider without prompt caching, without changing the judging semantics.
- **The clarification gate is Phase 1 only**: the pre-start gate, PRD assumption visibility and shadow instrumentation have shipped, but the **"PRD confirmation sheet" is not done** — no pause after the PRD, no "edit the plan directly" (`resume(runId, { redoFrom: 'prd', supplement })`), no reuse of the host's native review card. Today the gate only "triggers the first round of alignment"; it does not "keep asking until satisfied" (leftover uncertainties become explicit PRD assumptions). Two things remain to be observed: whether triage over-judges pure `lite` requirements (upgrade rate and token amplification from `journal.triage.upgradedFrom`), and the extra triage call now made on explicit `lite`/`mode` paths (cost <1%, pending measurement).
- **Delivery-form contracts are policy-level for now**: the PRD is required to write form contracts as testable ACs, but a missing one **does not block** (QA/acceptance follow the ACs; it can be upgraded to a host hard gate); the `plugin-client` form has only 2 contract items so far (bundle declaration + `files`), pending real cases.
- **The host's Windows sandbox ACL problem is reported upstream**: in a user-created directory (with no inherited sandbox ACE) the host fails to provision the workspace ACE, so **every shell command in that directory fails** — surfacing only as a tool error deep inside a session with no actionable message (measured cost: one stage burned 52.6k output tokens before anything was reported). The plugin cannot fix it and can only **stop early** and say "this is not the model's fault — fix the workspace and resume" (measured on the same workspace and fault: 52,588 output / 3m45s → **1,510 output / 15s**). The minimal reproduction and measured root cause are in `docs/reports/`.
- **`$DSH_HOME/teamflow/` still has no forgetting mechanism**: `logs/` has a retention policy (latest 20 runs per workspace plus a start-up self-healing sweep), but `runs/` has no TTL or archiving (largest single file 137 KB, one workspace at 2.90 MB) and empty shells that only ever received a `teams.json` are never cleaned up (measured: 6 of 11 directories were empty shells, plus one legacy-format key); `backlog/*.json` each carry an equally sized `.bak`.

### Install

```bash
dsh plugin --profile web add dsh-plugin-teamflow
```

Restart `dsh --profile web` afterwards for the change to take effect. **Upgrade dsh to `0.1.7-alpha.1` (or a later version in the same line) first — otherwise the pipeline fails outright while writing events.**

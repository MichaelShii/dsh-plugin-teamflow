# TeamFlow v0.1.7

[中文](#zh) | [English](#en)

Release — a host-compatibility release: token metering now reads the host's official Session projections instead of scanning historical events (the synchronous event readers were deprecated in dsh 0.1.5-rc.2), and the package declares its DSH compatibility window.

## 中文

### 本次变更

**修复**
- **token 计量改走官方 Session 投影**：dsh 0.1.5-rc.2 起，宿主把 `Session.eventAt()` / `snapshotEvents()` / `ownEvents()` 三个同步历史读取器标记为 deprecated（存量调用可留、**新调用禁止**，方向是不再把完整事件序列常驻内存）。计量来源因此改为**官方投影优先**：`ctx.sessionProjections.stateOf(session,'tokenUsage')` 取四桶（输入未命中/命中/写缓存/输出）+ `'sessionStats'.steps` 取调用数——与宿主 token-meter 同一份 fold，重试替换语义更准，且**不再扫描任何历史事件**。投影缺失（最小 profile）、四桶全 0 或读取异常时静默回退原事件扫描：不虚报 0、不中断流水线，存量环境行为不变
- **护栏改用官方通道**：① 轻提醒从手写 `session.append('user/message')` + step/end 刷写时序，改为官方 `run.localAgent.inject()`——宿主在协议安全边界整批认领，原先注释担心的「插入 tool_calls→tool_result 触发 400」并不存在；② 挂死判据从「多源取最长事件视图」长度启发式，改为官方 **`subagentTiming` 投影**的 `active.through`（已提交事件时间，不受视图失明影响）。长工具静默执行（跑十几分钟测试无输出）仍由活动守卫豁免；投影不可用时回退旧启发式。**中止语义与阈值均未变**

**改进**
- **声明宿主兼容窗口**：`package.json` 新增 `engines.dsh: ">=0.1.5-rc.2 <0.2.0"` 与 `dsh.manifestVersion: 1`（dsh 0.1.5 起支持的公共 manifest 字段），README「版本锚定」段同步到 v0.1.5-rc.2
- **兼容核对结论入档**：会话格式 V3 与 Session 生命周期（`SessionHandle`、异步 `agentLoop.create()`、会话锁）、`ctx.agent` 移除与 Inbox 类型化、插件面板 Slot 迁移（`conversation` 根 slot → `main` 下的 `conversation` key）、默认工具调整、subprocess handle 去除 pid——本插件均未使用受影响接口，`conversation.view` / `conversation.input.right` 未变（已实测校验）
- **清理死注入**：`static inject` 硬注入的 `tokenMeter` 全仓从未使用 → 移除（假依赖会拖累插件加载条件）
- **工作区 key 描述纠偏**：文档里「优先使用 DSH workspace UUID」与事实不符——该分支当前不可达（宿主 `resolveByPath` 是异步、插件同步调用），实际生效的是路径派生 key；注释与 AGENTS.md 已改为事实描述

**已知待办**
- 护栏的**复读检测**仍读已弃用的事件读取器（提醒通道与挂死判据已迁官方；复读需要流式文本内容）：官方替代是订阅 `'session/event'` post-commit 投递，需先定等价判据（`docs/TODO.md`）。本次行为与阈值不变

## English

### Changes

**Fixes**
- **Token metering now reads the host's official Session projections**: as of dsh 0.1.5-rc.2 the host deprecates the three synchronous history readers — `Session.eventAt()`, `snapshotEvents()`, `ownEvents()` (existing calls may stay, **new calls are prohibited**; the storage direction is to stop keeping the complete event sequence in memory). Metering therefore prefers the official projections: `ctx.sessionProjections.stateOf(session,'tokenUsage')` for the four buckets (uncached input / cache read / cache write / output) plus `'sessionStats'.steps` for the call count — the same fold the host token-meter runs, more accurate under retries, and **no historical scan at all**. When the projection is missing (minimal profile), all-zero, or unreadable, metering silently falls back to the previous event scan: it never invents zeros and never interrupts a pipeline, so existing environments behave exactly as before
- **The guard now uses official channels**: (1) light reminders moved from hand-rolled `session.append('user/message')` plus a step/end flush state machine to the official `run.localAgent.inject()` — the host claims the batch at a protocol-safe boundary, so the tool_calls→tool_result window the old comment feared does not exist; (2) hang detection moved from a "longest of several event views" length heuristic to the official **`subagentTiming` projection**'s `active.through` (committed-event time, immune to a blind view). Long silent tool runs stay exempt via the agent-activity guard, and the old heuristic remains as a fallback when the projection is unavailable. **Abort semantics and thresholds are unchanged**

**Improvements**
- **Declared DSH compatibility window**: `package.json` gains `engines.dsh: ">=0.1.5-rc.2 <0.2.0"` and `dsh.manifestVersion: 1` (public manifest fields supported since dsh 0.1.5), and the README version anchor is updated to v0.1.5-rc.2
- **Compatibility review recorded**: Session format V3 and the Session lifecycle (`SessionHandle`, asynchronous `agentLoop.create()`, session lock), the `ctx.agent` removal and typed Inbox, the plugin panel slot migration (root `conversation` slot → the `conversation` key under `main`), default-tool changes, and subprocess handles dropping `pid` — this plugin uses none of the affected interfaces, and `conversation.view` / `conversation.input.right` are unchanged (verified by inspection and tests)
- **Dead injection removed**: the hard-injected `tokenMeter` service was never read anywhere → dropped from `static inject` / `setRuntime` / the runtime singleton (a phantom dependency only tightens the plugin's load conditions)
- **Workspace-key description corrected**: the documented "prefer the DSH workspace UUID" path is currently unreachable (the host's `resolveByPath` is asynchronous while the plugin calls it synchronously), so the effective key is the path-derived slug; the comments and AGENTS.md now state the facts

**Known follow-up**
- The guard's **repeat detection** still reads the deprecated event readers (the reminder channel and the hang criterion are off them now; repeat detection needs streaming text content). The official replacement is subscribing to the `'session/event'` post-commit feed, which needs an equivalent-criterion design pass first (`docs/TODO.md`). Behavior and thresholds are unchanged in this release

## 中文

### 本次变更

**新增**
- **分支策略闭环**（ADR-2026-08-27）：启动前用户决策（`needs-decision` 四情况：main+干净 / main+脏 / feature+干净 / feature+脏；选项：stash / commit / 新建 / 沿用 / 自定义兜底）；`branchPolicy` / `branchName` / `preAction` / `commitMessage` 决策参数；auto=建 `feat/<slug|branchName>`、keep=沿用；`preAction`（stash/commit）在 sanity 前执行，完成汇报附 stash pop 提醒
- **收尾合回决策**（与前置对称）：完成汇报带「合回决策邀请」，新工具 `teamflow_merge`（① host 代为合回 ② 给命令自行合回 ③ 暂缓）；`journal.mergeStatus` 持久化（pending/merged/kept/failed）
- **统一收口提交**：子代理只改不提交（Git discipline 硬约束，禁 checkout main/merge/commit），host 验收通过后单 commit（代码 + 任务夹产物）；结构性消灭文档漏提交与未验收中间态；failed/cancelled/打回超限不提交（工作区保留人工处理）
- **视觉验证能力条件化**：`llm.resolveModelInfo` 探测模型 `inputModalities` → QA/验收视觉条款动态生成——支持视觉=DOM 计算断言优先 + browser-use 截图看图 + 人工补测收窄（音频/真机/FPS/读屏）；不支持=禁截图看图（防幻觉/循环，历史禁令动机=模型不识图），只走 DOM 计算断言 + 视觉观感进人工补测
- **需求意图预检**：疑问/建议/反馈句式（「是不是应该」「要不要」等）→ `needs-confirmation` 不启动，主线程 Agent 先向用户确认（实测：反馈「是不是应该加个 Toast」曾被误判为需求启动流水线）
- **activeTeams 持久化**：会话→团队映射落盘 `$DSH_HOME/teamflow/active-teams.json`，重启/刷新后恢复（UI 状态与启动通道一致，agent 记忆 teamId 不再绕过团队状态）

**修复**
- 护栏注入通道：`subagents.start` 句柄无 inject → 改用 DSH 官方 `session.append('user/message')`；注入改安全窗口（step/end 后 flush，防插进 tool_calls→tool/result 序列导致 provider 400——实测 tf-mtcnejqj 曾烧 1.98M）
- 复读检测重复计数 bug：轮询重复收集事件导致计数虚增（实际 4 次 × 3 轮 = 12 压线误杀，实测 tf-mtcomxpq 开发两次被误杀）→ 增量收集（复读/token 观测/提醒注入共用单一指针）
- `isUnretryable` 覆盖 400/invalid_request（provider 客户端拒绝不再重试烧钱）
- 开发任务全部失败 → 停止流水线（无产物可测不再继续 QA 误测；部分失败仍继续 QA 测成功部分）
- resume 断点按阶段定位（PRD 重试成功后不再被失败尝试带回重跑，实测 tf-mtcomxpq）
- 分支 slug 派生（branchName > triageSlug > 需求英文标识词 > r<N> > feature；分支检查移到 initBacklog 之后——修复「feat/feature」）
- `journal.options` 透传 branchPolicy 等决策参数（keep 不再被吞，实测 tf-mtd6mbeq）
- DSH 0.1.2-alpha.1 事件词汇适配（text-chunks/reasoning-chunks → assistant/chunk 双兼容）；tool schema 校验兼容（needs-decision 不返回 runId 字段）

**其他**
- 执行路径基准（小需求样本）与假优化判定收敛：`docs/benchmarks/hold-pipeline-vs-native.md`（流水线多花 44% 是质量预算非浪费——470 行测试 + AC 逐条验收；billed 96% 为 cacheRead 但命中价≈input 1/10，真实差距 ~1.4M 等价；「共享已读文件」等五项判定假优化）

## English

### Changes

**New**
- **Branch-policy decision loop** (ADR-2026-08-27): pre-start user decision (`needs-decision` across 4 scenarios: main+clean / main+dirty / feature+clean / feature+dirty; options: stash / commit / new branch / stay / custom); `branchPolicy` / `branchName` / `preAction` / `commitMessage` decision params; auto=create `feat/<slug|branchName>`, keep=stay; `preAction` (stash/commit) runs before sanity, completion report reminds `git stash pop`
- **Post-acceptance merge decision** (symmetric): completion report carries a merge-decision invitation, new tool `teamflow_merge` (host merges / print command for manual merge / defer); `journal.mergeStatus` persisted (pending/merged/kept/failed)
- **Unified closing commit**: subagents never commit/merge (Git discipline hard constraint), host commits once after acceptance (code + task-folder docs together); structurally eliminates missing-doc commits and un-accepted intermediate states; failed/cancelled/rework-exceeded stays uncommitted for human handling
- **Visual-verification capability gating**: probe model `inputModalities` via `llm.resolveModelInfo` → QA/acceptance visual clauses generated dynamically — vision-capable: scripted DOM assertions first + browser-use screenshot reading + narrowed manual checklist (audio/real-device/FPS/screen-reader); text-only: no screenshot-reading (prevents hallucination loops — the original ban's motivation), scripted DOM assertions only + visual-judgment items into the manual checklist
- **Requirement-intent pre-check**: question/suggestion phrasing (「是不是应该」「要不要」 etc.) → `needs-confirmation`, no pipeline start; main-thread Agent asks the user first (verified: a feedback message "should we add a Toast?" was once misjudged as a requirement and started a pipeline)
- **activeTeams persistence**: session→team mapping persisted to `$DSH_HOME/teamflow/active-teams.json`, restored on restart/refresh (UI state consistent with the start path; agent-remembered teamId no longer bypasses team state)

**Fixes**
- Guard injection channel: `subagents.start` handle has no inject → use DSH official `session.append('user/message')`; injection moved to a safe window (flush after step/end — never between assistant(tool_calls)→tool/result, which caused provider 400 and burned 1.98M on tf-mtcnejqj)
- Repeat-detection double-count bug: polling re-collected the same events, inflating counts (actual 4 × 3 polls = 12 threshold hit — tf-mtcomxpq dev killed twice) → incremental collection (repeat / token-observation / reminder-injection share one pointer)
- `isUnretryable` covers 400/invalid_request (no more pointless retry burn)
- Pipeline stops when ALL dev tasks fail (nothing to test; partial failure still proceeds to QA for the successful parts)
- Resume breakpoint located per-stage (a reworked-and-passed PRD no longer drags the resume back to re-run PRD/tech — tf-mtcomxpq)
- Branch slug derivation (branchName > triageSlug > English identifier in requirement > r<N> > feature; branch check moved after initBacklog — fixes the "feat/feature" case)
- `journal.options` now carries branchPolicy & friends (keep no longer swallowed — tf-mtd6mbeq)
- DSH 0.1.2-alpha.1 event-vocabulary adaptation (text-chunks/reasoning-chunks → assistant/chunk, dual-compatible); tool output-schema compatibility (needs-decision omits runId)

**Other**
- Small-requirement execution benchmark + false-optimization verdicts: `docs/benchmarks/hold-pipeline-vs-native.md` (the pipeline's extra 44% is a quality budget — 470 lines of tests + per-AC acceptance; 96% of billed is cacheRead at ~1/10 hit price, real gap ~1.4M equivalent; five candidate optimizations judged fake)

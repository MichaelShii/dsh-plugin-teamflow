# TeamFlow v0.1.4

[中文](#zh) | [English](#en)

Bugfix release — driven by one real run (tf-mte906e9): branch-decision loop, guard false-kills on large-file tasks, resume breakpoint honoring open QA defects, no auto-retry after degradation, and a dev→QA submission gate. Plus README screenshots and a CI lockfile fix.

## 中文

### 本次变更

**修复**（全部由真实 run tf-mte906e9 实锤驱动）
- **分支决策死循环**：`branchPolicy='auto'` 同时是默认值与「已确认新建分支」的回传值，协议缺「已确认」信号——用户确认新建后重发 `auto` 再次触发 needs-decision（工作区干净场景无 preAction 可带）。修复：新建分支选项 value 改显式确认值 `'new'`（选项 value 即回传协议），显式 `branchName`/`preAction` 视为确认信号
- **护栏复读判定升级为状态判定**：大文件 read-edit 循环是正常模式（每次 edit 后必须重读确认，相似推理片段逐字累积可达阈值）——检测到变更进展（edit/write）时仅记录观察不中止；零变更进展的纯复读（真退化）照拦。r26 一次 run 内 6 次误杀（技术方案/T2/QA 修复/验收）
- **进展信号扩展含脚本执行**：QA/验收等只读分析任务（read + 跑测试脚本，不 edit）不再被误杀——bash/pwsh 跑脚本 = 有进展
- **退化中止不再自动重试**：实证 6 次护栏中止自动重试全部失败（复读计数 12→27 递增，污染会话越滚越差），而 resume（全新会话）一次成功——退化中止直接 needs-human，引导 `teamflow_resume`
- **resume 断点尊重 QA 缺陷未闭环**：P0-P2 缺陷仍 open → 断点回「QA 测试」修复-复验闭环（不再带缺陷代码直接进验收；判定提前到「第一个无 done 阶段」之前——验收失败过也会正确回 QA）
- **resume 不再删除失败 stage 记录**（历史失败痕迹保留，只清 running/pending）
- `hasOpenBlockingBugs` store key 统一（workspace||product||default），防老 run 查错 store 误判无缺陷

**新增**
- **提测门禁**：开发任务失败（哪怕 1 个）→ needs-human 拦截，不进 QA——failed = 已知缺口，QA 检查轮必然重复报告同一缺项（r26 QA 轮 450k token 白烧，报告的 D1-D4 全是 T2 缺项）。配套 resume 精确补跑：复用 done 任务产物，仅重跑 failed 子卡（`buildDevTaskDefs` 单一来源）
- **README 界面预览**：5 张真实工作台截图（流水线视图/看板/阶段详情/看板任务详情/团队选择，`docs/screenshots/`），中英双语

**其他**
- pnpm-lockfile 同步（react 移 peerDependencies 后 lockfile 未更新 → CI frozen-lockfile 校验失败 `ERR_PNPM_OUTDATED_LOCKFILE`）

## English

### Changes

**Fixes** (all driven by one real run, tf-mte906e9)
- **Branch-decision loop**: `branchPolicy='auto'` served both as the default and as the value sent back after the user confirmed "create branch" — no "confirmed" signal existed, so resending `auto` re-triggered needs-decision (clean workspace leaves nothing to pass as preAction). Fix: the "create branch" option value is now the explicit confirmation value `'new'` (option values are the reply protocol); explicit `branchName`/`preAction` also count as confirmation
- **Guard repeat-detection upgraded to state-detection**: large-file read-edit loops are normal (must re-read after each edit; similar reasoning fragments can accumulate to the threshold verbatim) — with change progress (edit/write) the guard only logs observation; pure repeat with zero change progress (true degradation) still aborts. 6 false kills in one run (tech/T2/QA-fix/acceptance)
- **Progress signal extended to script execution**: read-only analysis tasks (QA/acceptance: read + run test scripts, no edits) no longer falsely killed — running scripts (bash/pwsh) counts as progress
- **No auto-retry after degradation**: evidence — all 6 guard aborts failed their auto-retries (repeat count climbed 12→27 in the polluted session), while resume (fresh session) succeeded on the first try. Degradation now goes straight to needs-human with a `teamflow_resume` hint
- **Resume breakpoint honors open QA defects**: P0-P2 bugs still open → resume goes back to the QA fix-reverify loop (no more accepting code with known defects; the check now precedes the "first stage without done" scan so even failed acceptance attempts route back to QA)
- **Resume no longer deletes failed stage records** (history retained; only running/pending cleared)
- `hasOpenBlockingBugs` store key unified (workspace||product||default) so legacy runs without a workspace can't query the wrong store

**New**
- **Dev→QA submission gate**: any failed dev task → needs-human, no QA entry — a failed task is a known gap and the QA pass would only re-report the same missing items (the r26 QA pass burned 450k tokens reporting D1-D4, all of which were T2's missing work). Paired resume re-runs exactly the failed subtasks (done-task outputs reused; `buildDevTaskDefs` single source of truth)
- **README screenshots**: 5 real workbench captures (pipeline view / board / stage detail / board task detail / team selector, `docs/screenshots/`), bilingual

**Other**
- pnpm-lockfile synced (react moved to peerDependencies without a lockfile update → CI frozen-lockfile failed with `ERR_PNPM_OUTDATED_LOCKFILE`)

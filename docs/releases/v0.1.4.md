# TeamFlow v0.1.4

[中文](#zh) | [English](#en)

Bugfix release — branch-decision loop, guard false-kills on large-file tasks, resume breakpoint honoring open QA defects, no auto-retry after degradation, and a dev→QA submission gate. Plus README screenshots and a CI lockfile fix.

## 中文

### 本次变更

**修复**
- **分支决策死循环**：用户确认「新建分支」后重发启动参数仍会再次弹出分支决策（干净工作区场景）。修复：决策选项增加显式确认值，自定义分支名/工作区处理参数均视为已确认
- **护栏误杀大文件任务**：模型在大文件上「读-改-读-改」是正常模式（每次修改后必须重读确认），可能被误判为推理复读而中止。修复：复读判定升级为状态判定——有实际修改进展时不中止，仅纯复读（零进展）才中止
- **QA/验收只读任务不再被误杀**：QA 跑测试脚本、验收核对代码这类只读分析任务（不做文件修改）不再被复读检测误伤——执行脚本同样视为进展信号
- **退化中止不再自动重试**：护栏检测到真退化（推理复读死循环）后，自动重试大概率在同一污染会话内复现且持续烧钱——改为直接需人工介入，引导 `teamflow_resume`（全新会话续跑，实证一次成功）
- **断点续跑尊重未闭环的 QA 缺陷**：QA 打回修复未完成（阻断缺陷仍 open）时，resume 回到 QA 修复-复验闭环，不再带着已知缺陷直接进产品验收；验收失败过的 run 同样正确回 QA
- **历史失败记录保留**：resume 不再清除失败的阶段记录（审计可追溯）

**新增**
- **提测门禁**：开发阶段有任务失败（哪怕 1 个）→ 需人工介入，不再自动进入 QA——失败任务是已知缺口，QA 检查必然重复报告同一缺项。人工处理后 resume 会**精确补跑失败任务**（已完成任务产物复用，不重跑）
- **README 界面预览**：5 张真实工作台截图（流水线视图/看板/阶段详情/看板任务详情/团队选择）

**其他**
- pnpm-lockfile 同步（依赖调整后 CI 的 frozen-lockfile 校验失败，已修复）

### 安装

```bash
dsh plugin --profile web add dsh-plugin-teamflow
```

## English

### Changes

**Fixes**
- **Branch-decision loop**: resending start params after the user confirmed "create branch" still re-triggered the branch decision (clean-workspace case). Fix: decision options now carry an explicit confirmation value; a custom branch name or workspace-handling param also counts as confirmed
- **Guard false-kills on large-file tasks**: read-edit-read-edit on large files is normal model behavior (must re-read to confirm after each edit) and could be mistaken for reasoning repetition. Fix: repeat detection upgraded to state detection — actual edit progress means no abort; only pure repetition with zero progress is treated as degradation
- **Read-only analysis tasks (QA/acceptance) no longer false-killed**: running test scripts counts as progress, so QA/acceptance loops (read + run scripts, no edits) are no longer aborted
- **No auto-retry after degradation**: retrying inside the same polluted session after a real degradation (reasoning loop) almost certainly fails and keeps burning tokens — now goes straight to human intervention with a `teamflow_resume` hint (fresh session, proven to succeed on the first try)
- **Resume honors open QA defects**: with blocking defects still open, resume goes back to the QA fix-reverify loop instead of accepting code with known defects; runs with failed acceptance attempts also route back to QA correctly
- **Failed stage history retained**: resume no longer clears failed stage records (audit trail preserved)

**New**
- **Dev→QA submission gate**: any failed dev task → human intervention, no automatic QA entry — a failed task is a known gap and the QA pass would only re-report the same missing items. After manual handling, resume **re-runs exactly the failed subtasks** (completed-task outputs are reused, not re-executed)
- **README screenshots**: 5 real workbench captures (pipeline view / board / stage detail / board task detail / team selector)

**Other**
- pnpm-lockfile synced (CI frozen-lockfile check failed after dependency adjustments; fixed)

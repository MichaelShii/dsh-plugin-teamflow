> 本版焦点：**兼容 dsh 0.2.2-rc.2 破坏性子代理 API 变更（issue #38）** ＋ **公共 CI 可跑性修复**。
> 逐笔归属与真机取证见 `docs/devlog.md` 的 v0.3.4 批次。本文件面向使用者；内部流水不在正文里。

## 中文

### ⬆️ 升级要点

- **`engines` 无变化**：`engines.dsh` 仍为 `>=0.2.1-rc.5 <0.3.0`，**覆盖** dsh `0.2.2-rc.2`/`rc.3`。无需迁移。
- **重要：若你运行在 dsh `0.2.2-rc.2` 及以后**，此前会起流水线即崩（见 issue #38），本版修复后可直接运行；升级后**重启** `dsh --profile web`（桌面版重启应用）生效。
- 无 `teamflow_*` 工具 schema / journal / 任务夹契约改动，**不需要迁移数据**。

### 🐛 修复：dsh 0.2.2-rc.2 破坏性子代理 API 变更导致流水线起不来（issue #38）

`dsh 0.2.2-rc.2` 对 subagent 服务做了两处破坏性变更（各有官方迁移指南），本插件两处都中招，表现为**起跑即崩**（PRD 阶段 0 token、childId=null、连续重试后需人工介入）：

**① `ctx.subagents.list()` 被删除**（迁移指南 `docs/upgrade-guide/v0.2.1-rc.2/subagent-service-methods/` D3：改用 `getProvider(name)` 检查已知 provider，不再枚举全部注册名）。

- 现象：`No subagent provider available (the subagents registry is empty)`。
- 修复：`providerName()` 改为**优先 `getProvider` 逐个探测已知候选**（`spawn`→`fork`），旧宿主（只有 `list()`）回退枚举——rc.2+、rc.1、更旧宿主三态均正确。

**② `startActivation` 的 `request` 嵌套被移除、字段提升到 spec 顶层**（迁移指南 `docs/upgrade-guide/v0.2.1-rc.2/subagent-activation-options/`：`prompt`/`parent`/`agentOptions` 等直接挂 `SubagentActivationSpec`）。

- 现象：`Cannot read properties of undefined (reading 'id')`——新宿主读顶层 `spec.parent.id`，而旧调用把 `parent` 放在 `spec.request` 里 ⇒ 顶层 `parent` 为 undefined ⇒ 崩（`triage` 与 `runAgent` 两条 `startActivation` 调用都中招）。
- 修复：两处调用改为**扁平字段与 `request` 嵌套同时传**（新宿主读顶层、旧宿主读嵌套，多余键被忽略），`runner.ts` + `triage.ts` 双兼容 rc.1 与 rc.2+。

### 🐛 修复：公共 CI 因测试 import `runner.ts` 拉入宿主私有包而红

- **根因**：`resolve-child-route` / `dev-continue-timeout` 两个测试 import `runner.ts`，而 `runner.ts` 顶层 import 了 `guard.ts` / `util.ts` 的 `@deepseek-ai/dsh-llm`（公共 CI 无此私有包）⇒ `ERR_MODULE_NOT_FOUND`，CI 红（本地有 dsh profile 才绿）。
- **修复**：纯函数 `resolveChildRoute` / `finalizeNoTextStage` 下沉到 `host/core/agent/route.ts`（只依赖 context/types），`runner.ts` re-export 保持既有 import 面不变；两测试改 import `route.ts`。

### 📝 文档

- `README.md` / `README.en.md`：基线跟进到 `v0.2.2-rc.2`，semver 矩阵补 `0.2.2-rc.1`/`rc.2` 行；英文版整体对齐中文（修掉 `alpha.4` 陈旧漂移与缺失的 rc.5 抬升记录），并补上述两处破坏性变更的说明。

## English

### ⬆️ Upgrade highlights

- **No `engines` change**: `engines.dsh` stays `>=0.2.1-rc.5 <0.3.0`, already covering dsh `0.2.2-rc.2`/`rc.3`. No migration needed.
- **Important: on dsh `0.2.2-rc.2` and later**, the pipeline previously crashed on startup (see issue #38); this release fixes it. **Restart** `dsh --profile web` (restart the desktop app) after upgrading.
- No `teamflow_*` tool schema / journal / task-folder contract changes — **no data migration**.

### 🐛 Fix: dsh 0.2.2-rc.2 breaking subagent API changes broke pipeline startup (issue #38)

`dsh 0.2.2-rc.2` made two breaking changes to the subagent service (each has an official migration guide); this plugin was hit by both, showing up as **crash-on-start** (PRD stage 0 tokens, childId=null, human intervention after repeated retries):

**① `ctx.subagents.list()` was removed** (migration guide `docs/upgrade-guide/v0.2.1-rc.2/subagent-service-methods/` D3: use `getProvider(name)` to check known providers; the service no longer enumerates all registered names).

- Symptom: `No subagent provider available (the subagents registry is empty)`.
- Fix: `providerName()` now **probes known candidates via `getProvider`** (`spawn`→`fork`) first, falling back to `list()` enumeration on older hosts — correct across rc.2+, rc.1, and older.

**② `startActivation`'s nested `request` was removed and fields lifted onto the spec top level** (migration guide `docs/upgrade-guide/v0.2.1-rc.2/subagent-activation-options/`: `prompt`/`parent`/`agentOptions` are passed directly on `SubagentActivationSpec`).

- Symptom: `Cannot read properties of undefined (reading 'id')` — the new host reads top-level `spec.parent.id`, but the old call put `parent` in `spec.request` ⇒ top-level `parent` is undefined ⇒ crash (both `triage` and `runAgent` `startActivation` calls were hit).
- Fix: both calls now pass **both flat fields and the nested `request`** (new host reads top level, old host reads the nested object; extra keys are ignored), dual-compatible in `runner.ts` + `triage.ts` across rc.1 and rc.2+.

### 🐛 Fix: public CI red because tests importing `runner.ts` pulled in a host-private package

- **Root cause**: the `resolve-child-route` / `dev-continue-timeout` tests imported `runner.ts`, whose top-level imports `guard.ts` / `util.ts` pull in `@deepseek-ai/dsh-llm` (absent on public CI) ⇒ `ERR_MODULE_NOT_FOUND`, CI red (green only locally with a dsh profile).
- **Fix**: pure functions `resolveChildRoute` / `finalizeNoTextStage` moved into `host/core/agent/route.ts` (depends only on context/types); `runner.ts` re-exports to keep the existing import surface; the two tests now import `route.ts`.

### 📝 Docs

- `README.md` / `README.en.md`: baseline moved to `v0.2.2-rc.2`, semver matrix gains `0.2.2-rc.1`/`rc.2`; English fully aligned with Chinese (drops the stale `alpha.4` drift and the missing rc.5 raise), with notes on both breaking changes above.

## 中文

### ⬆️ 升级要点

- **宿主窗口放宽到 dsh 0.2.0-rc.2**（预览版）。区间是**并集** `">=0.1.7-alpha.1 <0.3.0 || >=0.2.0-rc.1 <0.3.0"`——⚠ 上界**不能简单放宽**：semver 的「预发布只匹配同 tuple 区间」规则下，把 `<0.2.0` 直接改成 `<0.3.0`，`0.2.0-rc.1` / `0.2.0-rc.2` **仍判 fail**（semver 7.7.4 实测）。
- **桌面版（dsh 0.2.0 起）需要单独安装一次**：它用独立的 `desktop` profile（`~/.dsh/profiles/desktop`），与 `web` 各自一份 node_modules。**只装在 web 上，桌面版里看不到本插件**（不是插件坏了，是那份 profile 里没装）。且 CLI **明确拒绝** `--profile desktop`（`error: profile "desktop" is managed exclusively by the Electron application`）⇒ **桌面版请用应用内的插件管理界面安装**。
- 升完**重启** `dsh --profile web`（桌面版重启桌面应用）生效。
- ⚠ **prompt 变长了**：`host/prompts/index.ts` 净增 76 行（craft 五条款 + 四处磁盘路径指引）。本仓的 `instruction-budget` 门禁**只管 AGENTS.md、不管 prompt**，所以这部分**未量化**（增量以百字符计，单次调用多几十到几百 tok）。
- 新增日志键 `log.hostScanTruncated`。

### ① 交付枚举不再被上限截断（本版头条）

**取证**：`tf-mupnk8h0-1otbl2`（工作区 `E:\Code\Probe\tf-stpanel-r1`）——工作区里有 pnpm 的 `.pnpm-store/`，里面是**几千个无扩展名 blob**，而旧的跳过名单**漏了 `.pnpm-store`**，且它在 `readdir` 顺序里排在 `AGENTS.md` 之前 ⇒ 瞬间吃满 400 上限 ⇒ 返回的 400 条里**源文件 0 个、HTML 0 个** ⇒ 四项检查同时静默跳过：

```
host 侧加载检查：本次未执行（no-html；根=E:\Code\Probe\tf-stpanel-r1）
host 侧接口核对：本次未执行（skip；源文件 0 个）
host 侧冒烟：本次未执行（no-html）
QA 验证证据观察：交付未见可执行入口（扫到 400 个交付文件），本项跳过
```

而交付其实完好：**28 个交付文件 / 13 个源文件 / 1 个 `index.html`**。机制复现：同目录形状 + 1000 个 store blob ⇒ 不跳点目录时「400 条 / 源文件 0 / HTML 0」；跳过点目录后恢复「23 条 / 源文件 11 / HTML 1」。**用户是在浏览器里点不动才把它暴露出来的。**

**改动**：`scanDeliverableFiles(root, limit)` 返回 `{ files, truncated, limit }`，**点目录一律不遍历**（它们从不是交付物，又最易吃满配额）；`listDeliverableFiles` 退为薄包装（签名与旧行为不变）。三项检查任一 `truncated` ⇒ 追加一条 `log.hostScanTruncated` **撤回提示**。

⚠ **措辞要说准**：那三条「未执行 / 源文件 0 个 / no-html」的**原文保留**（检查确实没执行），撤回靠的是**后一条 warn 点名它们不是事实** ⇒ **顺序也是契约**（编排测试第 ⑨ 组钉住，实测 neg@13 / warn@16）。

**门禁两层**：`test/smoke-check.test.js` ②b 段（扫描器层）、`test/orchestration.test.js` 第 ⑨ 组（接线层，430 个无扩展名文件顶满 400）。变异实测：短路 `if (scanTruncated)` ⇒ 4 条立刻红。

### ② 大文档注入：裸 clip → 「小 teaser + 磁盘完整路径」

按 256 份真实任务夹文档实测：`TECHNICAL.md` 中位 **19075** / 最大 35547；`DESIGN.md` 中位 9338；PRD 中位 6334；QA-REPORT 中位 4430。

| 文档 | 原阈值 | 会截断 | 处置 |
| --- | --- | --- | --- |
| TECHNICAL.md（dev / qaFix） | 12000 | **47/50（94%）** | 4000 + 磁盘路径 |
| DESIGN.md（scaffold / tech） | 10000 | **11/31（35%）** | 4000 + 磁盘路径 |
| PRD.md（design / tech / architect） | 15000 / 12000 | 3~6/56（5~11%） | **阈值不动**，只补路径 |
| QA-REPORT.md（qaFix） | 12000 | 2/51（4%） | **阈值不动**，只补路径 |

⚠ 一个反直觉结论：TECHNICAL 中位 19075 ⇒ **连 4000 的 teaser 也截 94%** ⇒ **磁盘路径才是修复主体，teaser 价值有限**——缺了它，模型根本不知道后面还有内容。

**明确不动**的两处：`clip(scaffold, 10000)` 与 `clip(devSummary, 8000)`——它们**不是磁盘文件**，无路径可指，加提示就是空话。

**门禁**：clip 纪律源码锁 6 道（tech / design 各一条「只用 4000」+ 四条「路径指引覆盖 N 处」：TECHNICAL 2 处、DESIGN 3 处、PRD 3 处、QA 1 处）。

### ③ craft 引导通道（design → dev 接通）

来源是「流水线 vs 裸跑」对照的机制归因：**`designPrompt` 写出的 DESIGN.md 到不了 dev 手里**（`devPrompt` 签名没有 `design` 参数）⇒ 流水线在「做好看」这件事上结构性输给单 agent。

- `devPrompt(task, tech, prd, design, …)` 新增 design 入参，注入视觉规格 + 磁盘路径，明写「视觉规格写在 DESIGN.md 开头，先读它再动手做任何可见的东西」。
- 开关 `TEAMFLOW_CRAFT`：**未设置 / 空串 = 开**，只有 `0` / `false` / `off` / `no` 才关；经 `util.envFlagOn` → `options.craft` → `state.__runCtx.craft`。**不做工具参数**（工具 description 每次都进主会话上下文），**resume 读 journal 快照不读环境变量**。
- 定位收窄为**交互反馈下限 + 状态可见性**，不做审美裁决；QA 只记 **P3 observation、绝不阻断**（弱/本地模型产不出 craft，硬门禁会让插件对它们不可用）。
- ⚠ **净收益至今无定论**：三组样本方向互不相同，全被 QA 返工轮 / dev 任务拆分数 / host 检查静默跳过盖住。详见 `docs/benchmarks/craft-ab-pomodoro.md`。

### ④ 新增脚本

- **`scripts/artifact-selfcheck.mjs`** —— 产物自洽探针（静态、零浏览器依赖）：`[geo]` 几何自洽 / `[bind]` 未绑定按钮与歧义选择器 / `[craft]` 反馈态计数 / `[state]` **死快照** / `[persist]` 持久化缺口。`[state]` 来自一次真实误判：某产物「滑块点不动」，而此前所有静态指标（反馈态规则数 10 vs 9、AC 数、bind/geo）**全绿**——真问题（入口把 value 写死成常量）没有任何门禁看得见。
- **`scripts/hi-report.mjs`** —— 人工介入归因巡检（只读）。动机是本仓曾长期按「humanIntervention 8/23 = 35%」排优先级，而那是**早于 09-17** 的样本。分层实测 91 个 run：09-17 之前 58 个（**20.7%**、failed 12）；09-17 之后 33 个（**9.1%**、**failed 0**），且剩下 3 次**全部**是 `knownIssuesAcceptance`（QA 复验超限 → 产品决策**刻意**交给人，不是缺陷）。
  ⇒ **没有可复跑的度量，旧数字就会一直驱动错误的优先级**——本脚本就是那个度量。

### ⑦ 宿主兼容核对（dsh 0.2.0-rc.2）

**逐项核对：未发现破坏**，七条证据（完整版见 `CHANGELOG.md` 对应节）：

3. `dsh.client.inject` 语义未变。⚠ manifest 类型里那句 "Informational … **not** Cordis service injection" 指的是**对 Cordis 而言**，运行时仍用 manifest 的 `inject` 排 factory 到达顺序——**别把它误读成语义变更**。

6. 宿主只校验 `peerDependencies`、**不读 `engines.dsh`**。
7. dsh 侧无 `CHANGELOG`；`docs/upgrade-guide/` 尚无 0.2.0 篇。

⚠ 以上全是**静态**核对：运行时（cordis 服务在 activate 时是否仍在、插件能否在桌面版 profile 正常加载）**需重启宿主实测**。

### ⬆️ Upgrade notes

- **Host window widened to dsh 0.2.0-rc.2** (preview). The range is a **union**, `">=0.1.7-alpha.1 <0.3.0 || >=0.2.0-rc.1 <0.3.0"` — ⚠ the upper bound **cannot simply be widened**: under semver's rule that a prerelease only matches a range on the same tuple, changing `<0.2.0` to `<0.3.0` still fails for `0.2.0-rc.1` / `0.2.0-rc.2` (measured with semver 7.7.4).
- **The desktop app (dsh 0.2.0+) needs its own install**: it runs from a separate `desktop` profile with its own `node_modules`. Installed only into `web`, **the desktop app will not show the plugin** (nothing is broken — that profile simply doesn't have it). The CLI also **refuses** `--profile desktop` (`managed exclusively by the Electron application`) ⇒ **install it from the desktop app's own plugin management UI**.
- **Restart** `dsh --profile web` (or the desktop app) after upgrading.
- ⚠ **Prompts got longer**: `host/prompts/index.ts` grows by 76 lines net (five craft clauses + four disk-path pointers). This repo's `instruction-budget` gate covers **AGENTS.md only, not prompts**, so the cost is **unquantified** (increment is in the hundreds of characters per prompt).
- New log key: `log.hostScanTruncated`.

### ① The deliverable scan no longer gets cut off (headline)

**Evidence**: `tf-mupnk8h0-1otbl2` — the workspace held a pnpm `.pnpm-store/` with **thousands of extension-less blobs**, and the old skip list **missed it** while `readdir` returns it *before* `AGENTS.md` ⇒ the 400-file cap was consumed instantly ⇒ the returned 400 entries contained **0 source files and 0 HTML** ⇒ all four host checks (load / interface / smoke / evidence observation) **silently skipped** and the journal read as "the delivery contains nothing" — while the delivery was intact (**28 files / 13 sources / 1 `index.html`**). **It surfaced only when the user found the demo page's slider un-clickable in the browser.**

**Fix**: `scanDeliverableFiles(root, limit)` returns `{ files, truncated, limit }` and **never walks dot-directories** (they are never deliverables and are the usual cap-eaters); `listDeliverableFiles` becomes a thin wrapper (same signature, same behaviour). If any of the three checks reports `truncated`, a `log.hostScanTruncated` **retraction** line is appended.

⚠ **Wording matters**: the three "not executed / 0 source files / no-html" lines are **kept verbatim** (the checks genuinely didn't run) — the retraction is a following `warn` that names them as *not facts* ⇒ **order is part of the contract** (pinned by orchestration test group ⑨: neg@13 / warn@16).

**Two test layers**: scanner level (`test/smoke-check.test.js` §2b) and **wiring level** (`test/orchestration.test.js` group ⑨ — 430 extension-less files saturating the 400 cap). Mutation check: short-circuiting `if (scanTruncated)` turns 4 assertions red.

### ② Large-document injection: bare `clip` → small teaser + on-disk full path

Measured over **256 real task-folder documents**: `TECHNICAL.md` median **19075** / max 35547; `DESIGN.md` median 9338; PRD median 6334; QA-REPORT median 4430.

| Document | Old cap | Truncated | Action |
| --- | --- | --- | --- |
| TECHNICAL.md (dev / qaFix) | 12000 | **47/50 (94%)** | 4000 + disk path |
| DESIGN.md (scaffold / tech) | 10000 | **11/31 (35%)** | 4000 + disk path |
| PRD.md (design / tech / architect) | 15000 / 12000 | 3–6/56 (5–11%) | **cap unchanged**, path added |
| QA-REPORT.md (qaFix) | 12000 | 2/51 (4%) | **cap unchanged**, path added |

⚠ Counter-intuitive: with a median of 19075, **even a 4000-char teaser is truncated 94% of the time** ⇒ **the disk path is the actual fix; the teaser is marginal** — without it the model has no idea more content exists.

**Deliberately untouched**: `clip(scaffold, 10000)` and `clip(devSummary, 8000)` — neither is an on-disk file, so there is nothing to point at; a pointer would be noise.

**Gate**: 6 source-level locks (tech / design "only 4000" + four "path pointer covers N sites": TECHNICAL 2, DESIGN 3, PRD 3, QA 1).

### ③ craft guidance channel (design → dev connected)

Born from the mechanism analysis of the "pipeline vs bare agent" comparison: **the DESIGN.md written by `designPrompt` never reached dev** (`devPrompt` had no `design` parameter), so the pipeline structurally lost to a single agent on "make it look good".

- `devPrompt(task, tech, prd, design, …)` gained the `design` parameter, injects the visual spec + disk path, and states that the visual spec is written first in DESIGN.md and must be read before writing anything visible.
- Switch `TEAMFLOW_CRAFT`: **unset / empty = on**; only `0` / `false` / `off` / `no` turn it off; wired `util.envFlagOn` → `options.craft` → `state.__runCtx.craft`. **Not a tool parameter** (tool descriptions enter the main session context every time); **resume reads the journal snapshot, not the environment variable**.
- Narrowed to an **interaction-feedback floor plus state visibility**, not an aesthetic verdict; QA records **P3 observations only, never blocking** (weak/local models cannot produce craft — a blocking gate would make the plugin unusable for them).
- ⚠ **Net benefit is still unproven**: three samples point in different directions, all confounded by QA rework rounds / dev task granularity / silently-skipped host checks. See `docs/benchmarks/craft-ab-pomodoro.md`.

### ④ New scripts

- **`scripts/artifact-selfcheck.mjs`** — static artifact self-check (no browser): `[geo]` geometric consistency, `[bind]` unbound buttons and ambiguous selectors, `[craft]` feedback-state count, `[state]` **dead snapshot**, `[persist]` persistence gaps. `[state]` came from a real false negative: a deliverable whose slider did nothing, while every static metric (feedback rules 10 vs 9, AC count, bind/geo) was **green**.
- **`scripts/hi-report.mjs`** — read-only human-intervention attribution. Motivation: the repo had been prioritising against "humanIntervention 8/23 = 35%", a figure from samples **older than 09-17**. Measured over 91 runs: 58 before 09-17 (**20.7%**, 12 failed) vs **33 after (9.1%, 0 failed)**, and all 3 remaining cases are `knownIssuesAcceptance` (QA rework limit reached ⇒ the product decision is **deliberately** handed to a human, not a defect).
  ⇒ **Without a repeatable measurement, stale numbers keep driving priorities** — this script is that measurement.

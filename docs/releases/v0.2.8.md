## 中文

### ⬆️ 升级要点

- 从 0.2.7 及以前升级：本版起插件会**自己提示新版本**；本次升级仍需手动（命令见 README「升级（对使用者）」），
  之后的新版本就能在工作台 / 插件页里看到并一键升级。
- 升完**重启** `dsh --profile web`（桌面版重启桌面应用）。

### ① 为什么做这个（ADR-0012 的问题定义）

真机观察：插件已更新多版，仍有不少用户停在旧版本。拆成两轴后结论是——问题不在「装不上」，
而在 ①**用户不知道有新版**（发现）②**升级不是点一下**（动作成本）。本版只解决这两轴；
可达性（npm 镜像滞后等）不是本轮问题。

**对存量用户的第一次触达无效**——通知机制本身要靠升级才能获得 ⇒ 老版本用户看不到它。
撬动存量靠 README / 发版通稿写明升级命令，这根杠杆不能省。

### ② 发现：三处落点，一份实现

| # | 落点 | 覆盖谁 |
|---|---|---|
| ① | 宿主插件页徽标 + 操作（`plugins.detail.badge` / `.actions` 槽位贡献） | 去设置页管理插件的人——找「更新」的默认位置 |
| ② | 工作台顶部提示条 | 打开工作台的人（打开时按需探测一次） |
| ③ | 全局面板头部「检查更新」按钮 | **唯一的手动入口**：①②都吃 24h 缓存，用户得有主动问一次的办法 |

三处共用 `client/update-ui.tsx`（唯一实现，不许调用方各写一套）。

⚠️ **三处在 web 与桌面版都可见**（「插件」页是两端同一个页面）；差别只在**升级动作归哪个 profile**：
web 走命令，桌面版在应用内操作（CLI 拒绝 `--profile desktop`）。
探测**按需触发 + 24h 缓存**，不做后台定时（探测功能不得变成轮询）。

### ③ 动作：一键升级 + 守卫

- 走宿主 `pluginManager.installBundle`：备份 / 回滚 / profile 写锁 / install-script 审批 / 取消
  都是宿主现成的，不自己 spawn pnpm。
- **两步确认**：点一次只展开说明（在当前 profile 执行 pnpm 安装、改动依赖、装完要重启），
  再点确认才真调。这条服务路径绕过了宿主工具层的审批门槛 ⇒ 知情责任落在我方。
- **run 进行中拒绝**；失败按宿主分型结论渲染（run 中 / 无插件管理服务 / 非 registry / 待构建包是不同的事）。
- **只对 registry 安装开放一键**：`file:` / git / tarball 装法一键会把依赖**静默换成线上版本**
  （真机踩过：0.2.7 本地部署被一键切成 registry 版，随后回滚）⇒ 只给可复制的裸命令。

### ④ 探测底座（`host/core/update-check.ts`，纯函数）

- `TEAMFLOW_UPDATE=0` 可整体关闭（环境开关不进公开 schema——同 `craft` / `confirm` 的处置）。
- 「跳过此版本」跳的是**具体版本号**：更新的版本出现时仍会提示（跳过 ≠ 永久静默）。
- 4s 超时；**永不抛**：联网失败降级为「不提示」并在返回对象里显式带 `error`——探测不得成为故障源。
- 版本比较含 prerelease 语义；解析不了的版本一律**不提示**（宁可漏报不做假提醒）。

## English

### ⬆️ Upgrade notes

- Upgrading from ≤ 0.2.7: this is the version that **starts telling you about newer ones** — this
  particular upgrade is still manual (commands in README "Upgrade (for users)"); after it, new
  versions surface in the workspace / plugins page with one-click upgrade.
- **Restart** `dsh --profile web` afterwards (or restart the desktop app).

### ① Why (ADR-0012)

Real-world observation: many users stay on old versions despite frequent releases. Split into two
axes, the problem is NOT "can't install" but ①**discovery** (users don't know) and ②**action cost**
(upgrading isn't one click). Reachability (mirror lag etc.) is explicitly out of scope.

**First contact does not reach existing users** — the notice mechanism itself arrives only by
upgrading ⇒ the lever for the installed base is the README / release notes carrying the upgrade
command.

### ② Discovery: three surfaces, one implementation

| # | Surface | Who it covers |
|---|---|---|
| ① | Host plugins-page badge + action (`plugins.detail.badge` / `.actions` slot contributions) | People managing plugins in settings — the default place to look for updates |
| ② | Workspace top banner | People opening the workspace (probes once on open) |
| ③ | Global panel "Check for updates" button | **The only manual entry**: ①② eat a 24h cache, so users need a way to ask |

All three share `client/update-ui.tsx` (single implementation). Probing is **on-demand + 24h cache**;
no background polling.

⚠️ **All three are visible on both web and desktop** (the "Plugins" page is the same page on both);
only the upgrade *action* differs — a command for web, the in-app page for desktop (the CLI refuses
`--profile desktop`).

### ③ Action: one-click upgrade + guards

- Goes through the host's `pluginManager.installBundle` (backup / rollback / profile lock /
  install-script approval / cancel are the host's, not reimplemented).
- **Two-step confirm**; **refuses mid-run**; failures render by the host's typed verdict, not one
  generic "upgrade failed".
- **Registry installs only**: for `file:` / git / tarball installs, one click would **silently swap
  the dependency to the registry version** (hit on a real machine, then rolled back) ⇒ those get a
  copyable bare command instead.

### ④ Probe base (`host/core/update-check.ts`, pure functions)

- `TEAMFLOW_UPDATE=0` disables the whole feature (env-only, not in the public schema).
- "Skip this version" skips that **exact version**; a newer one still notifies.
- 4s timeout; **never throws** — network failure degrades to "no notice" with an explicit `error`.
- Unparseable versions never notify (prefer a missed notice over a false one).

### ⑤ Docs

- README / README.en gain "Upgrade (for users)": one-click and command paths, skip semantics, restart.
- `docs/adr/0012`: full decisions + seven toolbar-presentation rules from five rounds of real-machine
  feedback. Core lesson: **a string with two consumers is two contracts**.

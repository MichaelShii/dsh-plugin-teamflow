# TeamFlow v0.2.1

[中文](#zh) | [English](#en)

Release — 一次「并行安全 + 环境自愈」的小版本（2 个功能提交 / 12 个文件 / +997 −50 行）：多个并行开发任务不再互相踩写集或读到改写前状态（依赖分波调度，社区 issue #4 的完整答案）；Windows 数据盘新建目录首跑流水线必撞的沙箱授权失败（`grantWrite (Win32 5)`）由插件在启动前自动自愈，不再需要任何人工排查。**无破坏性变更**，宿主窗口不变。

Release — a small "parallel-safety + environment self-healing" release (2 feature commits / 12 files / +997 −50 lines): parallel development tasks no longer stomp each other's files or read half-written state (dependency-wave scheduling, the full answer to community issue #4); the sandbox authorization failure every fresh directory on a data disk used to hit on its first pipeline run (`grantWrite (Win32 5)`) is now healed automatically by the plugin before the pipeline starts — no manual investigation. **No breaking changes**; the host window is unchanged.

## 中文

### 升级要点（TL;DR）

- **无破坏性**：宿主窗口不变（`>=0.1.7-alpha.1 <0.2.0`）；技术方案蓝图的 `tasks[]` 新增可选 `reads` 字段、`teamflow_start` 任务参数新增可选 `files`/`reads` 说明——全部向后兼容，旧 journal 与续跑行为不变。
- **升完重启 `dsh --profile web` 生效**；非 Windows 用户升级后无行为差异（新增的 ACL 预检只在 Windows 且宿主带 ACL 沙箱包时激活）。

### 本次变更

**① dev 依赖分波调度（新增，社区 issue #4 的完整答案）**

- **修的问题**：issue #4 报告「多个并行 dev 子代理抢写同一文件」。此前的护栏只有一道：写集有交集的任务合并为一个串行组。但真实蓝图里还有第二类冲突——**依赖阻塞**（issue 的 AC3）：任务 B 要读任务 A 负责改写的文件，B 并行起跑会读到改写前的状态。实测某条流水线 5 个任务里 T2↔T3 互相 `reads` 对方的属主文件，交叉依赖密集。
- **做法（三层护栏不变，新增排序层）**：
  - 写集有交集 → 仍合并为一个组（同一作者调和优于两个 agent 先后覆盖）；
  - 新增**波次分层**：`reads` 命中别人属主文件 / `dependsOn` 声明 / 未声明 `files`（写集未知）三类依赖边做 Kahn 分层——**波内并行、波间屏障**；实测屏障精确到秒（第二波起跑时间 = 第一波最慢任务结束的同一秒，零重叠零提前）；
  - **环 = 软依赖丢边**：互相 reads 的任务若各自独占一波会退化成全串行，改为按声明顺序增量插边、会成环的边丢弃并计数留痕（代价：读方可能与写者同波、读到改写前状态——波屏障保证不会读到半写）；
  - **失败传播**：某波有失败 → 后续波不再启动（跑下去只是烧 token），未执行组记账失败；续跑时按未完成重算波次补跑（复用产物，已完成任务不重跑）。
- **配套契约与修复**：技术方案蓝图 `tasks[]` 与 `teamflow_start` 任务参数支持 `reads`（只读边界，**不阻塞并行**，不确定就省略——未标记视为属主，安全默认）；dev 子代理注入 `[READ-ONLY CONTEXT]` 段（点名「另一个 agent 可能正在改写它，不要修改」）；修掉任务数日志的口径错误（旧文案把「1 个未声明」说成「5 个」）；新增三条留痕日志（分波形状 / 丢边警告 / **只读声明保住并行**——实测某条流水线「按可写边界判定比把 reads 当冲突多保 2 路并发」）。
- **门禁**：`test/overlap-merge.test.js` 扩展 [10] 系列——真实蓝图形状回归（4 波 1+2+1+1、丢边计数）、读链分波、双形态 dependsOn、环丢边、写合并、合并组吸收 reads、30 轮随机不变量（含「未知写集组必须独占一波」）；下标空间转换（建组顺序 → 波次扁平顺序的 remap）由变异测试锁死。

**② Windows ACL 预检自愈（新增，「每次新建目录都碰 ACL」的根治）**

- **根因（控制变量实验实锤）**：宿主沙箱的写授权用一次 `SetNamedSecurityInfoW` 同时写 DACL（能力 SID 的允许 ACE + Everyone 的删除抑制拒绝 ACE）与 SACL（Low 完整性标签）。**写标签进 SACL 需要 `WRITE_OWNER`**，而 owner 身份只隐式授予读控制与改 DACL——于是首跑成败取决于目录 DACL 里有没有给当前用户的**显式** ACE：系统盘用户目录的继承链自带 Full Control（含 `WRITE_OWNER`）→ 必成；**数据盘的继承 DACL 通常只有 `Authenticated Users:(M)` + `Users:(RX)` → 必败（Win32 5）**。四态对照实验：无 ACE 失败 / 显式仅 `WRITE_OWNER` 成功 / 仅 `WRITE_DAC` 失败 / Full Control 成功——单一变量即 `WRITE_OWNER`。
- **修法（插件层自救，不需要管理员）**：流水线起跑时（在任何阶段与任何模型调用之前）用宿主自己的 ACL 包按**同一工作区 SID**（由规范化路径确定性派生）把 standing 授权提前物化——宿主随后命中幂等快路径，**零重复、零残留**（落的就是宿主本来要落的 ACE）。拿不到授权时：自动补一条仅含 `WRITE_OWNER` 位的修复 ACE（该写操作只需改 DACL 的权利，owner 隐式足够 → **无需提权**）后重试；仍失败 → run **立即失败**，附一条可复制的修复命令与「续跑即可」指引——问题被挡在任何子代理之前，不再出现「跑到开发阶段环境不可用、主会话排查几分钟」。
- **边界与回退**：非 Windows、宿主未装 ACL 沙箱包（可选 peer 依赖）、工作区目录不存在 → 预检整体跳过，行为与旧版完全一致；幂等——同目录重复预检是 O(1) 读检查（宿主的精确 ACE 匹配跳过），不触发全树继承传播；修复 ACE 仅含 `WRITE_OWNER` 一个权限位，授给当前用户自己，不影响其他授权面。
- **实测**：真实流水线端到端——新目录首跑在分诊之前打出「已自动补写修复 ACE」，全 run 零授权错误；父目录修复 ACE 的可继承传播同时覆盖已存在的子目录。

### 已知限制 / 开放项

- **宿主侧的根因仍在待上游**：本版本的预检是插件侧自愈（绕过），宿主 `grantWrite` 对「owner 无显式 `WRITE_OWNER` ACE」的目录仍会失败——上游正解（授权前自检并在需要时先补 `WRITE_OWNER`）待 deepseek-ai/deepseek-harness Discussion #7538 跟进。
- **dev 末尾的「QA 独立验证」任务**：技术方案模型会自发把验证自查拆成 dev 任务（本次两个实测 run 都出现）。定位讨论中：保留（dev 是唯一能「发现问题→当场修」的环节）但可能与 QA 阶段职责重叠；正攒拦截率数据（首个样本：自查完成后 QA 仍发现 2 个阻断缺陷），攒够再决定是否用 prompt 收紧。
- **CHANGELOG 0.2.0 段的详细论证仍未迁 `docs/releases/v0.2.0.md`**（历史性内容棘轮基线未下调），随下个版本收口。

## English

### Upgrade notes (TL;DR)

- **No breaking changes**: the host window is unchanged (`>=0.1.7-alpha.1 <0.2.0`); the tech-blueprint `tasks[]` gains an optional `reads` field and `teamflow_start` task parameters gain optional `files`/`reads` hints — all backward compatible; old journals and resume behavior are unchanged.
- Restart `dsh --profile web` after upgrading; on non-Windows the upgrade is a no-op behaviorally (the new ACL preflight activates only on Windows with the host's ACL sandbox package present).

### Changes

**① Dependency-wave scheduling for parallel dev tasks (new — the full answer to community issue #4)**

- **The problem**: issue #4 reported parallel dev subagents stomping the same file. The previous guard was a single merge rule (overlapping write sets collapse into one serial group). Real blueprints contain a second conflict class — **blocked dependencies** (issue AC3): task B reads a file task A is about to rewrite, so B starting in parallel observes pre-write state. Measured on a real pipeline: 5 tasks where T2↔T3 read each other's owner files — dense cross dependencies.
- **Approach (existing three guard layers unchanged, a scheduling layer added)**:
  - Overlapping write sets still merge into one group (reconciliation by one author beats two agents overwriting each other);
  - New **wave layering**: three kinds of dependency edges — `reads` hitting another task's owner file, explicit `dependsOn`, and undeclared `files` (unknown write set) — feed a Kahn layering: **parallel within a wave, barrier between waves**; measured barriers are second-exact (wave 2 starts the same second the slowest wave-1 task ends; zero overlap, zero early starts);
  - **Cycles drop edges as soft dependencies**: mutually-reading tasks owning one wave each would degrade to fully serial, so edges are inserted incrementally in declaration order and a cycle-closing edge is dropped and counted (cost: the reader may share a wave with the writer and observe pre-write state — the wave barrier still guarantees no half-written reads);
  - **Failure propagation**: a failed wave stops later waves from starting (running them only burns tokens); unfinished groups are recorded as failed and resume re-plans the waves from what is unfinished (completed tasks are reused, not re-run).
- **Contracts and fixes**: the tech-blueprint `tasks[]` and `teamflow_start` task parameters support `reads` (a read-only boundary that **does not block parallelism**; omit when unsure — unmarked means owned, the safe default); dev subagents receive a `[READ-ONLY CONTEXT]` block (naming that another agent may be rewriting the file right now); the task-count log no longer misreports "1 undeclared" as "5"; three new trace logs (wave shape / dropped-edge warning / **read-only declarations preserved parallelism** — one measured pipeline kept 2 extra concurrent lanes by judging writable boundaries instead of treating `reads` as conflicts).
- **Gates**: `test/overlap-merge.test.js` gains a [10] series — a real-blueprint shape regression (4 waves 1+2+1+1, dropped-edge counting), read-chain waves, both `dependsOn` forms, cycle dropping, write merging, merged groups absorbing reads, and a 30-round random invariant (including "unknown-write-set groups must own a wave alone"); the index-space conversion (group order → flattened wave order remap) is locked by mutation testing.

**② Windows ACL preflight self-healing (new — root-cures "every fresh directory hits the ACL")**

- **Root cause (settled by a controlled experiment)**: the host sandbox's write grant uses one `SetNamedSecurityInfoW` call to write the DACL (capability-SID allow ACE + an Everyone deny on ambient delete) and the SACL (Low mandatory label) together. **Writing the label into the SACL requires `WRITE_OWNER`**, and ownership only implicitly grants READ_CONTROL and WRITE_DAC — so first-run success depends on the directory DACL carrying an **explicit** ACE for the current user: the system-drive user profile chain ships Full Control (which includes `WRITE_OWNER`) → always succeeds; **a data drive's inherited DACL usually has only `Authenticated Users:(M)` + `Users:(RX)` → always fails (Win32 5)**. A four-state experiment: no ACE fails / explicit `WRITE_OWNER`-only succeeds / `WRITE_DAC`-only fails / Full Control succeeds — the single decisive variable is `WRITE_OWNER`.
- **Fix (plugin-side self-healing; no admin needed)**: when a pipeline starts — before any stage and any model call — the plugin materializes the standing workspace grant using the host's own ACL package and the **same workspace SID** (deterministically derived from the canonical path), so the host later hits its idempotent exact-ACE fast path: **zero duplication, zero residue** (the ACE that lands is the one the host would have written anyway). When authorization is unavailable: a repair ACE carrying only the `WRITE_OWNER` bit is added automatically (that write needs only owner-implicit DACL rights → **no elevation**) and the grant is retried; if that still fails, the run **fails immediately** with a copy-pasteable repair command and a "resume and go" hint — the problem is caught before any subagent, instead of surfacing mid-development as an unavailable environment followed by minutes of manual investigation.
- **Boundaries and fallback**: non-Windows, a host without the ACL sandbox package (an optional peer dependency), or a missing workspace directory → the preflight is skipped entirely and behavior matches the previous release; it is idempotent — repeated preflights on the same directory are an O(1) read check (the host's exact-ACE skip), never triggering full-tree inheritance propagation; the repair ACE carries a single `WRITE_OWNER` permission bit, granted to the current user, touching no other authorization surface.
- **Measured**: end-to-end on a real pipeline — a fresh directory's first run prints "repair ACE written" before triage and the whole run shows zero authorization errors; the parent-directory repair ACE's inheritable propagation also covers already-existing subdirectories.

### Known limitations / open items

- **The host-side root cause is still pending upstream**: this release's preflight is plugin-side self-healing (a workaround); the host `grantWrite` still fails on directories whose owner lacks an explicit `WRITE_OWNER` ACE — the upstream fix (self-check before granting, topping up `WRITE_OWNER` when needed) is tracked in deepseek-ai/deepseek-harness Discussion #7538.
- **The dev-final "QA independent verification" task**: the tech-phase model spontaneously splits a self-check task into development (both measured runs in this release show it). Positioning is under discussion: keep it (development is the only stage that can "find a problem and fix it on the spot") but it overlaps with the QA stage; interception-rate data is being collected (first sample: QA still found 2 blocking defects after the self-check), and a prompt tightening will be decided once enough runs accumulate.
- **The verbose argumentation in the CHANGELOG 0.2.0 section has not yet moved to `docs/releases/v0.2.0.md`** (the history-content ratchet baseline is not lowered yet); this lands with the next release.

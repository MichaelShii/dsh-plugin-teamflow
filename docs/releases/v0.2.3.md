# TeamFlow v0.2.3

[中文](#zh) | [English](#en)

Release — 一次「诚实可见性」版本（9 个提交 / 21 个文件 / +1267 −580 行）：让流水线在三类最容易出黑箱的地方把事实摆到台面上——**git 提交面**（不再 `-f` 强加被 .gitignore 忽略的文件、add 失败不谎报、收口提交前列出完整清单）、**失败诊断**（带正文长度与响应块构成，空收尾/宿主中断/预算截断在日志内即可分辨）、**主会话触发纪律**（显式禁令堵住「需求简单就绕过流水线自己干」）。附带空收尾止损（A 档文件兜底）、只读检查 CLI `run-inspect` 与空收尾根因归因（实测数据）。**无破坏性变更**，宿主窗口不变。

Release — an "honest visibility" release (9 commits / 21 files / +1267 −580): makes the pipeline state facts on the table in the three places most prone to black boxes — the **git commit surface** (no more force-adding `.gitignore`d files, no more false "added" on failure, full scope listed before the closing commit), **failure diagnostics** (body length + response-block shape, so empty-finish / harness-abort / budget-cut are distinguishable in the log itself), and **main-session trigger discipline** (an explicit ban on bypassing the pipeline when the requirement looks simple). Plus the empty-finish stop-loss (file-fallback verdict), a read-only inspection CLI `run-inspect`, and a measured root-cause attribution of empty finishes. **No breaking changes**; the host window is unchanged.

## 中文

### 升级要点（TL;DR）

- **无破坏性**：宿主窗口不变（`>=0.1.7-alpha.1 <0.2.0`）；journal 格式、任务夹契约、`teamflow_*` 工具参数全部向后兼容。
- **升完重启 `dsh --profile web` 生效**。
- 新增可执行脚本 `scripts/run-inspect.mjs`（随 npm 包分发，`files` 白名单已登记）：给定 runId 只读输出该 run 的文本态/JSON 态报告，不再需要手工解压 journal。

### 为什么是「诚实可见性」：三类实测黑箱

本版的每一组改动都来自一次实机排查中「日志说的和事实不符 / 日志没说的只能翻原始记录」：

1. **git 提交面**（`tf-muigy5eq` 排查实锤）：交付文档 `add -f` 强加被仓库 `.gitignore` 忽略的文件、add 被拒后日志仍写「已入库」、整树收口提交连带工作区其它未提交改动而用户无从知晓。
2. **失败诊断**（空收尾排查实锤）：`stopReason=completed` + 空正文与 provider 报错在日志里长得一模一样，只能解压子代理的 zstd 会话原始记录（十几分钟）才认得出。
3. **主会话触发**（`tf-regression-r1` 实测）：换 provider 后主会话模型把「只有收到明确的开发需求时才调用」反向理解为自由裁量——需求越明确越倾向自己动手，两次绕过流水线。

### 本次变更

**① 交付文档入库尊重 .gitignore（修复）**

- **问题**：doc 类阶段交付文档一律 `git add -f --` 强加入库——目标仓库的 `.gitignore` 被无视（实锤：`docs/teamflow/` 被目标仓忽略却仍进了索引）。
- **修复**：改为 `tfDocAddPlan` 三态判定（`git check-ignore`：0=忽略 / 1=未忽略 / −1=无法判定）。被忽略的不入库并在日志点名；unknown **仍按入库处理**（丢弃用户东西的方向必须从严）。

**② 交付文档 add 失败不再谎报「已入库」（修复）**

- **问题**：调用点不判 `add` 结果，失败时日志仍写「已入库」——比静默更糟的假事实。
- **修复**：失败降级 warn 并转述 git 原话（zh/en），产物仍在工作区不丢失。

**③ 收口提交前如实列出提交范围（新行为）**

- **问题**：收口提交是整树 `add -A -- .`，工作区里未被忽略的其它未提交改动（WIP、已跟踪文件的修改）会被一并带入，用户事先无从知晓。
- **修复**：提交前日志列出完整清单（项数 + 路径，超 12 项省略号显示）。只加可见性、不改行为——实测日志：`统一收口提交范围：9 项（.gitignore, README.md, docs/teamflow/…）`。

**④ 失败诊断自证化：正文长度 + 响应块构成（修复）**

- **问题**：失败诊断只报 `stopReason`，无法区分「空正文 / 被截断 / provider 报错」。
- **修复**：`diag.noResult` 带正文长度与 `util.blockShape` 压出的响应块构成（`reasoning:2472, tool-callx3` 一行）；`completed` + 0 字符给专属措辞 `diag.emptyTurn`。配合根因归因（见下），空收尾形状 = 只有 reasoning、无 text、无 tool-call；宿主中断 finish kind=`aborted`、预算截断=`max-tokens`，在日志内即可分辨，不必再解压子代理会话。

**⑤ 空收尾止损：文件兜底判交付（新行为）**

- **背景（实测归因）**：推理模型空收尾（DeepSeek 实测：`finish kind=stop`，reasoning 之后、正文之前被服务端收尾——非宿主动手，宿主中断/预算截断走 `aborted`/`max-tokens` 有源码锚点）此前一律整轮重跑，一次实测沉没 **112 万 token / 2 分钟**（重跑又花 147 万）。
- **A 档**：`completed` + 空正文时回读任务夹产物，达下限即判交付收口，返回值用文件内容顶替空回复（state 块不在文件里则宽容跳过）。判定抽纯函数 `util.emptyTurnDocVerdict` 并配行为级测试套件 `test/empty-turn.test.js`（真值表 10 例 + 真实文件系统端到端）——测试抓出并修掉一个边界（min=0 时空文件 `0>=0` 误判交付）。
- **诚实边界**：该兜底只救「文件已合格、只差说话」的形态；实测另一次空收尾死在写文件**之前**（全程只写了验证脚本），不命中、照旧重跑。「干到一半死掉」须 continuable 续跑（宿主 `coldResume` 仅覆盖 `startContinuable`，one-shot 不可续），已立项 `docs/TODO.md`（B 档，本版不做）。

**⑥ 主会话触发纪律：注入补显式禁令（修复）**

- **问题**：TeamFlow 上下文注入旧文本「只有收到明确的开发需求时才调用」——防乱调约束写了三处，「必须走流水线」却只在「调用之后」的从句里；换 provider（inceptionlabs/mercury-2.5）后模型反向理解为自由裁量，需求越明确越倾向自己实现，实测两次绕过。
- **修复**：改为最高优先级正向规则——开发需求唯一动作是 `teamflow_start`；无论需求多小多明确，禁止绕过流水线自行实现；需求小不是跳过的理由（journal 留痕 / QA 验证 / 可审计记录正是价值）。zh/en 同步。
- **验证**：修复部署后同 provider 重发同需求 → 流水线正常触发，8 阶段（prd/tech/dev×4/qa/acceptance）全绿零重试（run `tf-muinvkvp-e6h4ul`）。

**⑦ 新工具：`scripts/run-inspect.mjs`（只读检查 CLI）**

- 给定 runId，从 `$DSH_HOME/teamflow` 的 journal 落盘数据读出该 run，输出文本态（人读）与 `--json`（18 键冻结契约，schema `teamflow.run-inspect/v1`）两种报告：phases 定序、stages 升序、run 级 usage 五桶、失败原文 D7 优先级。全程只读（三读函数 + fixture 逐字节不变门禁），随包分发。
- 典型用法：`node scripts/run-inspect.mjs <runId>` / `node scripts/run-inspect.mjs <runId> --json`。

## English

### Upgrade notes (TL;DR)

- **No breaking changes**: host window unchanged (`>=0.1.7-alpha.1 <0.2.0`); journal format, task-folder contract and `teamflow_*` tool arguments are all backward compatible.
- **Restart `dsh --profile web` after upgrading**.
- New executable script `scripts/run-inspect.mjs` (shipped in the npm package, registered in `files`): given a runId, prints a read-only text/JSON report of that run — no more hand-unzipping journals.

### Why "honest visibility": three measured black boxes

Every change group in this release comes from a live debugging session where the log disagreed with the facts, or where what the log omitted could only be recovered from raw session records:

1. **Git commit surface** (`tf-muigy5eq`): delivery docs were force-added (`add -f`) past the target repo's `.gitignore`; a rejected `add` was still logged as "added"; the tree-wide closing commit silently swept in unrelated uncommitted changes.
2. **Failure diagnostics** (empty-finish investigation): `stopReason=completed` with an empty body was indistinguishable from a provider error in the log; the only way to tell was unzipping the subagent's zstd session record (tens of minutes).
3. **Main-session triggering** (`tf-regression-r1`): after a provider switch, the main-session model read "only call teamflow_start for clear development requirements" as discretion — the clearer the requirement, the more it leaned toward implementing directly, bypassing the pipeline twice.

### Changes

**① Delivery docs respect .gitignore (fix)** — delivery docs are no longer force-added (`git add -f`); a three-state `tfDocAddPlan` (`git check-ignore`: 0=ignored / 1=not ignored / −1=unknown) decides. Ignored files stay out and are named in the log; unknown still goes in (the direction of discarding user work must stay strict).

**② Failed `git add` no longer logged as "added" (fix)** — on failure the log demotes to warn and quotes git's own message (zh/en); artifacts remain in the workspace.

**③ Full commit scope listed before the closing commit (new behavior)** — the closing commit is a tree-wide `add -A`; the log now lists every entry (count + paths, ellipsis past 12) so unrelated uncommitted changes are visible beforehand. Visibility only, behavior unchanged.

**④ Self-evidencing failure diagnostics: body length + response-block shape (fix)** — `diag.noResult` now carries the body length and a block-shape line (`reasoning:2472, tool-callx3`); `completed` + 0 chars gets a dedicated wording. Combined with the attribution below, an empty finish reads as `reasoning`-only in the log itself, while harness aborts (`aborted`) and budget cuts (`max-tokens`) are distinguishable without unzipping sessions.

**⑤ Empty-finish stop-loss: file-fallback verdict (new behavior)** — measured attribution: reasoning-model empty finishes (DeepSeek: `finish kind=stop`, cut between reasoning and the body — not the harness, which aborts via `aborted`/`max-tokens`) used to trigger a full rerun, once sinking **1.12M tokens / 2 minutes** (the rerun cost another 1.47M). Track A: on `completed` + empty body, the task-folder artifact is re-read; if it meets the minimum the stage is judged delivered, with the file content returned in place of the empty reply. The verdict is a pure function (`util.emptyTurnDocVerdict`) covered by a behavioral suite (`test/empty-turn.test.js`: 10-case truth table + real-filesystem end-to-end) — the suite caught and fixed a boundary (min=0 mis-judging an empty file as delivered). Honest boundary: this covers "file done, only the reply missing"; a finish that dies *before* writing the file (measured: only a verification script was written) does not hit the fallback and still reruns; mid-work finishes need continuable resume (filed as B-track in `docs/TODO.md`, not in this release).

**⑥ Main-session trigger discipline: explicit ban in the injected context (fix)** — the old wording's three anti-spurious-call constraints left "you must use the pipeline" only inside an "after calling" clause; on a provider switch (inceptionlabs/mercury-2.5) the model read it as discretion and bypassed twice. Now the injected context leads with a highest-priority positive rule: a development requirement → the only correct action is `teamflow_start`; implementing it yourself regardless of size is a violation; smallness is not a reason to skip (journal trail / QA / auditability are the point). Verified: same provider, same requirement → pipeline triggered, 8 stages green with zero retries (run `tf-muinvkvp-e6h4ul`).

**⑦ New tool: `scripts/run-inspect.mjs` (read-only inspection CLI)** — given a runId, renders the run from on-disk journal data: text mode and `--json` (18-key frozen contract, schema `teamflow.run-inspect/v1`): ordered phases, ascending stages, five-bucket run usage, D7-priority failure excerpts. Strictly read-only; shipped with the package.

### Known boundaries and follow-ups

- The empty-finish fallback does not cover the "died mid-work" form — continuable resume is filed (B-track in `docs/TODO.md`); it requires a subagent-lifecycle switch and is scheduled separately.
- `engines.dsh` window stays `>=0.1.7-alpha.1 <0.2.0` (semver does not cover prereleases; documented against official-release boundaries).

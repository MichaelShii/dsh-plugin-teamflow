## 迭代变更流水（2026-08-19 起）

- 2026-09-03：**dev/qaFix 验证证据块（单方宣称 → 可审计的具体自述）**——审计发现：dev 阶段「run verification to ensure green」依赖模型自觉执行与如实汇报，prompt 无证据结构化要求（「how verified」仅摘要一句话）；guard 只防「重复/复读」，防不了「声称跑了其实没跑 / 跑了但简报全绿」；QA 有独立对抗探针 + QA-REPORT.md 结构化测试结果表兜底，dev 是唯一单方宣称阶段。定性：审计可见性缺口而非正确性缺口（功能质量有 QA 兜底），但「全绿自述 vs QA 缺陷」的信息不一致同构于双轨制问题，且假宣称打回多烧一轮。落地：① `devPrompt`/`qaFixPrompt` 强制回复末尾「验证证据」块（`[Verification evidence]`：命令+退出码+断言计数+失败行引用，或显式 `N/A: <原因>`）——policy 级（缺失记 warn 不中断，防误杀纯配置改动任务）；② `util.extractVerificationEvidence` 提取纯函数（到 state 块前截断）；③ `pipeline.noteVerifyEvidence` 三处接入（dev 主路径/断点补跑/qaFix），存证 `stage.verifyEvidence`（JournalStage 新字段）；④ `stageDetail` 返回 verifyEvidence（审计可见）；⑤ 证据块可与 `logs/teamflow/<runId>/` 命令输出日志交叉核对——**不是 enforcement**（模型仍可伪造），是「可审计的具体自述」：具体细节难编造一致（具体性压力）+ 伪造可发现（审计轨迹）；⑥ 新增 `test/evidence.test.js`（8 断言）+ smoke 3n 断言组。typecheck/bundle/全套测试通过。
- 2026-09-03：**prompt 约束分级（hard 自称与 enforcement 脱节 → HOST-ENFORCED / policy）**——审计发现：5 处约束自称「hard constraint」但真实 enforcement 全部弱于措辞——TOKEN_HYGIENE 第一句即自认「violations only log a warning, never interrupt」（自我拆台）；ONCE_DISCIPLINE 声称「violating it burns tokens」但文档重复 write **零观测**（guard 只观测 read/验证脚本，连 warn 都没有）；Doc/AGENTS/Git 边界为纯 prompt 约束、host 无校验。危害：措辞层面「hard」与后果脱节会训练模型对 high-signal 词脱敏（实证：17 条 warn 零削减，guard 注入闭环后才见效），且污染真硬约束（单轨产物/验收结论行）的信号空间。落地：① **分级标签**——`[HOST-ENFORCED]`（host 有真实校验/解析/硬失败后果：QA/验收单轨回复、缺陷表、验收报告与结论行；标注同时**必须**描述真实后果如「missing file = hard failure (needs-human, pipeline stops)」）+ `[policy]`（无 host 强制、靠自律 + guard warn/轻提醒：TOKEN_HYGIENE/ONCE_DISCIPLINE/Doc/AGENTS/Git 5 处）；② TOKEN_HYGIENE 诚实标注「warn + live reminder only (never interrupts)」，ONCE_DISCIPLINE 改为「repeated write/read cycles pay cache replay fees」（不再声称 violating burns tokens）；③ prompts/index.ts 头部固化分级约定注释（新增 HOST-ENFORCED 约束必须先加 host 代码再标词）；④ **禁止 prompt 内自称 hard constraint**（smoke 3m 负断言防回归）。typecheck/bundle/全套测试通过。
- 2026-09-03：**验收结论契约强度修复（漏报护栏：结论行字面量模板 + 无结论行 → needs-human）**——审计发现反向风险：`parseAcceptanceVerdict` 只认含「验收结论/整体结论」的行，但 prompt 未强制该行字面量格式；模型漏写该行时 accLine='' → 旧实现**默认返回 accepted（最乐观默认值）**——模型写「❌ 不通过」但漏前缀 → 判通过 = 质量门禁漏报=假交付。历史只修过误杀（tf-msytlok5），无结论行的默认值方向反了（验收应宁严勿松：误拦截=人工看一眼，误放行=假交付）。落地：① `acceptancePrompt` 结论行字面量模板——回复 verdict line 固定「验收结论：✅ 通过 ／ ⚠️ 有条件通过 ／ ❌ 不通过 ／ 📝 需求不适用」；ACCEPTANCE.md **最后一行必须为字面量结论行**（缺失=契约违例停线人工）；② `parseAcceptanceVerdict` 无结论行 → 返回 `needs-human`（新返回值；📝 全文命中与架构红词仍优先）；③ `pipeline.ts` 新增 needs-human 分支（对齐 reject 模式：advanceTask needs-human + humanIntervention + persist + throw）；④ verdict.test.js 更新旧「无结论行→保守 accepted」断言 + 新增漏报回归（正文 ❌ 无前缀→needs-human；📝 全文无前缀→reject 仍优先）；smoke 增补 3l 断言组。typecheck/bundle/全套测试通过。
- 2026-09-03：**输出单轨制（文件即产物：QA/验收 host 只读文件，回复仅摘要）**——双轨制实锤：日志「QA 未发现缺陷」与验收「打回 BUG-P1-1」对不上（回复正文与产物文件不一致）。落地：① `qaPrompt` 回复收敛 ≤12 行摘要（结论一句话+文件路径）、验收 ≤10 行（结论+路径），正文全部收口 `QA-REPORT.md`/`ACCEPTANCE.md`——**文件即交付物，host 直接导入**（缺陷表/补测清单/核对表必须在文件里），回复不再重复正文；② `pipeline.ts` 新增 `artifactText(journal, fileName)` 读任务夹产物，QA 后 `qa = artifactText('QA-REPORT.md')`、验收后 `acceptance = artifactText('ACCEPTANCE.md')`，`parseDefects`/`parseAcceptanceVerdict`/qaFixPrompt 注入/验收 QA 注入全部吃文件内容；③ **文件缺失 → 硬失败 needs-human + stageFailError**（不回退解析摘要：QA 回复无缺陷表，回退=「QA 未发现缺陷」静默假交付；验收回复无结论行，回退=保守 accepted 误放行）；④ state 块仍附回复尾部（host 机器元数据不进文件），`mergeStageState` 改用回复文本；⑤ resume 复用 QA 产物**文件优先、journal 兜底**（兼容存量 run）；⑥ stage.output 保持回复文本（重试诊断/详情浮层语义不变）。smoke 增补 3k 断言组（prompt 单轨话术 + artifactText + 硬失败 + resume 文件优先）。tech/PRD 等阶段不在范围（tech 已有蓝图文件 fallback）。
- 2026-09-03：**重试诊断包（盲试 → 带因重试）+ stalled 不再自动重试**——withRetry 对同一 prompt 原样重试=盲试（子代理只知道 label 变「第 N 次重试」，不知道上次为何失败）。落地：① `runAgent` 失败路径落 `stage.output`（截断 4k，重试诊断/详情浮层可查），`insubstantial` 细分——命中 `REFUSAL_PATTERN` 时 `refusalHit` 提取命中短语+原文上下文入 summary（实测最左匹配：`抱歉` 先于 `我无法完成`），否则报「内容过短 N 字符 < 下限 M」；② `withRetry` 重试 prompt 附 `buildRetryDiagnostic`（失败分类/详情/guardReason/产出尾部 1k，闭合标记收尾），诊断源全为现成字段，零新持久化字段；③ **stalled（护栏挂死/空转）不再自动重试**——修 guard 注释与实际行为矛盾（此前注释声称走预算门转人工，实际会重试），与 degenerated 同策略 needs-human 引导 resume；④ 重试日志带 outcome。新增 `test/diagnostic.test.js`（拒绝词命中点 + 诊断块结构，最左匹配语义回归）、smoke 3j 断言组。typecheck/bundle/全套测试通过。
- 2026-08-27：**分支策略基调（ADR-2026-08-27）**——启动前用户决策（needs-decision）：teamflow_start 在 auto 策略下按四情况（main+干净/main+脏/feature+干净/feature+脏）返回决策问题+选项（stash/commit/新建/沿用，自定义兜底），主线程 Agent 询问用户后带 branchPolicy/branchName/preAction/commitMessage 重发；auto=建分支 feat/<slug>（从当前 HEAD 派生）、keep=沿用；preAction 在 sanity 前执行；devPrompt Git discipline 硬约束（子代理禁 checkout main/merge/delete 主干）；验收通过后完成汇报附人工合回命令 + stash pop 提醒（host 不自动合回）。配套：护栏注入通道修复（session.append('user/message')，观测→执行闭环真正生效）。
- 2026-08-25：**任务夹文档制落地（ADR-0008，破坏性）**——按头脑风暴定稿实施：① **结构**：每需求一个自包含任务夹 `docs/teamflow/<yyyyMMdd>-r<N>[-<slug>]/`（PRD/DESIGN/TECHNICAL/QA-REPORT/ACCEPTANCE 收口其中），host 在 initBacklog 后建夹（mkdir+meta.json）并持久化 `journal.runDocs`——重试/续跑复用同夹，双归档/版本虚增/memory 堆积三类 bug 结构性消失；② **slug**：triage 输出协议新增 `slug` 字段（`[a-z0-9-]{3,24}` 校验，非法/缺失退化为 `<date>-r<N>`）；③ **prompt 全改**：TF_DOCS 拆产品层/任务夹两层，`RUN(state)` 读 `state.__runCtx.runDocs`（stateSliceFor 首行注入），删除 VERSION_SLICE_BLOCK 与全部 mv 归档/防双归档话术；PRD 头部三行声明（meta summary/基线依赖/取代）、AC 夹内从 1 编起、修订表废除；④ **SUMMARY.md 废除**（host 扫 meta 聚合，本轮只做注入不做浏览器）、memory.md 收窄为约定层（仅约定变更时幂等更新）；⑤ **VERSION 解耦**：代码头是发布版本，迭代不碰；state.currentVersion→lastRunFolder；⑥ smoke 拆旧断言加 3i 断言组。存量项目零迁移。设计文档 docs/adr/0008-task-folder-docs.md。

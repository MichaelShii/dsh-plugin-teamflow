- 2026-09-11（补 4）：**reasoningEffort A/B 扩样到 n=3/臂——修正（补 3）的 n=1 结论**——同需求、同档位（patch）、只比「单点确认」阶段；臂归属用日志证死（low 臂有 `推理强度：low（机械阶段降档）`，high 臂 0 条）。逐样本（in / cacheRead / out / calls / 耗时）：**high** H1 25,702/158,720/12,649/6/68.7s、H5 18,802/255,744/8,260/11/179.5s、H6 14,643/143,872/5,412/7/40.9s → 均值 **19,716 / 186,112 / 8,774 / 8.0 / 96.4s**；**low** L2 21,647/78,720/3,421/5/24.6s、L3 8,751/108,800/2,791/6/22.8s、L4 19,959/308,096/8,930/13/81.4s → 均值 **16,786 / 165,205 / 5,047 / 8.0 / 42.9s**。**均值方向一致**：output −42.5%、每次调用 output −49.5%（1,211→612）、cacheRead −11.2%、input −14.9%、**计费总量仅 −12.8%**（214,601→187,038）、耗时 −55%。**但区间大量重叠**（high output 5,412–12,649 vs low 2,791–8,930；low 的 L4 因自己探索了 13 次调用反而比 high 的 H6 更贵）——n=3 下这些差异**统计上不可分**（output：high sd≈3,640 / low sd≈3,390，差 3,727，t≈1.3）。**结论修正**：① 链路正确性已证（降档在预期的臂、预期的时间点生效，零失败零重试）；② **本任务规模下 run 间方差（模型自选探索深度，调用数 5–13）压过 effort 效应，无法据此宣称具体节约百分比**；③ 决策：降档**保留**（机制明确——推理 token 计入 output 且每回合回传；无质量退化、无成本倒退），但**文档/发布说明不写百分比**；要拿可信数字需要更大任务样本或固定调用数的评测场。方法学教训：n=1 的 A/B 在本项目这种高方差任务上**没有结论价值**（（补 3）的 −47% 即被扩样推翻）。

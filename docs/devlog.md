- 2026-09-12（补 20）：**全局面板状态徽章可点筛选（多选）**（用户提议："这块要不要做成单击筛选？"）。落地：① 新增 `filterChip`（按钮版徽章，选中态实心 + 状态色边框）——分组行上的每个状态计数都可点，**多选 toggle**（真实问法是「还没结束的有哪些」= 进行中/待验收/需人工的并集，单选会逼人来回点）；② **筛选优先于折叠**：选中含终态时自动展开（否则点了「已验收 19」却看不到卡片），清掉筛选回到默认折叠；③ **状态可见**：行尾显示「筛选中 N 项 · 显示 x/y × 清除」，无筛选时不出现（不加噪音）；④ **作用域**：backlog 每组独立（chip 本就是分组计数），run 标签加同款一行（`running/pending/interrupted/failed/cancelled/completed/superseded`）——run 的折叠（最近 8 条 + 进行中置顶）**只作用于筛选结果**；⑤ 切产品线清空筛选与展开态（面板不重挂载，必须显式 reset：`useEffect([productKey])`）；⑥ **纯客户端过滤**，host 数据面与 slice 上限一律不动（数据不丢，清除即见全部）。冒烟补 3 条断言（filterChip/toggleRunStatus、每组独立 + 优先于折叠 + 切产品线重置、筛选状态可见 + ×清除）。**教训**：计数徽章天然是"筛选入口"——展示与操纵同一处，比另开一排筛选控件更省认知；但必须同时解决"筛了却看不到"（折叠与筛选的优先级）与"筛了不知道在筛什么"（可见状态 + 一键清除）。

  **测试**：L1 prompt-contract 新增 2 条契约——`LOG-LAYOUT-REUSE`（四阶段共享锚点，含 `exclude: /qa-out\.log/` 防回退）+ `LOG-LAYOUT-PER-PHASE`（三处指向）；typecheck + 全套 11 文件测试通过。

  **教训**：**「落盘省 token」和「落盘堆垃圾」是同一机制的两面**——落盘是给上下文减负的，但规则若只写"写到某目录"、不写"复用与归处"，模型每次都会开新文件；**可复核性要的是"少而稳"的文件集，不是"多而全"的倾倒场**。

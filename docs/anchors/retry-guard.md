**外部供应商故障 ≠ 交付缺陷（2026-09-17 实测，勿回退）**：`dddd` 第一轮 01:37 六条 dev `stopReason=error`（旧行为：快速重试两次 → `failed + human`），**16 分钟后同请求成功** → 证明是「供应商时间窗内不可用」。处置三件套：① `util.classifyExternalFailure`（纯函数，关键词含 429/402/rate limit/quota/insufficient_balance/5xx/upstream/timeout/ECONNRESET + 中文限流/额度/余额/超时/上游不可用；`content` 类仅上下文超限/护栏/产出过短；未命中→`unknown` 按内容类处置）——**启发式**（宿主只给 stopReason+文本，命中原文必须记日志）；② 外部类走 **长退避** `EXTERNAL_BACKOFF_MS = 30s/60s/120s/240s`（总 ≈7.5min，跨过实测 16min 窗口的一半以上）、**不计熔断预算**、**不受 `RETRY_LIMIT` 约束**、等待可被取消打断（`sleepUnlessCancelled`）；③ 用尽仍失败 → **`journal.externalFailure=true` + 阶段 `interrupted/external` + 汇报 `report.externalFailure`**（明写"非交付缺陷、resume 只补这一段"），**禁止落 `failed` 让人误判成交付质量**。**不做阶段内续写**（要动「产物写一次不可变」契约与全部完成判定，收益只有非 dev 阶段重跑几分钟 → 价值低）。withRetry 重试附诊断包（上次 outcome/summary/护栏原因/产出尾部）；退化（degenerated）与挂死/空转（stalled）不自动重试（needs-human 引导 resume）；护栏=进度信号非配额。**门序**：不可重试/外部中止/护栏中止 → 熔断预算门 → 自动重试——预算按新增口径且量级合理（≈两轮尝试）时「重试优先于熔断」，不得再让单次失败必然熔断。**环境不可用（`env-unavailable`）是第五个早停信号（2026-09-23 probe-v4 实锤，勿回退）**：同一工具以同一错误（指纹 = `工具名::归一化错误`；判据只用结构化 `message.isError`，文本正则仅兜底）连续失败 `GUARD_TOOL_FAIL_WARN=2` 次 → 落 `stage.envUnavailable` + 轻提醒，`ABORT=3` 次 → 中止本次尝试并落 `outcome='env-unavailable'`（**不自动重试**，直接 needs-human：「这不是模型问题，请先修复工作区，再 resume」）。**它优先于「完成了」**——模型听劝停手后改用文件工具把骨架写完，那种「完成」无法验证，不得算 done（probe-v4 第二次实测就是这样烧掉 83k 输出）。阈值必须早于模型放弃：实测它第 2 次相同失败就改走绕道，旧的 3/5 从未触发。outcome 名刻意不含 `/token|context|limit/` 正则（只有 `degenerated` 享受干净重试豁免）。

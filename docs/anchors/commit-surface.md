> 本文件是 `AGENTS.md` §5 中「收口提交面」锚点的**论证、实锤与门禁细节**——从 AGENTS.md 原文迁出，
> 内容逐字保留（仅把表格分隔还原为正常 Markdown 段落）。**行为不变量以 `AGENTS.md` §5 为准**；

一个 run 一个 commit，面 = **代码 + 任务夹（`docs/teamflow/`）+ memory.md**；**`logs/teamflow/` 永不入提交**（插件自有运行日志与子代理临时脚本，prompts 已定性为非交付物）。**三道防线**：① 提交前 `pipeline.ensureLogGitignore()` 幂等补写工作区 `.gitignore`（卫生，**也是整树 add 的唯一依赖**）；② `sanity.tfUnstageArgs()` 紧随 add 把自有日志从索引里摘掉（保证：规则被删/写不进去时兜得住；真摘出东西会记 warn——那是防线①失效的信号）；③ 提交结果分派日志（`commitDone`/`commitSkip`/`commitFail`，「无事可做」先用 `git status --porcelain` 空判定，措辞兜底 `GIT_NOTHING_TO_COMMIT`）——**失败必须可见**。**`tfAddArgs(excludes?, cwd?)` 默认 `git add -A -- .`，禁止再用负 pathspec 点名自有日志**：2026-09-11 → 09-15 的实锤是 `:(exclude)logs/teamflow` 与「刚写好的 .gitignore 规则」互相拆台——git 对显式点名且被忽略的路径**报错退出 1**（索引其实已写好），而旧代码 `add === null ? null : git commit(...)` 据此**短路提交且三条日志一条都不写**，4 天里没有任何 run 提交过（assetd 09-11 / 插件仓 09-15 11:15 / slugkit-en 12:08 / durparse-en 13:47 全部 staged-but-uncommitted）；`:(exclude)logs/teamflow/**`、`:(exclude,glob)`、`:(exclude,literal)`、`-c advice.addIgnoredFile=false` 四种变体实测同样 exit 1。回归门禁 = **真 git 集成测试 `test/commit-path.test.js`**（负 pathspec exit 1 的防回退锁 + 写规则→整树 add→索引兜底→commit 真跑通 + 「无事可做」判据）+ `test/gitignore.test.js` 参数形状。**禁止回退为裸 `git add -A`**（无 .gitignore 保证、无索引兜底）——实锤 assetd `tf-mtwvwpxa-p3vw08`：一次提交 227 文件里 208 个（92%）是日志噪音。已污染的目标仓库用 `git rm -r --cached logs/teamflow` 移出。**2026-09-15 后这些防线只覆盖「run 进行中用户自己提交」的窗口**（终态日志已归档离开项目，见下一条）。**基线噪音排除只在索引层，绝不写用户 `.gitignore`（2026-09-18 方案 B，勿回退）**：旧的 `ensureCommonNoiseIgnores()` 把 `.pnpm-store/`+`node_modules/` 写进**用户** `.gitignore`（且 `mergeGitignore` 的注释是整批一条 → 顶着「TeamFlow 运行日志…」文案落盘，用户截图实锤）——**越界**：「该忽略什么」归 L2（PRD 阶段 PM 按技术栈规划）/L3（QA 收口探针）/用户本人，host 只该在**自己那一次 git 调用**上收敛范围。现改为 `tfAddArgs(BASELINE_NOISE_EXCLUDES, 工作区路径)` 的 magic pathspec（只影响 host 那次 add，用户 `.gitignore` 逐字节不动）。**安全性前提（temp 仓库实测）**：`:(exclude)` 报错 exit 1 的唯一前提是该路径**已被 .gitignore 忽略**，故清单项**永不得写进 .gitignore**，也不得含自有日志。**自检必须 `git check-ignore -q`（以目标仓库为根）**——相对路径读 `.gitignore` 读到的是宿主 cwd，两个方向同时错（漏排→噪音进索引；误排→点名被忽略→**exit 1 复活「4 天没提交过」那个坑**）；无法判定时一律不下发（宁可少排，不得让 add 失败）
